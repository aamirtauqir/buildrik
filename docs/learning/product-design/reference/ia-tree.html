Buildrik IA — the build board.

Not just where every feature lives — what to ship first, in what order, with what acceptance bar. ~100 features from 17 backend clusters → 6 user jobs, each with a home, a verdict, a priority (P0/P1/P2), an entry point, the states it must cover, the data it needs, who uses it, and what it depends on. Pick a row → you can build the screen.

verdict: keep fix merge hide cut priority: P0 first-slice blocker · P1 next · P2 defer · ◆ slice on the wedge path states: E empty L loading X error S success D denied A async owner: D dashboard E editor S server

Scope test (decides every home): one site's content → Editor; across sites / the business → Dashboard. Priority test: on the agency wedge proof-path → P0; earns revenue/trust right after → P1; everything else → P2 (defer).

  • Dashboard home · Template gallery · First-run
  • Interactions · ⌘K · Stock · Image editor · Save-as · insert-section
  • Custom CSS · Analytics · AI SEO/alt-text
  • + hidden: collab · localization · billing-upgrade · extra-workspace · (Export = cut)

Dedup → one home each

  1. Site settings ×3 → dashboard site-detail
  2. Media ×2 → editor (dashboard read-only)
  3. SEO ×2 → per-page editor + defaults in settings
  4. Design system ×3 → one "Brand" area
  5. Settings hub → drop the catch-all
  6. Templates → not a dupe (rename to disambiguate)

6 decisions · 4 are merge-verdict rows; 2 are drop/rename.

How to read a row → build it

  1. Pri says when (P0 first).
  2. Entry says where it opens from.
  3. States says which screens to draw (E/L/X/S/D/A).
  4. Data says the entities + mutations to wire.
  5. Roles + Deps say who sees it and what must exist first.
  6. Done means (per job) is the acceptance bar.

Completeness check

  1. Every feature has one home? ✓
  2. Every group names a job, not a module? ✓
  3. Top-level ~5–6, not 17? ✓ (5 + 4)
  4. Every row has a priority + acceptance? ✓
