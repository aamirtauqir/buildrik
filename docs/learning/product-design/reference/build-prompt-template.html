Reference · Build-prompt template · for directing AI ("vibcoder")

The prompt the AI can't misread.

A build-prompt is the 4-part handoff + a verify clause, phrased so an AI (or a human) builds the right thing and can't claim "done" without proving it. Use it for every roadmap phase. One rule comes first, before any of the four parts:

Rule 0 — make the AI CHECK before it builds. Tell it to read the current code and confirm what already exists, not assume. Half of "the AI built the wrong thing" is the AI inventing something that was already there. (Example: Buildrik's collab flag already existed — a prompt that said "add a flag" would have been wrong. The right prompt says "audit that all collab UI respects the existing flag.")

The template — fill the five slots

CONTEXT — one line: why this, and "check the current code first; don't assume." WHAT — the change, concretely. The behaviour/UI you want. Numbered steps if several. WHERE — the files / area to touch (and which existing thing to reuse). DON'T-BREAK — the rules + what must keep working (design system, the engine, existing handlers, named features). DONE — the checkable acceptance: how you'll both agree it's finished. VERIFY — "climb all 5 rungs (types · tests · walk states in browser · click actions · check DONE). Don't claim done until verified."

What YOU add (the inputs only you have)

  • The why / user pain — the real reason (from your user feedback), so the AI optimises for the right thing.
  • The acceptance — what "done" looks like to you. The AI can't know your bar; state it.
  • The constraints it can't infer — "don't ship collab," "cobalt only," "don't touch the engine." Pull these from the constitution + project rules.

Notice: you rarely add code or tools up front. You add information — the why, the bar, the limits. The AI supplies the typing.

Worked example — Phase 0 (gate collaboration)

CONTEXT — Recovery roadmap Phase 0: hide what's broken. Check the code first — FEATURE_COLLAB already exists; this is an audit, not a new flag. WHAT — 1) Audit every collab UI (topbar presence/collaborationSlot, PresenceIndicators, ConnectionQualityIndicator, the Collaborate/Invite CTA, any collab panel) and ensure ALL are gated behind isFeatureEnabled("collab") (OFF by default); fix any that leak when off. 2) Sweep for any "coming soon"/placeholder/broken/dead control and hide each. WHERE — packages/editor/src/editor/ (shell/Topbar, shell/StudioHeader, collaboration/*); flag in shared/utils/featureFlags.ts + runtimeEnv FEATURE_COLLAB. DON'T-BREAK — don't delete collab code, only gate it. Keep the flag + vibcoder primitives. Don't touch the engine. Don't break the just-restructured topbar. DONE — with FEATURE_COLLAB off, no collab UI shows anywhere; no broken/"coming soon" control visible; tsc clean; editor tests pass; live-verified in the browser. VERIFY — climb all 5 rungs; don't claim done until verified.

How to "start it as a goal"

Paste the prompt as a message, or use /goal with a one-line completion condition so the agent keeps working until it's truly done: "/goal Phase 0 complete — all collab + broken UI hidden behind flags, tsc + tests green, browser-verified." The goal's stop-hook blocks finishing until that holds — which forces the verify.
