The method (how a map becomes a plan)

Three moves, in order:

  1. Split keep vs new from the status column. A surface that already works (✅) is a re-lay-out, not a re-wire — keep the handlers, restyle the chrome (Lesson 8). A surface that's partial (🟡) or was a stub (🔵) needs a new flow + honesty gate. The status column already decided this; we just read it off.
  2. The split is also the effort estimate. Keep+reskin is cheap (hours). New-flow is the real design+build cost (days). So the plan can be honest about scope before a line is written.
  3. Order by dependency, then pull the differentiator forward. The spine must come first (everything docks into it, #15). After that, default order is by job (build → brand → sign-off → ship). But the business reason for this redesign is agency-first — so the wedge (Shared DS push) and the agency sign-off loop get pulled forward, not left for last.

What's explicitly NOT in this plan

It is not a phase; promoting it would be promoting something that isn't ready. Export-HTML stays cut (takes the user out of the product). AI-create-site / billing-upgrade / runtime-locale stay hidden (backend stub/throws).

Stage 5 — what the reviews must pressure-test

This plan is a set of bets. Hand it to autoplan (CEO + design + eng) and codex, and make them argue these:

Sequencing bet: is pulling the wedge (DS-push) to P2 right, or does it need the full editing loop shipped first? CEO-review owns this.
Honesty-vs-fix bet: for the 8 new-flows touching backend gaps (Comments, Share, Redirects, Domains), is "design honest + gate the feature" the right call, or fix the backend first? Eng-review owns this.
Effort bet: the 30 "keep+reskin" assume the handlers truly stay (re-lay-out, not re-wire). Eng-review should spot-check that no ✅ surface secretly needs a rewire.
Coherence bet: do the 7 "deepen-states" surfaces reach the same state-completeness bar (#13) as the freshly-drawn ones? Design-review owns this.
