The whole-product redesign pipeline.

Haan — poora editor redesign ho sakta hai. Par yeh ek pipeline hai, ek button nahi. Yeh playbook batata hai: har skill asal mein kya karta hai, kis stage par fit hota hai, kaunsa flow rakhna hai vs naya banana, aur "har screen check ho" kahan hota hai. Backbone = job + module (Webflow ki tarah).

Pehla faisla: purana flow rakho ya naya banao?

Sab kuch naya karne ki zaroorat nahi. Yeh aap ke #8 (subtract) + L8 ka "re-lay-out, not re-wire" hai — jo chal raha hai uske wires mat chhedo, sirf shakl badlo.

✓ Rakho + re-skin (flow theek hai)

Agar user bina atke goal tak pohonchta hai → flow same, sirf presentation redesign. Status ✅ wali surfaces: publish, pages, canvas, inspector, media. Wires same, boxes naye.

✦ Naya flow (toota / confusing / missing)

Agar user atakta hai ya feedback nahi milta → naya flow. Status 🟡/🔵 wali: client-review loop (client side toota), silent actions (no feedback), CMS sync. In ka flow dobara design hota hai.
Test per flow (ek line): "kya user goal tak bina atke pohonchta hai?" Haan → rakho + re-skin. Nahi → naya flow. Yeh faisla aap ki coverage map ke status column se already nikal aata hai (✅ = keep · 🟡🔵 = new).

The 8-stage pipeline

1

Inventory — real functionality nikalo DONE

Code se har surface (reverse-wireframe). Output = functionality coverage map (~40 surfaces, status + home).

reverse-wireframe · grounded in code
2

Wireframe every surface YOU + me · NOW

Job + module backbone: 6 jobs → ~15 modules/surfaces → har surface ka grey-box (5-step recipe). Keep-flow surfaces = re-skin; new-flow surfaces = naya flow draw. To-draw → 0.

me drives · aap har surface confirm karte
3

Check every screen YOU

"Har screen check ho" — yahan. Har wireframe ko 10 heuristics + states checklist se guzaaro (build se PEHLE — sasta). Aap ki eye + naming muscle (L1). Loop: draw → check → fix → next.

aap + heuristics-cheatsheet · design-review ka method, par wireframe par
4

Assemble the redesign plan me

Ek doc: har surface → keep/new flow → 4-part build spec (L4 handoff: WHAT/WHERE/DON'T-BREAK/DONE). Yeh woh "plan" hai jise stage 5 review karega.

me writes · grounded in stages 2–3
5

Pressure-test the plan SKILLS

Yahan aap ke naamzad skills aate hain. autoplan = ceo + design + eng reviews ek saath ("features sahi karte hain"). Phir codex = external second-opinion. Plan theek hone tak iterate (L: codex-iterate-until-clean).

autoplan (ceo+design+eng) + codex · validate, don't generate
6

Build it /goal + codex

/goal autonomous run — re-lay-out not re-wire (L8). Har piece 5-rung ladder se verify (types → tests → walk states → click → acceptance). codex har risky diff review.

/goal builds · codex reviews · 5-rung verify
7

Design-review the BUILT UI SKILL

Ab design-review — bani hui real UI par: spacing, AI-slop, hierarchy, slow interactions → fix. (Yahi woh skill hai jise aap ne socha wireframe banata hai — yeh QA karta hai, build ke baad.)

design-review · on the shipped UI, not the wireframe
8

Walk it with 5 users YOU

Asli test (L15 / Krug). 3–5 agency users core job chalaayein; jo trip kare woh agla worklist. Decide > perfection.

aap · the real feedback loop

Honest limits (autonomous ≠ magic)

Stage 2–3 (design) aap ki judgment maangti hai — aap designer ho (L15), AI guess karega aur slop dega. Stage 6 (build) par /goal chamakta hai — woh wahi banata hai jo wireframe + plan specify karte hain. Ek /goal poora product "design" nahi karega — woh aap ke design ko build karega. Isliye sequence: pehle design (insaan), phir build (autonomous). Yeh L8 ka "presentation ≠ logic" macro level par.

Job + module backbone (the Webflow model)

Aap ka instinct theek: Webflow job-aur-module se bana hai — top-level = jobs (Designer/CMS/Editor), har job ke andar modules (panels/blocks) jo fixed jagah par rehte (#15 spine). Aap ka version: 6 jobs (home-map) → ~15 modules (functionality-map) → har module ka wireframe. Same do-axis jo L17 sikhata hai: job (prominence) × module (layout).

Method: Lesson 19. Skills: autoplan (runs plan-ceo/design/eng review) · codex · design-review (QA built UI) · /goal (autonomous build). Flow rule: L8 re-lay-out-not-re-wire. Grounding: functionality map + home-map. Webflow = job+module reference model. Kuch atke — poocho.
