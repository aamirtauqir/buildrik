# Mission: Become a pro product builder & designer (via Buildrik)

## Why (evolved 2026-06-21)
It started narrow — "Buildrik's design feels like AI slop; learn enough UX to audit and fix it." Through the course the learner built the whole **craft** (audit → name → rate → place → handoff → build → verify) and a living **design language** (the constitution). The mission has grown: the goal now is to **become a genuinely good product builder & designer — a "vibcoder" who directs AI like a PM directs a team and judges the output like a designer** — and to use that to make Buildrik, and any product, obvious and well-made.

## Success looks like
- **Craft (done):** run a heuristic audit, name + rate findings, decide placement by principle, write a build handoff, design every state, build without breaking, verify before claiming done. Captured in lessons 1–8 + the [constitution](reference/buildrik-design-principles.html).
- **Pro frontier (the new edge):**
  - **User-first:** start any problem from *who the user is · what job they're doing · where they get stuck* — not from the UI.
  - **Research:** watch ~5 real users attempt a task; let what they trip on drive the work (not personal taste).
  - **Measure:** define what "better" means for a change, and check whether it actually moved.
  - **Direct AI well:** brief with the 4-part handoff + the constitution; review AI output against principles, reject slop.
  - **Prioritise like a PM:** ship the smallest thing that solves the real user pain; say no to most.

## Constraints
- Solo builder, shipping fast to `main`. Lessons stay short + immediately applicable to the real codebase.
- Roman-Urdu-friendly; one clear recommendation, not a menu. Drive, don't quiz.
- Learn by working the REAL app (editor `/edit/:id`, dashboard) — worked examples, not abstractions.

## Now in scope (was "later")
- **User research / usability testing** — the previously-deferred highest-leverage habit. Steve Krug's DIY 5-user test is the entry point.
- **Measurement** — defining + checking success for a change.
- **Product prioritisation** — deciding what NOT to build.

## Still out of scope (for now)
- Deep visual/brand theory (DESIGN.md locks the brand).
- A formal multi-team design-system org/process.
