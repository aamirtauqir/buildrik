# Mission: Product & UX design for Buildrik

## Why
Buildrik's features are strong, but the product *design* is incoherent — the app feels weird to use, features don't relate to each other, actions don't give the result a user expects, and the UI reads as "AI slop." I want to learn product/UX design well enough to **audit my own app, name what's wrong, and redesign it so a real user (an agency operator) finds it obvious** — not just functional.

## Success looks like
- I can run a heuristic UX audit on any Buildrik screen and write findings that name the exact principle each one violates.
- I can rate each finding by severity (0–4) and know what to fix first vs. ignore.
- For any feature, I can state its *expected result* in one line and check whether the UI delivers it.
- I can spot "AI slop" patterns (density, decoration, no hierarchy) and name the fix.
- The editor + dashboard read as one coherent product, not a pile of features.

## Constraints
- Solo builder, shipping fast to `main`. Lessons must be short and immediately applicable to the real codebase.
- Prefer Roman-Urdu-friendly explanation; one clear recommendation over a menu of options.
- Learn by auditing the REAL app (editor at `/edit/:id`, dashboard) — not abstract examples.

## Out of scope (for now)
- Visual/brand design theory (color theory, typography systems) — DESIGN.md already locks the brand.
- Building a formal design system from scratch.
- User research / interviews / analytics — start with expert heuristic audit, add research later.
