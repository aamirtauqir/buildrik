Lesson 13 · ~6 minutes

One home, grouped by the job.

Aap ne bilkul theek pakda: "samajh nahi aa raha kis cheez ko kahan rakhun." Yeh taste ka masla nahi — yeh information architecture ka masla hai: features ko kaise group karein, aur har feature ka ek hi ghar kahan ho. Yehi woh layer hai jo "messy product" ko "obvious product" banati hai. Aur achhi khabar — guess nahi karna, aapke paas already poori feature-list maujood hai.

IA kya hai? Features ko organize + label karna taake user (a) cheez dhoond le aur (b) jaane woh kahan hai. Buरी IA ki nishani aapke apne lafz hain — "kahan rakhun samajh nahi aata." Achhi IA obvious lagti hai. (NN/g: IA ≠ navigation — pehle structure, phir nav).

Asal galti: aap ne backend ki tarah group kiya, user ki tarah nahi

Aapki feature-inventory abhi 17 clusters mein bati hai — Auth, Workspace, Editor, Inspector, CMS, Media, AI, Publishing… Yeh engineering ke modules hain (PRD Module 1–9). User kabhi nahi sochta "main Module 4 mein jaa raha hun." Woh sochta hai "mujhe client ka site ship karna hai."

Sabse badi IA galti yehi hai: product ko apne system ki shakal par chala dena (database tables, backend domains) bajaye user ke kaam ke. (NN/g: structure user ke mental model se match honi chahiye, aapke org-chart se nahi.)

Theek karne ke 3 rule

Rule 1 — Group by the job, not the module

17 technical clusters ko ~6 user-jobs mein collapse karein. Agency operator ke asal kaam:

DashboardBusiness chalao — account · team · clients · billing · integrations
DashboardSite shuru karo — naya site · templates · first-run
EditorPage banao — canvas · add · pages · layers · CMS content · media
EditorBrand par lao — design system · tokens · components · inspector
+DashboardSign-off lo — preview · client review · comments · share
+DashboardShip + chalao — publish · domains · SEO · forms · analytics

Rule 2 — Har feature ka ek hi ghar

Agar ek hi cheez do jagah se khulti hai, user ka mental map kabhi nahi banta. Duplicate = pick one, baaki merge. Yehi dedup aapki constitution ka naya principle #14 hai.

Rule 3 — Do surfaces, ek hi sawaal se baant

The scope test: "Kya yeh ek site ke andar ka kaam hai, ya kai sites / business ka?"
Andar ek site → Editor.   Across sites / business → Dashboard.

Yeh ek line har "kahan rakhun" ka jawab de deti hai — bina taste ke.

IA smell: top-level nav mein 17 cheezein, ya ek feature jiske 2 ghar hain. Dono ka matlab — structure abhi user ke kaam se match nahi karti.

Method — the home-map pass

  1. Flat list lo (inventory ki ~100 features).
  2. Har feature: kaunsa user-job serve karta hai? (Rule 1)
  3. Scope test se ghar do — Editor / Dashboard. (Rule 3)
  4. Verdict: keep · merge · cut · hide — sach backend-map se. (Rule 2)
  5. Grouped result = nayi IA = nav ka skeleton. Ab guess khatam.

Output ek home-map hai — woh SSOT jise har builder cite karega. Bilkul L12 ke reverse-wireframe ki tarah: list banao, gap khud bol dega.
