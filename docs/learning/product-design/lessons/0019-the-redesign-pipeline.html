Lesson 19 · ~5 minutes

Redesign is a pipeline, not a button.

Aap ne poocha: poora product redesign karein — using plan-ceo-review, design-review, ek /goal skill + codex, har screen check ho, job+module (Webflow jaisa)? Haan — ho sakta hai. Par yeh ek staged pipeline hai, ek autonomous button nahi. Aur in skills ka kaam shayad woh nahi jo aap samajh rahe ho — pehle woh theek karte hain.

1 · Purana flow rakho ya naya banao?

Sab naya karne ki zaroorat nahi. Yeh L8 ka "re-lay-out, not re-wire" hai — jo chalta hai uske wires mat chhedo, sirf shakl badlo.

✓ Rakho + re-skin

User bina atke goal tak pohonchta hai → flow same, presentation nayi. (Status ✅: publish, pages, inspector, media.)

✦ Naya flow

User atakta / feedback nahi milta / toota hai → naya flow. (Status 🟡🔵: client-review loop, silent actions, CMS sync.)

Test: "user goal tak bina atke pohonchta hai?" Haan → keep. Nahi → new. Yeh faisla aap ki coverage map ke status column se already nikalta hai.

2 · In skills ka asli kaam (yeh galat samjha ja raha tha)

Aap ne kaha "design-review se wireframing banwate hain." Asal mein:

  • plan-ceo / plan-design / plan-eng-review = likhe hue plan ko pressure-test karte hain. Wireframe nahi banate. (autoplan teeno ek saath chalata hai.)
  • design-review = bani hui UI ka QA (spacing/slop/hierarchy). Build ke baad, wireframe nahi.
  • codex = external model se code/plan review. /goal = autonomous build.

To: wireframe main banata hun (aap ki eye ke saath) · reviews + codex validate karte · /goal build karta. Koi skill wireframe khud nahi banata.

3 · Teen lanes mein poora pipeline

Design
(YOU)
1 Inventory — code → surfaces. ✓ done (map)
2 Wireframe har surface (job+module, 5-step recipe). ← abhi yahan
3 Check har screen — heuristics + states, build se pehle.
Validate
(SKILLS)
4 Plan likho — surface → flow → 4-part spec.
5 Pressure-test — autoplan (ceo+design+eng) + codex. "Features sahi karte hain" = yahan.
Build
(AUTO)
6 Build — /goal + codex, 5-rung verify, re-lay-out not re-wire.
7 design-review bani hui UI par (QA).
8 Walk 5 users (L15) — asli test.

4 · Honest limit

Stage 2–3 (design) aap ki judgment maangti — aap designer ho, AI guess karega = slop. Stage 6 (build) par /goal chamakta. Ek /goal poora product design nahi karega — woh aap ka design build karega. Isliye: pehle design (insaan), phir build (auto). Aur job+module backbone = bilkul Webflow ka model (top-level jobs, andar fixed modules, #15 spine).
