Lesson 16 · ~5 minutes

Lock the spine, dock the rest.

Aap ne bilkul theek cheez maangi: "jab naye features add hon to editor ka core design kharab na ho — Add button ki position har version mein same rahe; core features kareeb rahein, extra helping features bahar." Iska ek naam nahi — teen naam hain, teen layers par. Pehle naam, phir Buildrik par seedha apply.

Iska naam kya hai

Aap ek hi cheez ko teen altitudes se dekh rahe ho:

Visible
Spatial stability — "consistency." Add button har version same jagah → user ki muscle memory bachti hai. Nielsen heuristic #4: jab layout stable rehta hai, user ko dobara seekhna nahi padta.
Structure
Stable core + periphery — core features fixed & central; rare/helper features edge par ya ek-click andar. Ye aap ka constitution #9 (progressive disclosure) ka bada bhai hai.
Why
Pace layering — system ki layers alag raftaar se badalti hain; fast layer ko slow layer hilaana mana. Stewart Brand: "Fast learns, slow remembers. Fast proposes, slow disposes."

Code mein jab AI ko brief karo, yahi qaida Open–Closed Principle kehlata hai: open for extension, closed for modification — naya feature add karne ke liye purana core chhedna na pade.

Ek handle mein: "lock the spine, dock the rest."

Spine kya hai, edge kya hai

Spine = woh chand cheezein jinki jagah user ko zabani yaad ho jaati hai. Inhe hilaana = har user ko dobara seekhne par majboor karna. Edge = baaki sab — yeh badalta rehta hai, par spine ko chhuye baghair.

Spine — fixed, kabhi reorder nahi

  • Rail ke slots: ➕Insert · 🖼Media · 📄Pages · 🎨Design
  • Topbar zones: Navigate │ View │ Status+Ship
  • The one hero button (Publish)
  • Inspector ka frame (header → tabs → body)

Edge — yahan naya feature dock karo

  • Andar kisi spine-panel ke (naya element → Insert ke andar)
  • Ek sub-tab ya "More" section
  • ⋯ overflow (rare/global controls)
  • Ek context menu / right-click
Aap ka asli example: ➕ Insert hamesha rail slot #1 par rehta hai. Naya element-type (say "Pricing table") aata hai → woh Insert panel ke andar jaata hai, ek naya rail icon nahi banta. Spine same → muscle memory zinda. Yeh #14 "har feature ka ek ghar" + #9 ka jod hai.

Buildrik par kyun yeh abhi zaroori hai

Aap jo rail lock kar rahe ho (Insert · Media · Pages · Design) — woh khud spine lock karna hai. Asli khatra agle 6 mahine hain: jab CMS, reviews, comments, animations — sab aayenge. Bina rule ke, har naya feature ek naya rail icon maangega, aur 6 mahine baad rail phir wahi 11-tab grab-bag ban jaayegi jise aapne abhi theek kiya. Rule yeh rokta hai: naya feature spine mein jagah nahi maangta — woh edge par dock karta hai.

The spine test — har naye feature se pehle

  1. Kya yeh kisi cheez ki position hilaata hai jo user ko pehle se yaad hai? Haan → ruk jao.
  2. Kis spine-ghar ke andar yeh dock ho sakta hai? (Insert / Pages / Design / Media / ⋯). Koi ghar fit nahi → shayad feature hi galat hai.
  3. Common ya rare? Common → panel ke andar saamne. Rare → "More" / overflow ek click neeche (#9).
  4. Spine count badha? Naya top-level slot tabhi jab woh ek nayi user-job ho — varna #8 "subtract before you add."

Carry this forward

Yeh lesson aap ki constitution mein ek naya usool ban gaya: #15 — "Lock the spine; dock additions to the edge." Aur jaisa L15 mein kaha — spine lock karna hi pehla decision hai jo aapko aage badhne deta hai. Stable spine = aap features tezi se add kar sakte ho bina dar ke ki design toot jaayega.
