Lesson 17 · ~6 minutes

Wireframe it: pehle job, phir blocks.

Aap ne IA kar li (kya kahan jaata hai), rail lock kar li (Insert · Media · Pages · Design). Ab agla qadam: us structure ko draw karna — taake test ho sake. Aap ne theek tareeqa maanga: pehle "job-to-be-done", phir "module/block." Yeh ek hi screen par do pass hain — pehla pass kya zaroori hai decide karta hai, doosra woh kahan baithta hai.

Do pass, ek screen

Pass 1 · Job

User is screen par ek asal kaam karne aaya — woh kya hai? Yeh decide karta hai prominence: sabse bada kaam = sabse loud box. Baaki dheema.

Pass 2 · Modules

Us kaam ke hisaab se screen ko blocks mein todo (header / main-action / info / nav). Phir blocks ko grey boxes mein grid par rakho.

Job pehle isliye, kyunki agar aap blocks pehle banaoge to aap sirf UI ko copy karoge. Job pehle = aap user se shuru karte ho. Yahi aap ka #4 (prominence = frequency × importance) hai, aur Christensen ka "job-to-be-done" lens — "log product ko ek kaam karwane ke liye hire karte hain."

5-step recipe (aap ki tarteeb)

  1. Screen Naam · kiske liye (user) · platform. Ek line.
  2. Job Ek main kaam. Phir likho: kya numayan, kya dheema.
  3. Modules Us kaam ke hisaab se blocks/sections — har block mein kya.
  4. Wireframe Sirf grey boxes, lines, placeholders. No colour, no asli tasveer. Grid par align. Sabse ahem action sabse numayan.
  5. Why Har bade faisle ki ek-line wajah ("ye yahan isliye kyunke…").

Worked example — the editor shell

Chalo isi recipe ko aap ki sabse pehli screen par chalate hain — poora editor frame (the "spine").

1 · Screen: Editor shell (/edit/:id) · kiske liye: agency builder jo ek site banata hai · platform: Desktop.
2 · Job: "Is page ko banao aur publish karo." → Numayan canvas + Publish; dheema rail icons, status, footer.
3 · Modules: Topbar (site-wide actions) · Rail (jobs, ek waqt mein ek) · Drawer (active job ka panel) · Canvas (kaam ki jagah) · Inspector (selected cheez) · Footer (status).

Low-fi · grey boxes only · dark box = the one hero

  1. aExit top-left. Escape hamesha pehli jagah dhoondhi jaati hai (left-to-right reading). Site-wide action → topbar, canvas nahi.
  2. bPublish = sirf dark box. Ek screen par ek hero (#5). Baaki sab outline. ⋯ rare cheezein chhupata hai (#9).
  3. cRail = locked spine. 4 slots, Insert #1 hamesha. Naya feature andar dock hota hai, naya icon nahi (#15).
  4. dCanvas sabse bada. Job "page banao" hai → kaam ki jagah ko sabse zyada room. Prominence = area (#4).
  5. eInspector right, on-demand. Sirf jab kuch select ho. "You are editing this" + 3-reach = plain language (#1).
  6. fFooter = whisper. Status/zoom zaroori hai par kaam nahi — sabse dheema, neeche, chhota.

Low-fi ka anushasan (kyun grey)

Wireframe ka poora maqsad hi "final nahi" hai. Colour ya asli tasveer dalte hi log layout par baat karna chhod ke "ye neela acha hai?" par aa jaate hain. Isliye:

box = koi bhi element dark = sabse numayan (hero) dashed = khaali / placeholder ✕ box = tasveer aayegi
  • Copy ki jagah grey bars — asli text likhne se aap copywriting mein phans jaate ho. Structure pehle.
  • Prominence size + position se, colour se nahi. Bada + upar/center = ahem.
  • Grid par align — sab kuch ek base spacing par snap. Tedha alignment = baad ki guesswork.
Krug ka usool: wireframe ko "sahi" nahi, "testable" banao. Grey boxes 5 minute mein phenk sakte ho; painted mockup se aap shaadi kar lete ho. Decide → draw → walk → fix.
