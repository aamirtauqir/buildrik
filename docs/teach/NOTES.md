# Notes — how to teach this user

## Confirmed preferences
- **Roman Urdu + English mix.** Technical terms stay English.
- **Concrete worked examples beat principles.** A Sara-the-restaurant-owner walkthrough with
  ASCII screens landed; an abstract option-list did not. When an explanation failed, the fix was
  always "make it a story with real screens", never "explain more".
- **Caveman mode is on** — drop filler, fragments fine, keep all technical substance.
- **Drive, don't quiz.** One recommendation + confirm. Long option-lists get rejected.
- Founder, not a designer. Makes product calls, hires execution.

## Teaching hooks that work
- Use **their own doc's real failures** as the material. Higher trust than any textbook, and
  they already have the context loaded.
- They spot gaps fast and push back hard ("is mein bohat kuch miss hai") — and they are usually
  right. Treat pushback as signal, re-audit rather than defend.
- They asked for Codex cross-review unprompted — they value adversarial second opinions.

## Watch out
- Don't over-explain. When they said "itna explainery kyun hota hai", the fix was fewer words
  and one concrete picture.
- Don't claim something is fixed without verifying — they have caught overclaims twice.
