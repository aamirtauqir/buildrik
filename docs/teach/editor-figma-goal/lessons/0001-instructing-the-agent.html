Telling an agent to implement a Figma design — cleanly, in one goal

Mission: direct an AI agent to apply your Figma foundations to the whole editor, remove the old design, and prove it with tests — like a real developer.

Aap code nahi likhte — aap agent ko direct karte ho. To asli skill CSS nahi hai. Skill yeh hai: ek accha goal likhna — scoped, phased, verifiable. Yeh lesson aapko wo goal deta hai, aur samjhata hai har hissa kyun hai.

Pehle ek sच्च: aapka Figma (g4GzQFqzNYz5sosz1QtZXC, node 32-2) sirf foundations hai — colour, type, spacing, radius, size tokens. Ismein koi naye screen/flow nahi. To "design apply karo" ka matlab hai: yeh visual language poore editor pe consistently lagao. Agar naye layouts chahiye, wo alag Figma chahiye hoga.

02Aapka goal — copy/paste ke liye

Yeh grounded hai aapke codebase pe (tokens, gates, vibcoder, 311 hex drift). Isko paste karo, agent ko bolo "run as one goal, stop at Phase 0".

GOAL — Editor ko Figma "Foundations (32-2)" pe le aao, clean.

# SCOPE
Source of truth: Figma g4GzQFqzNYz5sosz1QtZXC, node 32-2
(Foundations page — sirf tokens: colour, type 11 styles, spacing,
radius, size). Apply karo POORE editor chrome pe: rail, sidebar,
canvas-chrome, topbar, footer, inspector, panels. Naye layout NAHI —
sirf visual language unify + purana/drifted styling REMOVE.

# PHASE 0 — AUDIT (koi edit nahi, phir RUKO)
- Figma tokens padho: figma MCP get_variable_defs + get_metadata
  (file g4GzQF..., node 32-2). Har token nikaalo.
- Current tokens map: src/themes/design-system/*.css.
- Diff table banao: Figma value vs current value — har mismatch.
- Saara hardcoded hex grep: src/editor/**/*.tsx (~311). Surface ke
  hisaab se list — rail/sidebar/canvas/topbar/footer/panels.
- Audit doc likho. RUKO. Mujhe dikhao edit karne se pehle.

# PHASE 1 — TOKEN RECONCILE
- Har design-system token ko Figma value ke exactly barabar karo:
  colour.css, typography.css (11 styles), spacing.css, radius.css,
  layout.css size tokens (rail 60, inspector 300, drawer 320,
  panel-right 360, topbar 56, header 44, footer 32, nav 240, rows).
- Ek source of truth. Duplicate token def NAHI (DS SSOT respect).

# PHASE 2 — APPLY + PURANA HATAO
- Har chrome surface tokens use kare, hardcoded value nahi. 311 hex
  ko token vars se replace.
- Inspector wali 32-2 language (compact pills, UPPERCASE section
  labels, type scale, density) baaki sab surfaces pe consistently.
- Dead/purani CSS + orphan class rules delete karte jao. Clean,
  additive nahi.

# PHASE 3 — VERIFY (jaise real dev)
- Token-conformance test: assert har design-system token === Figma
  value (fixture figma MCP se). Drift wapas aaye to FAIL.
- Visual regression: Playwright screenshots har chrome surface ki
  (editor route pe); baseline ek baar, phir diff.
- DS gates chalao: pnpm verify:ds (SSOT, no-hex Gate 24, baseline).
  Yeh isi design ko ENFORCE karte — GREEN rakho.
- tsc dono package + vitest.

# GUARDRAILS
- Gates MAT hatao — woh yeh design enforce karte. Agar kisi gate ka
  baseline number ek legit naye value ko rokta hai, sirf US baseline
  ko adjust karo aur reason likho. Kabhi blanket-disable nahi.
- Har phase report + commit (solo -> main). Phase 0 pe RUKO review ke liye.

03Har hissa kyun (taake aap adapt kar sako)

  • "Source of truth: Figma …node 32-2" — agent ko exact file batao. Warna woh apni marzi ka design bana dega. Scope
  • "Phase 0 audit, phir RUKO" — sabse important. Agent pehle dikhata hai kitna kaam hai. Aap scope dekh ke tab green light dete ho. Mass-rewrite se pehle brake. Phases
  • "311 hex ko token se replace" — yeh "purana design remove" ka asli matlab. Hardcoded colour = drift. Token = ek jagah se control. Clean
  • "token === Figma value test" — yeh woh cheez hai jo real dev karta. Agar kal koi token Figma se hat gaya, test foran fail. Design locked. Verify
  • "Gates mat hatao" — aapne bola tha "rule rok raha ho to hata do". Ulta: gates isi design ko enforce karte (token use karo, hex mat likho). Hatana = drift ko invite. Guardrail
Woh "rule hata do" wali baat: 90% waqt jo gate design ko "rok raha" lagta hai, woh actually design ko protect kar raha hai. Agent ko bolo: "gate ko samjhao pehle, hatao mat — sirf agar ek specific baseline number literally naye value ko block kare to us number ko adjust karo." Yeh ek line aapko bade regressions se bachati hai.

05Vibcoder — agent ko yeh batao

Vibcoder aapki component library hai (chrome ke buttons, inputs, pills, panels). Aapko iska code nahi aata — koi baat nahi, agent ko yeh rules do:

# Vibcoder rules (goal mein add karo)
- Chrome primitives yahan: src/editor/shared/vibcoder/ (React)
  + src/themes/components/ (CSS).
- Primitive restyle karna? Wahi files EDIT karo. Buildrik-owned hai,
  fork/wrapper mat banao.
- Sirf tokens use karo: --buildrick-* / --bd-*. Inline hex kabhi nahi.
- Naya primitive? vibcoder mein add + matching CSS themes/components/
  mein + @import themes/default.css mein.

Ek line mein: "vibcoder ko fork mat karo, uski files direct edit karo, hex ki jagah token."

06Aapke liye 5 tips (kisi bhi agent goal pe)

  1. Hamesha Phase 0 = audit + RUKO. Agent ko andha mat chhodo. Pehle scope dekho.
  2. "Source of truth" naam se do. Figma link, file, ya doc — exact. Guess-room zero.
  3. "Verify" ko goal ka hissa banao, baad ki soch nahi. Test = design lock.
  4. "Clean, additive nahi." Yeh 3 shabd purana code delete karwate hain, banner nahi.
  5. Guardrails likho — kya nahi karna. Gates, blanket-delete, scope-creep.

Primary source (padho): Buildrik ka apna design contract — packages/editor/CLAUDE.md ka "DESIGN SYSTEM — SSOT CONTRACT" section. Woh batata hai token kahan rehte, vibcoder kaise extend hota, kaunse gates hain. Yeh aapki apni sabse high-trust reference hai.

Agla kadam: Yeh goal main abhi khud run kar sakta hoon (Phase 0 audit se, jahan aapko scope dikhega). Ya aap ise kisi aur agent ko de sakte ho. Bolo — main Phase 0 audit start karun?
