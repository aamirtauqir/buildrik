## Found on the way

- **CMS RecordsTable crash (blocks C-4 and half of D-11):** opening any CMS collection throws `TypeError: Cannot read properties of null (reading 'dir')` in `RecordsTable`'s `head()` function (`packages/editor/src/editor/cms/RecordsTable.tsx`), caught by `StudioErrorBoundary`, crashing the whole CMS panel to "Something went wrong / Please reload." Reproduced 3× (owner, editor, fresh reload). This is a significant, previously-unreported product bug — the CMS panel is unusable in this build. Console stack captured in the run transcript (`packages_editor_src_editor_cms_0lcb5-~._.js:2758`).
- **`isForbiddenSaveError` regex doesn't match real permission errors** (see C-9): the A15-9 "mid-session demotion" recovery contract in `useSaveCallback.ts` never fires against a real server 403/PermissionError — it falls through to the generic "Save failed" path, which does not call `keepUnsaved()`, so unsaved work is silently NOT offered for recovery after a role downgrade.
- **Content-issue scanner (missing-alt / broken-link) doesn't surface in the Issues panel** even though the underlying page data is confirmed correct on the wire (see B-14/A02-9) — a second, independently-found bug from the same investigation.
- **Server-side `prePublishChecks` has no alt-text/broken-link check at all** — confirmed by source inspection, not just a missed wire-up. If this parity is expected/planned, it doesn't exist yet.
- **`/dashboard/projects?sort=traffic` doesn't actually sort by traffic** — the batched `sites.list` call always sends `"sort":"lastEdited"` regardless of the URL's `sort` query param, seen while capturing D-11's network evidence. Not chased further (out of scope for D-11 itself).
- The always-present third-party design-annotation overlay widget (bottom-left avatar) from the first pass is still present in this build and still occasionally intercepts pointer events in headless runs (worked around with `force: true` clicks in a couple of places this pass).
