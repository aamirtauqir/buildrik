## Found on the way

- **Cross-agent DB contamination, again**: at the start of this pass, S1's Home/About/Contact pages had all been overwritten to identical "Contact" content (heading "Contact", "Reach out to us.", "Email us" mailto link) and the seed's slider on Home was gone entirely — consistent with the same interference `results-editor-b.md` reported from a concurrent verifier session. This cost significant time in X-4 (had to re-add a slider from scratch) and made the Home/About/Contact page tabs visually indistinguishable throughout this run (clicking any of the 3 tabs showed the same content), which is itself worth someone double-checking isn't a real bug once the shared DB is quiet — this pass could not tell contamination apart from a genuine tab-routing defect by observation alone.
- **A recurring "server has the update, client never refreshes it" pattern**: X-1 (renamed version name), X-6 (dynamic-pages count), and X-4 (added component never reaching `pages.blocks`) all show the same shape — a mutation lands correctly in Postgres (confirmed by direct query/API readback) but a fresh reload of the editor UI still shows the pre-mutation state. This looks like one underlying caching/hydration issue hit from three different UI surfaces, not three unrelated bugs — worth investigating as one root cause.
- **VIEWER's Sharing tab still shows an enabled "+ New link" button** (`shots/X11-5-viewer-access-tab.png`, top right) — out of scope for X-11 as specced, not clicked/tested, but worth a follow-up check on whether the create mutation is actually gated server-side for VIEWER the way `sharing.revoke` clearly is.
- The Next.js dev-mode error overlay ("ResizeObserver loop completed with undelivered notifications") reliably fires and steals `[role="dialog"]`-based selectors whenever the Command Palette is opened in this build — a harness trap for anyone else automating ⌘K in this environment; use a more specific selector (e.g. a cmdk-specific attribute) instead of `[role="dialog"]`.
- The editor's dev/annotation floating widget (bottom-left "N" avatar, "Output Detail / Manage MCP & Webhooks / ...") is present on every screen in this build and its hidden panel copy leaks into `body.innerText()` captures — same finding already logged in `results-editor-b.md`.
