## Found on the way

- **X-A1 is real and reproducible**: fresh `/edit/<siteId>` loads can render the wrong page's content under a correctly-highlighted tab. Only observed on S1; not cross-checked against other sites, but the mechanism (tab-selection state racing content-fetch) is generic enough to likely affect any site.
- **Settings and Brand full-page screens hide the left rail entirely** — there is no rail-tab click available to trigger navigation-away while either screen is open; the only way out is the screen's own "‹ Back to canvas" link (or, for Settings, "Exit" isn't present either). Any check written as "click a rail tab to navigate away" needs to instead use "Back to canvas" for these two screens specifically.
- **Cmd+K fuzzy search can match live canvas content over intended commands** when the query is a short generic word (e.g. "export" matched a testimonial's question text before matching the "Open export settings" command) — a UX risk for command discoverability, not a correctness bug.
- **`data-buildrik-id` (as used in several check descriptions) does not exist** — the real attribute is `data-buildrick-id`. Any future scripted check using the literal string from the checklist will silently return 0 elements.
- Command palette chord badges (`cmdk-kbd-*`) are pixel-exact at 20px as specced in Figma-derived tokens.
