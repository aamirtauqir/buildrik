## Found on the way

- **`sites.publish` mutation response includes the raw `log.pages[].html` payload** (`server/services/publish.service.ts` `startPublish` returns the full Prisma job row; `server/trpc/routers/sites.ts`'s `publish` mutation forwards it verbatim). This contradicts the documented discipline stated in comments on `getPublishStatus`/`getPublishedSnapshot`/`getPublishHistory` ("raw HTML payload NEVER leaves the service"). In practice this only echoes the caller's own just-submitted HTML back to themselves (not a cross-user leak, and `publishStatus`/the SSE stream both correctly omit `log`), but it's a real deviation from the stated invariant and worth a one-line fix (strip `log` before returning from the mutation) for consistency with the rest of the publish surface.
- Raw `curl`/`fetch` with cookies copied out of a Playwright `storageState.json` gets a false **401 Unauthorized** from `/api/sse/publish/<jobId>` even though the same cookies authenticate fine against `/api/trpc/*`. A real browser context with the same storageState gets 200. This looks like a harness quirk (cookie flags/SameSite handling differs between `auth()`'s direct cookie read and however tRPC's context resolves the session) rather than a product bug — flagging in case it recurs for another verifier using raw HTTP instead of a browser.
- Verify WS is seeded at 6 members against a 5-seat PRO limit (`team.invite` refuses immediately with "Team member limit reached"), which blocked one live B-5 check (see above). Not a bug — just a seed/fixture note for whoever owns invite-flow verification next.
