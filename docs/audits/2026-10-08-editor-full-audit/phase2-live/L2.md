### L2-001 "Save page as template" corrupts the page HTML; applying the saved template strips almost all styling
- Module / Screen-location / Feature: Templates · ⌘K "Save page as template" → Templates catalogue → apply
- Labels: BROKEN FUNCTIONALITY · CODE ONLY ISSUE
- Category: Broken existing feature
- Type: Functional
- Severity: Critical
- Problem: The save step replaces design-token *values* with `{{token…}}` placeholders by plain substring matching. It does this inside hex colours, rgba numbers, element ids and pixel values. The token names it writes contain spaces, and the apply-side regex cannot match those.
- Expected behavior: A saved template round-trips. Applying it recreates the page as it was, with token-bound values re-mapped to the destination site's brand.
- Current behavior: LIVE. I saved Home, a dark SaaS page.
  - The stored HTML (localStorage `buildrick-my-templates`) contains `background: #{{token.radius.radius none}}a{{token.radius.radius none}}81e` (it was `#0a081e`), `rgba(124,1{{token.radius.radius none}}9,…)`, `data-buildrick-id="el-…d2h{{token.radius.radius none}}ibwr5w"`, `gap: 2{{token.spacing.space 2}}`, and 11 distinct broken placeholders.
  - Applied as a new page, the nav came out with background `rgba(0,0,0,0)` and padding `0px`. Every dark section is gone, so the white text sits on a white page.
  - Screenshots: `37-applied-saved.png`, `35c-saved-preview.png`.
- Figma status: board 1169:4753 ("Tokens are snapshotted — applying it later re-maps them")
- Code status: `editor/sidebar/tabs/templates/utils/inverseResolveTokens.ts:~60-80` (no token boundary; it matches `0`, `2`, `8px` and similar anywhere). `resolveTemplateTokens.ts:18` (`[a-z0-9-]+` cannot match "radius none"). Called from `editor/shell/hooks/useStudioHandlers.ts:111`.
- Integration impact: The template is also mirrored to the server (`userTemplates.upsert` returned 200), so the corrupted template spreads to every site in the workspace.
- Probable root cause:
  - It reverse-maps token values with a regex alternation over raw values, with no CSS-value tokenisation and no attribute or style scoping.
  - The snapshot's token names are display names that contain spaces.
- Dependencies: tokenSnapshot naming, `resolveTemplateTokens`
- Recommended next action:
  - Only reverse-map whole declaration values inside `style=""`, by property (colour props get colour tokens, spacing props get spacing tokens), and only colours that are not 0.
  - Use slug token ids.
  - Strip `data-buildrick-id`.
  - Add a round-trip test: save, then apply, then compare computed styles.
  - Repair or delete templates already saved.
- Evidence: LIVE-VERIFIED
