The rule (one default, others opt-in): editing always lands on the narrowest rung — Element — unless you deliberately climb. Today all five are reachable at once and the editor silently picks one, so changing one button breaks twelve. The fix: one default path (Element override), and every wider rung is an explicit, counted opt-in. Climb up = "make this reusable / push it wider"; the count tells you the blast radius first. You can never pick the wrong layer by accident — the wrong layers aren't even active until you ask for reach.

Why it confused people — the same visual change was reachable through up to four layers, with silent cascade winners (grounded in current engine)
"Make this button blue"ElementClassPreset → TokenComponentWho wins today (silent)
background colour inline override .btn-primary rule binds → --color-accent master style patch Element override beats class by CSS cascade — so a token/class edit silently does nothing here. Confusing.
padding / radius inline override .btn-lg rule binds → --space / --radius master patch Same trap — inline wins; the "global" edit appears broken.
a repeated CTA block override one — — edit master If you style an instance then the master syncs, your edit can be clobbered unless you detached first.
How the ladder resolves it: the five layers don't change — they stack in one fixed order (Element → Class → Component → Preset → Token, narrow wins). The UI now (1) defaults every edit to Element, (2) names the rung you're on in the scope banner, (3) makes climbing wider an explicit, counted opt-in, and (4) when a narrower override would mask a wider edit, says so — "this element overrides the class; reset to inherit?" So there's exactly one path by default, the cascade is never silent, and Pro users still reach every layer — just legibly.
