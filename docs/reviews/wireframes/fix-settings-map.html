WIREFRAME · LOW FIDELITY
Settings map — the dedup fix. Agency users said "good features, but I can't tell where a setting lives." Root cause: the same setting showed up in 2–3 places (Account vs Workspace vs Site vs Editor). This screen is the cure: one home per setting, sorted into 4 scopes. Everything else becomes a read-only "opens in X" deep-link — never a second editable copy. Grounded in account.* / siteDetail.* / billing.* tRPC + the editor Settings tab.

The scoping rule (one question decides the home): "If this setting changed, what is the blast radius?" just me → Account everyone in the org / billing → Workspace one site's deployment → Site the pages I draw → Editor/Design.
How dups were resolved: every setting gets exactly one editable HOME. Where a second scope legitimately needs to see it, that scope shows a read-only "↗ opens in X" deep-link, never a second input. No setting is editable in two places — that was the whole "good features, not user-friendly" complaint.
Duplicates found & how each was resolved
The 9 collisions agency users hit — each now has a single home, the rest demoted to deep-links.
Setting (was in 2–3 places)Where it used to live (ambiguous)Resolution — one home
Language & timezone Account profile · Workspace default · Site locale Three different settings, badly named the same. Renamed: Account="my language", Workspace="org default (seeds new sites)", Site="enabled locales". No dup — disambiguated.
Brand / accent color Workspace accentColor · Editor Palette · Site favicon Editor → Palette owns the site's brand. Workspace accent = dashboard chrome only, relabeled so it stops masquerading as site brand.
Favicon Site settings · Editor General → Site Identity Site is home. Editor "Site Identity" row becomes an ↗ deep-link (already the pattern in BrandingSection).
SEO defaults (title template / OG) Dashboard SEO (d5) · Editor SEO screen · per-page Site → SEO owns site-wide defaults. Editor shows the effective value read-only + per-page override stays in Editor.
Redirects Dashboard site settings (14/d3) · Editor Settings plumbing Site → Settings (edge ops). Editor row = ↗ deep-link, never editable in canvas.
Custom code & headers Site settings · Editor "Custom code / Headers" screens Site owns site-wide <head>/CSP. Editor keeps only per-page <head>; site-wide is ↗ deep-link.
Integrations / GA4 Workspace webhooks · /settings/integrations (Vercel) · Editor Analytics (GA4) Split by purpose: Workspace=org webhooks + hosting OAuth; Site=analytics tags (GA4/Plausible/Pixel). Two homes, two purposes — no overlap.
AI credits Account "AI credits" page · workspaceId-scoped pool Pool is Workspace (it's billed there). Account page keeps a read-only mirror + "Upgrade" deep-link.
Sharing & password Workspace sharing defaults · per-site published password / share links Workspace=defaults for new links; Site=this site's actual links & password. Default vs instance — disambiguated.
Net effect: the editor's existing "↗ opens Dashboard" boundary (§3, screens 14 / 53) is generalized into a full 4-scope map. Zero settings stay editable in two places; ambiguous same-named fields (language, brand color, sharing) are renamed by scope so users stop guessing.
