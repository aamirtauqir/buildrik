PROTOTYPE · M-ROLES · CAPABILITY MATRIX
M-roles — the capability matrix by role (the hidden 5th decision). Codex: the 4 ownership calls force this — exactly which writes each role can do. Replaces the obsolete 62-permissions (old Owner/Editor/Viewer). This is what makes the agency handoff safe and resolves "who can edit SEO / redirects / analytics." Role = permission (set by the agency on invite). Density (Simple/Pro) = a separate preference.
The 4 roles set per-member, per-site, on the invite — independent of the Simple/Pro view setting
Viewer
Read-only. Sees the live/preview site + analytics. Comments only. The "show the client" role.
density n/a
Content editor
The agency's client (the person). Edits content on assigned sites — text, images, page SEO. The white-label handoff role. Named by capability, not by "Client" (which is the account/company node).
defaults to Simple
Designer
Agency staff who builds. Full make-side + redirects + technical SEO + publish. Site-level, not the money/team.
defaults to Pro
Admin
Agency principal. Everything, including workspace: team, billing, white-label, integrations, shared theme. (Owner = Admin + transfer/delete.)
defaults to Pro

Two rules that make this not-confusing
1 · Density ≠ permission. Simple/Pro changes how much surface SHOWS (preference, per-user-per-site). Role changes what you CAN DO (permission). A Designer can run Simple; a Content editor can't unlock Pro capabilities by flipping density. 2 · Every hidden or disabled control says WHY. Greyed because of density → "Turn on full controls to see this." Greyed because of role → "Your role can't edit this — ask an admin." Never an unexplained disabled button. This is the single thing that stops the "missing feature" and "why is this disabled?" support tickets codex predicted.
This closes the loop: ownership map (where each concept lives) × this matrix (who can write it) = a complete, safe IA. The last open piece is the shared theme change contract (footnote 3 + audit finding A) — the one workspace action that needs its own review surface.
