PROTOTYPE · M0 · FOUNDER ARTIFACT
M0 — the spine, in 30 seconds. One rule, one tree, one journey, one example. The dense inventory + dedup table + dual-rail proof live in M0-spec (engineer appendix). This page is what answers the founder's "is it connected, and where's the agency."
Every feature has one home on the tree. Every screen sits on one journey. You only see the depth you ask for. The product never had this rule — that's why it felt overcrowded and scattered. This is the whole fix.

Boundary = the tree itself. Site business ops (domains, analytics view, submissions) + Workspace + Client → Dashboard. Site content & config (SEO, forms) + Page·Section·Element → Editor. ★ = the agency node v1 was missing.

The product is this line. "Modes" are gone — the rail is just the tools Edit needs, at the depth you asked for.
One example — SEO had three doors, now it has one
Before — guess which door

Editor › Settings › SEO
Editor › Pages drawer › SEO
→

Same rule applied to Analytics, Forms, Custom code, Publish — full list in M0-spec §dedup.
Where the agency lives — the 4 gaps, each one home (detail in M-agency)
Shared theme
One DS at Workspace, pushed to every client site. Editor Theme → "publish to workspace."
Multi-client
Dashboard › Clients list → sites under each. One place to run 30 clients.
White-label
Workspace › Branding — what the agency's invited client sees. Agency brand, not Buildrik.
Speed
Duplicate as template — stand up client N+1 from client N in one action.
How much shows (not the spine): a per-user fewerfull controls setting — set in account settings, seeded by role. The agency works with full controls; a client gets the calm, fewer-controls view (same 4 tools, no jargon). The agency can preview it any time with 👁 Client view in the editor. Reversible, hides-never-deletes.
