# CEO Plan: Editor 5-Features Expansion (Templates · Components · Design System · Workspace · Collaboration)
Generated by /plan-ceo-review on 2026-06-25

## The one-line strategy
Make the agency superpower real: **build once (component, template, theme), reuse everywhere (every client site), cleanly (no revert, no surprise, no drift).** Today all three propagation paths are broken, fragmented, or unshippable. Fix the foundations, then layer the delight.

## Vision

### 10x Check
An agency onboards a new client and is 80% done before touching the canvas: they pick from THEIR curated template library, drop in THEIR shared components (which already carry the client's brand via the pushed theme), and invite the client to comment/approve — all without rebuilding anything. One brand tweak propagates to 6 sites with a preview and a rollback. That is the Webflow-for-agencies wedge.

### Platonic Ideal
The editor feels like a design system that happens to render websites. Every reusable thing (token, component, template, theme) has one home, propagates predictably, and shows you the blast radius before it changes anything. Collaboration is ambient (presence + comments) for everyone and real-time for those who turn it on. A new engineer reads the component-sync path and says "oh, overrides are just a patch layer re-applied after clone — obvious."

## Accepted scope (ALL 25 items — dream big)

### Foundation fixes (Phase 0 — baseline, must precede enhancements)
- **F1 Component override survival — PHASED** (eng-review + 2nd outside voice re-sequenced this). The program's #1 risk; mandatory, critical-path, highest blast radius. Budget a heavy regression suite + a kill-switch flag.
  - **F1a (now, zero-migration):** (1) Kill the **3 coexisting override-path schemes** — `recordInstanceOverride` writes `#/children[0]/...` (position), `ComponentInstance.getPropertyPath` writes `/elements/${id}/...` (ephemeral clone ID, dies every resync), and `buildInstanceTree`/`detachToElements` apply overrides as JSON-Patch vs masterTree (a 3rd format `getOverridesForElement` never reads → **detach is already silently broken**). Pick ONE. (2) Wire the **already-written** `syncToMaster` diff-rebase (`createPatch`/`applyPatch`/`overridesConflicted`/`errors`, `ComponentInstance.ts:199-243`) into the live `syncInstance` — which today spreads `{...instance}` and discards the conflict machinery (`ComponentInstances.ts:237`). (3) Add render-resolution for **content/attr/trait**, not just style (`ElementStyles.ts:158` resolves style only). Fixes master-edit-without-reorder with NO migration.
  - **F1b (phase 2, only if overrides must survive master REORDER/INSERT):** stable `slotKey` on master elements. Real deliverable = **backfill migration** (stamp existing IndexedDB + `site-component.service` masters + rewrite every instance's override paths in one txn — else first sync evaporates all customizations), **orphan-GC + emit** (slotKey absent in new master ⇒ drop + warn, not silent), **idempotent re-stamp** (`updateComponent` rewrites masterTree wholesale `ComponentManager.ts:237` — preserve existing keys, mint only for new), **nested-component key qualification** (inner master flattens into outer at clone — keys must be path-qualified or tree-globally-unique). NOT a footnote.
- **F2 Template SSOT — FULL 3→1 collapse** (user decision, against both reviewers' caution). Collapse `template.service` (DB gallery), editor `SITE_TEMPLATES`, and `user-template.service` into one model + seed the gallery. **Regression-mitigation (mandatory, since reviewers flagged it):** `useTemplate`'s site-limit + unique-slug + page-count logic (`template.service.ts:83-134`) MUST be preserved; the unifying migration is **additive/backward-compatible** (no destructive schema change to `template.pages`); a smoke test proves dashboard site-create-from-template still works before/after. Note the two genuine shapes being merged: site-templates = page-level `{name,slug,blocks}` scaffolding; block-templates (T1) = element subtrees — the SSOT model must hold both as distinct kinds, not flatten them.
- **F3 Workspace authz — WIRING AUDIT** (rescoped DOWN per outside voice — primitives already exist). `permission.service.ts` already has `ROLE_RANK`, `checkWorkspaceRole`, `checkSiteRole`, per-site `roleOverride`, all four roles. F3 = grep every workspace mutation (`updateWorkspaceSettings`, `updateSharingSettings`, folder-create, etc.), wire the **existing** `checkWorkspaceRole(OWNER|ADMIN)` guard where missing. Plus `createWorkspace` mutation — **plan-gated: multi-workspace is Pro/agency only; free plan stays at the 1 signup workspace** (closes the per-workspace site-cap bypass; natural agency upsell, ties into `revenue-trust-plan.md`).

## Cross-cutting risk registries (the 11-section review, folded)

### Architecture — new coupling + the one big infra gap
- F1 touches the engine's component-sync hot path (`ComponentInstances.ts`). Highest-blast-radius change in the program; gate behind a regression suite before any enhancement rides it.
- Collab (X1-X4) needs a **realtime transport** Buildrik does not have. Current `collab.service` is a poll-based op-log. Presence/comments can ride polling or SSE; X4 co-edit needs a websocket + CRDT doc store. **This is a genuine infra + cost decision (see Decisions D-A).**
- Client portal (W3) + comments (X1) add a new **external-facing identity** (the agency's client, not a workspace member). New auth boundary — scope carefully.

### Error & rescue map (the gaps that would ship silent failures)
| Codepath | Failure mode | Rescued today? | Required action |
|---|---|---|---|
| `theme.service.pushSharedTheme` → N sites | one site write fails mid-push | partial-state risk | per-site txn + push-result report ("4 ok, 1 failed"), not all-or-silent |
| F1 override re-apply | override path no longer exists in re-cloned tree | N (would silently drop) | log + surface "1 override could not re-apply" to user, don't swallow |
| collab op apply (X4) | concurrent op conflict | N (corrupts — the 6 P1 bugs) | CRDT resolves by design; until then keep X4 flag OFF |
| `collab.service.appendCollabOp` prune | `Math.random()<0.02` prune → low-traffic site grows UNBOUNDED; busy site prunes ops a >24h-offline client still needs → resync gap | N (silent) | **PRE-REQ for all Phase 3**: deterministic time-based retention + resync-from-snapshot fallback when the seq gap can't be filled. Do NOT ship X1-X4 on the current op-log. |
| `createWorkspace` (F3) | plan limit / dup | must throw domain error | reuse PLAN_LIMITS gate pattern |
| Template gallery (F2) | empty after seed fails | N (blank screen) | empty-state UI + seed verification |

### Security & threat model
- **F3 is itself a security fix** — current "any active member edits sharing settings" is an authz hole. Every workspace mutation must call `checkWorkspaceRole(OWNER|ADMIN)`.
- W3 client portal = new attack surface (external users). IDOR-scope every portal read to the granted site only; no workspace traversal.
- X1 comments = user-generated content rendered in chrome → sanitize (DOMPurify SSOT already exists in the editor).
- Realtime channel auth: every collab/presence socket must verify workspace membership on connect, not just on the initial page load.

### Observability (day-1 needs)
- Theme push: metric `theme.push.sites_updated` + `theme.push.failures`; a failed multi-site push must alert.
- F1 override-sync: counter `component.override.reapply_dropped` — if this climbs, the fix regressed.
- Collab: `collab.active_sessions`, `collab.op_conflicts` (must stay 0 with CRDT).

### Deployment / rollout
- Every enhancement ships behind a feature flag (pattern exists: `FEATURE_COLLAB`, `featureFlags.ts`). X4 stays OFF until the spike clears.
- F1 ships with a one-flag kill-switch to fall back to current behavior if override-reapply misbehaves in prod.
- DB migrations (template SSOT F2, theme versions D2, audit log W4, comments X1) must be backward-compatible / additive.

### Long-term trajectory
- Reversibility: F1 = 2/5 (engine hot path, hard to unwind once enhancements depend on it) → land it carefully, test heavily. Everything else 4/5 (flag-gated, additive).
- Platform potential: F2 template-SSOT + C1 component-usage-index + D-versions together become a **"reusable-asset graph"** other features (search, analytics, AI-suggest) can build on.
