### Lesser findings (recorded, no defect number)

- **A 409 on the site's own project gets the wrong message.** If `removeDomain`'s best-effort detach fails, the domain stays on our Vercel project. Re-adding it then gets a 409 and the message "used by another Vercel project", which is wrong in this case. Same for a domain added by hand in the Vercel dashboard. Check `getVercelProjectDomain` on a 409 before refusing.
- **Cron vs "Check DNS" race.** Both may run `dnsRecord.deleteMany` + `createMany` at once, with no transaction. Interleaved, they duplicate the record rows. The status outcome is the same either way.
- **Cron checks soft-deleted sites.** `verifyPendingDomains` does not filter on `site.deletedAt`, so it keeps calling Vercel for domains of soft-deleted sites. These calls count against the cap of 20 per run.
- **The Add-a-domain dialog draws a `_buildrick` TXT for a Vercel-connected workspace.** `connect` will neither write nor require that record (Q6).
- **The ZIP export never contains `sitemap.xml`.** `generateZip` calls `exportAllPages` without `includeSitemap`/`baseUrl`, and no UI path sets them. Claim 4's ZIP half is wired but unreachable. Verified live: the ZIP held `index.html`, `about.html`, `blog/post.html`, `hidden.html` and `styles.css`, and nothing else.
- **IDN names are accepted only in punycode.** `HOSTNAME_RE` is ASCII-only. A limitation, not a regression.
- **The sitemap's noindex filter is a regex.** It needs `name=robots` before `content=…noindex`. The editor always emits it in that order; a robots meta from custom head code written in the other order would be missed.
- **Console noise.** The export modal's preview iframe logs "Blocked script execution … sandboxed". This predates the batch.
