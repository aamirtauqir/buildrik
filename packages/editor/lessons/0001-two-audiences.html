Lesson 01 · One component system

The two audiences

Aap ne kaha: purani CSS aur bekaar cheezein delete kar do, design kharab ho to koi baat nahi, bas business logic na toote. Ye lesson wo ek line sikhata hai jo tay karti hai ke delete karna safe hai ya nahi — aur wo line design ke baare mein hai hi nahi.

Aap ka apna constraint hi jawab hai

Aap ne do cheezein saath kahin: "design kharab ho to theek hai" aur "business logic na kharab ho". Ye tab tak alag alag lagti hain jab tak aap ye na dekhein ke editor mein CSS do alag cheezein style karti hai:

Audience 1 — aap

Editor chrome

  • Sidebar, rail, inspector, topbar, modals
  • Yahan design toot-ta hai to aap dekhte hain
  • Aap fix kar sakte hain, aaj hi
Audience 2 — aap ka customer

Published site

  • Canvas ke andar ki HTML, exported site, Vercel par live page
  • Yahan toot-ta hai to customer ka client dekhta hai
  • Aap ko pata bhi nahi chalega — koi test nahi pakadta

Doosri wali CSS delete karna cosmetic nahi hai. Wo product output hai — bilkul waisa hi jaise publish function tor dena. Aap ke apne constraint ke andar aata hai.

Kaise pehchanein — ek scanner ye kabhi nahi bata sakta

Chrome CSS ke class names aap ke .tsx mein likhe hote hain. Customer wali CSS ke class names engine runtime par likhta hai. Isliye koi bhi dead-CSS scanner Canvas.css ko 100% dead batayega: 

// blocks/Components/Slider.tsx:277 — ye string customer ke page mein jati hai
'<div class="buildrick-slider" data-buildrick-type="slider">'

Aaj 33 aise buildrick-* class names hain jo blocks/, templates/ aur engine/ se customer ki HTML mein emit hote hain. Un mein se ek ki CSS delete karein, aur har wo site jo pehle publish ho chuki hai — toot jati hai.

Ye is session mein waqai hua Maine 96 CSS classes ko "unreferenced" mark kiya. Sirf 63 delete huin. Baqi 33 mein se kuch template literals se bante the (med-fmt-btn${active ? " active" : ""}), kuch node_modules likhta tha, aur kuch customer HTML mein jate the. Ek plain grep ne 9 classes ko dead kaha tha — 7 zinda thin.

Pehle ratchet ye sab gin raha tha. Matlab css_lines ka farsh 1,438 tha — wo kabhi zero nahi ho sakta tha, chahe aap poora chrome convert kar dete. Ek aisa gate jo hil hi nahi sakta, use log --update se aage badha dete hain aur wo matlab khona shuru kar deta hai. Ab list explicit hai, har row ke saath wajah likhi hai.

Aaj ka win Kuch bhi delete karne se pehle ek command chalayein. Agar iska jawab khali nahi hai, wo customer ka hai — haath mat lagayein. 
grep -rhoE 'class="[^"]*your-class' src/blocks src/templates src/engine

Ek scanner kehta hai Canvas.css ki saari 800 lines unreferenced hain. Aap ne kaha hai design toot-na acceptable hai. Delete karein?

Wo chrome hai hi nahi. Uske class names engine runtime par likhta hai, isliye har scanner use dead batayega. Delete karne se aap ka apna editor bilkul theek dikhega aur customer ki live sites toot jayengi — aur suite bhi green rahegi, kyunki koi test published HTML render nahi karta.

Aage kya

Ye pehli line thi. Doosri line ye hai ke flowbite har cheez nahi kar sakta — aur wo aap ke repo mein pehle se rendered-DOM evidence ke saath likha hua hai. Lesson 02 wo padhna sikhayega, taake aap khud faisla kar sakein ke kaunsa flowbite component adopt karna safe hai, docs ke waade par nahi.
