Lesson 02 · One component system

Three libraries, two graveyards

Aap ne kaha "vibcoder ke components delete kar do". Wo 28 July ko mar chuka — 29,179 lines, ek commit mein. Uska replacement 31 July ko mara. Ye lesson wo tareeqa sikhata hai jis se dono safely mare, kyunki aap ka baqi ka plan usi tareeqe se chalega.

Vibcoder tha kya

Khud likha hua library nahi tha. Pehla commit (7a4328fe, 26 April) saaf kehta hai: 

shared/vibcoder/ is the single import surface for
chrome JSX consuming vendored components.

Yani bahar se copy ki hui UI kit, aur har component par ek patla React wrapper taake chrome ka ek hi import surface ho. Bilkul wahi kaam jo aaj chrome-ui/ flowbite ke liye karta hai.

Peak par 56 components the. In naamon ko dekhein:

ListRow · Menu · Modal · EmptyState · Toolbar · Popover
Skeleton · Tabs · FormField · SectionHead · Badge · Slider
Ye sab se aham observation hai Yehi naam chrome-ui/ aaj bhi ship karta hai. Library badli, par jo shapes ek visual editor ko chahiye wo nahi badle. Aap teesri baar wahi cheezein bana rahe hain.

Ab wo hissa jo copy karne layak hai

Library pehle delete nahi hui. Chhe slices ne har consumer hataya, aur delete aakhri qadam tha — jab count pehle se zero tha:

SliceKya move hua
1topbar
2rail + drawer
3Tooltip + leftovers
4saat dialogs → ek Modal

Deletion commit ki apni line: ratchet 402 → 0. Gate baqi imports ginta tha, aur delete tab hua jab wo number zero ho gaya. Isi liye 29,179 lines ek commit mein ja sakin aur 7,803 tests green rahe.

Himmat se zyada tarteeb ahem hai Pehle delete karke baad mein theek karna: ek saath sainkdon toota hua import. Phir aap bata hi nahi sakte ke kaunsa asli breakage hai aur kaunsa sirf missing shim. Pehle drain karo to har commit apne aap green rehta hai, aur delete boring ho jata hai.

Aaj vibcoder ka kya bacha hai

src/ mein 13 zikr. 12 comments hain — batate hain ke koi shape kahan se aayi: 

chrome-ui/BreakpointSwitcher.tsx:2
  * segmented viewport switcher (ported from vibcoder).

Terahwan asli hai: ek test purani DOM id saaf karta hai — getElementById("vibcoder-overlay-root")?.remove(). Koi import nahi. Koi component nahi. Koi CSS nahi.

Aap ko MediaTab.css (1,777 lines) hatani hai. Uske classes 24 files use karte hain. Sab se safe pehla qadam?

Wahi tarteeb jis se vibcoder mara: drain pehle, delete aakhir mein, gate ko zero dikhne do. Pehla option har commit ko red kar deta hai. Doosra behtar lagta hai par CSS ko tw: mein "convert" karne ka matlab hai wo 24 files bhi badalni — yani wahi kaam, bas gate ke bagair jo batata ke kab khatam hua. Chautha ek 1,777-line big-bang hai jise review nahi kiya ja sakta.

Aap ke liye is ka matlab

Aap ne kaha "purani cheezein delete kar do, tension mat lo agar toot jayein". Is repo ne wo do baar kiya hai — aur dono baar tension li, is shakal mein ke delete aakhir mein aaya, ek gate ke peeche jo sabit karta tha ke count zero hai. 29,179 lines bina kisi test ke red hue gayin.

Wahi ratchet aaj bhi chal raha hai, teen numbers par: inline_literal, inline_hoisted, css_lines. Wo aap ka 402 → 0 hai.
