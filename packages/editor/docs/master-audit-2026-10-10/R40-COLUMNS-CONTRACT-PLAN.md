# R40 — Columns structural-count contract and finite design plan

13 October 2026. Independent read-only source audit following R39. This is a proposed design contract for root to author in the existing improved Figma page `8463:2`, file `g4GzQFqzNYz5sosz1QtZXC`. Only this report was written. No source/test, Figma, browser, register or status edits; no tests run. Findings below are source observations and derived risks, not reproduced runtime failures.

## The task to design

Select a Columns element, change its number of actual column elements, understand exactly which content a reduction removes, cancel or confirm, and recover the same content with one Undo. Separately edit responsive Gap through canonical Style. Never use the shared CSS Grid Columns control to stand in for creating/removing column children.

Existing entry: Columns Settings root `8843:25014`. R36 register rows `columns:1`–`columns:5` contain only ID/Title/Tab index/CSS classes/Data attribute; there is no inventoried structural count control. Existing canonical Style root `8841:14864` has Layout Columns `8841:14909` and Gap `8841:14919`. The former is a CSS track count, not the missing structural count. IDs are register evidence, not a fresh Figma inspection.

## Verified source contract and defects

|---|---|---|
| Ownership and eligibility | `src/shared/constants/elementCapabilities.ts:154` gives Grid and Columns the same `grid` type block and `layout:false`. `src/editor/inspector/sections/typeBlock/bodies/layoutBodies.tsx:46` selects Columns property rows only when the primary element's actual type is `columns`. Source type block belongs to Style (`src/editor/inspector/sections/registry/type.tsx:15`). | Improved architecture should place the structural operation in Settings, with appearance routed to Style. This is an intentional design correction, not current source tab parity. |

Do not claim strict integer validation: strings such as `2.5`/`2abc` parse to 2 in this handler. Keep existing 2–6 choices in a source-faithful chooser; record 1 as an unresolved range decision. A future numeric field must reject noninteger input visibly. |
| Default/read | The builder creates 2 or 3 children (`src/blocks/Layout/Columns.tsx:9`, `:19`; `src/blocks/builders.ts:116`). Neither builder nor count handler writes `data-columns`. `PropertyField.tsx:141` reads this attribute rather than child count; the default select option is empty/`Default` (`src/editor/inspector/shared/controls/InputControls.tsx:450`, `:492`). | New or revisited controls can display Default/stale metadata although the actual children differ. Show actual child count, not metadata or a universal default. Imported/stale metadata needs reconciliation in implementation. |
| Increase | Count handler reads every direct child via `getChildren()`, creates `container` children with class `col`, content `Col N`, and appends through `el.addChild` (`attributeWriter.ts:77`–`:87`). `src/engine/elements/manager/ElementCRUD.ts:35` gives new elements generated IDs. | Preserve existing IDs/order/content. Added columns are new placeholders, not clones of existing content. Do not claim only `.col` children are counted: source counts all direct children. Unexpected direct child types require an explicit production contract. |
| Reduce | Handler removes direct children from the end, highest index first (`attributeWriter.ts:89`). `ElementCRUD.ts:148` detaches each child, recursively removes its descendants and deletes IDs from the element registry; it emits ELEMENT_DELETED and marks dirty. | Entire trailing subtrees disappear; no content redistribution or archive is performed. Name the affected columns and content before committing. Increasing count later creates new placeholders; it does not restore deleted content. |
| Count reset | Empty value parses to NaN and returns without structural change. Choosing the existing count creates/removes nothing (`attributeWriter.ts:74`, `:80`, `:89`). | No `Reset to default` operation is defined for structure. Use Undo for the previous count change. Same-count selection is a no-op and must retain the previous useful Undo snapshot. |
| Transaction / failure | `PropertyField.tsx:191` filters writable parent targets then wraps every selected target's change in one `runTxn("element-prop-change")`. `attributeWriter.ts:30` always calls endTransaction in `finally`; it does not call rollback on error. `src/engine/Composer.ts:1255`, `:1263`, `:1277` batches dirty notifications and captures the outer transaction snapshot. | Normal application is intended as one document edit. An exception after some changes is not guaranteed atomic by this helper: failure recovery/rollback is a runtime gate. The finite prototype should not simulate partial success as complete. |
| Undo scope | `src/editor/inspector/hooks/useStyleHandlers.ts:117` flushes pending edits/history before and after discrete controls; SelectRow uses field.discrete (`InputControls.tsx:483`). `src/engine/HistoryManager.ts:385` captures tree/tokens; `:516` flushes pending changes then restores previous state. | The normal count change is intended to have one-step document Undo. Fresh proof must check restored child IDs, descendants, order and content, not only count labels. No Columns-specific real-engine Undo test was found in the inspected test. |
| Selection / return | Removing a selected element or its ancestor selects the surviving parent, except page root, which clears selection; it also removes deleted IDs from multiselection (`ElementCRUD.ts:111`). History restores the existing active page where available and re-resolves selected IDs to rebuilt instances (`HistoryManager.ts:427`, `:596`). | Keep the initiating Columns parent selected in the finite task. Do not promise Undo automatically reselects a formerly deleted child: tree history is not a snapshot of prior selection. Preserve breakpoint, Settings tab and focus return separately. |
| Parent locks | `src/engine/commands/commandOperations.ts:192` drops locked selected targets and emits LOCKED_ELEMENTS_SKIPPED; missing targets are ignored. `src/editor/inspector/ProInspector.tsx:150`, `:238` makes fields read-only when the primary element is locked or save conflict is pending. | Root locked means legible read-only count with reason. Source can skip some selected parents; do not show an all-target success when some are skipped. |
| Descendant locks / components | Count reduction directly invokes low-level `removeElement`, which has a page-root guard but no locked/instance check (`ElementCRUD.ts:96`). Outer writableElements checks only the selected parent. Normal delete's stronger guard rejects component instances and locked descendants (`commandOperations.ts:40`). | This is a source safety inconsistency. Proposed count confirmation must revalidate every removal subtree, blocking locked/protected removals before mutation. Do not claim this protection already exists in the count path. |
| Mixed selection | ProInspector targets primary plus other selected non-root IDs (`ProInspector.tsx:142`). If Grid is primary, CSS GridControls appears instead. Avoid hiding this as a generic all-selection contract. |
| Refresh after edits / Undo | `PropertyRows` reads values in an effect keyed by composer, primary id/type and rows, then stores local state (`PropertyField.tsx:177`). It does not subscribe to tree/element updates. | Immediate local choice can look correct while external change/Undo/reopen is stale. Read-back accuracy is a separate runtime gate. |

## Gap and CSS grid count stay separate

Columns Gap is configured as `data-gap` with None (`0`), 8px, 16px, 24px, 32px (`layoutBodies.tsx:28`). Its reader gets the attribute, but `PropertyField.tsx:161` routes writes to `handleColumnsGapChange`, which calls `el.setStyle("gap", value)` (`attributeWriter.ts:104`). This sets base CSS regardless of current breakpoint/pseudo state. It does not update `data-gap`. Empty is passed to setStyle as an empty string rather than using the canonical removal route (`src/engine/elements/ElementStyles.ts:131`).

Corrected ownership: Settings `Gap` → `Edit in Style →` opens existing Layout Gap `8841:14919` within Style `8841:14864`, preserving Columns and current device/state. General Gap offers px/rem/em/% with separate advanced Row gap and Column gap (`src/editor/inspector/sections/layout/GapRow.tsx:13`). Canonical Inspector style handlers write the selected pseudo rule and media query, or base/current-breakpoint declaration; empty removes the scoped property (`src/editor/inspector/hooks/useStyleHandlers.ts:340`). Direct breakpoint helper has the same remove-at-scope intent (`commandOperations.ts:267`). Full effective Tablet→Mobile cascade is still an open gate.

The shared CSS grid count (`style/layout:Columns`, `8841:14909`) accepts integer 1–24 and writes `grid-template-columns:repeat(N,1fr)`; blank removes that style (`src/editor/inspector/sections/layout/GridControls.tsx:53`). Its label should be `Grid columns` where needed to distinguish it from `Column elements`. Changing grid tracks reflows existing children; it does not add or remove their content. Only show it when a grid layout is applicable; do not introduce display:grid as a hidden side effect of editing the Columns structure.

## Finite Figma task specification

Reuse the existing Settings/Style shell, shared select/link fields, existing confirmation-dialog master and recovery affordance. Add the missing controls/leaf states inside this existing module. New node IDs are for root to record after authoring; do not reuse `8841:14909` for structure.

| J — mixed/incompatible selection | For a minimal safe structural fixture, count is read-only with `Select one Columns element to change its column elements.` | This is a deliberately bounded design state, not a claim that source lacks bulk editing. Homogeneous multi-Columns bulk editing needs a later per-parent consequence preview and aggregate mixed count; it stays open rather than silently disappearing from parity. |

The three-item fixture is sufficient to demonstrate removal of meaningful content and exact restoration; a later increase after removal must show new placeholder content, never imply it recovers Contact. If only 2/3/4 are authored interactively, keep 5/6 capability and range explicitly open; do not advertise full 2–6 parity based on a three-state demo.

Confirmation is required by this proposed task only when count reduction removes existing column content, because the source operation deletes subtrees. It is a design action inside the prototype, not a request for the real user to authorize this audit. For production, preflight the target's revision, actual child order/count and affected subtree identities before commit; if any changed, refresh the preview rather than delete a different column. A finite stale-target leaf can say `These columns changed. Review the updated removal before continuing.` with Review/Cancel and no mutation.

## Acceptance checks and remaining limits

1. Settings entry is discoverable; count accurately names actual column elements and scope is all breakpoints. Gap route reaches canonical Style with captured parent/device/state.
2. Increase retains old child identities/content/order, adds a new placeholder, and Undo removes only the new child. A same-count action is a no-op.
3. Reduction opens the correct affected-content preview. Cancel/Escape/close preserve membership, count, content and previous Undo state. Confirm removes the named subtree; Undo restores its original identity/content/order.
4. Locked parent and locked descendant are distinct blocked fixtures; mixed/incompatible selection never reports a successful homogeneous write. Missing/stale target has a no-write recovery path.
5. Device switching demonstrates global structure, while Gap demonstrates only the scoped base/Mobile sample. CSS grid track changes, if included, leave all child identities/content intact.
6. Read authored reactions for destination/context/state correctness, then visually play the actual child/layer/spacing outcomes. A changed label or destination URL is insufficient. Exact keyboard focus, true persistence, generic arbitrary children, bulk selection, component permissions, nested content serialization and failure rollback remain runtime/design gates as applicable.

Existing inspected Columns test only uses mocks to assert that choosing 3 creates/adds three children (`src/editor/inspector/sections/typeBlock/__tests__/typeBlockBodies.test.tsx:79`). It does not cover deletion, content/ID recovery, locks, mixed selection, metadata read-back, responsive Gap or real history. No fresh test pass or browser parity is claimed here.
