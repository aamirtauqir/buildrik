## Concrete evidence boundaries and handoff gaps

1. **Exact restoration must name what is being proved.** The Columns plan requires original child IDs/content/order after Undo. A Figma fixture can preserve a logical identity manifest and reveal the same native specimen; it does not execute engine deletion, serialization or history restoration. The final report should distinguish authored logical identity, observed specimen/layer return, and still-unverified application ID restoration. A count changing back to 3 is insufficient.
2. **Protected removal is a proposed behavior change.** The source audit reports a stronger normal-delete guard than the current count-reduction path. A locked-child or component-blocked prototype is evidence of the intended correction, not proof that the existing application protects that subtree. Preserve that distinction in the control register and handoff.
3. **Columns is not complete when the finite 2/3/4 fixture works.** Keep 5/6, unresolved count 1, unexpected direct child types, homogeneous bulk editing, mixed Grid/Columns, component eligibility, stale target, exception rollback, read-back after Undo and full keyboard contracts individually visible. The current plan already does so; the closure report must not compress them into “runtime only.” Some still need design decisions and states.
4. **Responsive Gap and global structure need separate outcomes.** Count reduction affects every breakpoint; Gap writes a selected breakpoint/state. A no-Tablet Desktop/Mobile sample cannot settle the real Tablet cascade. Verify Gap leaves child identity/content/count unchanged, and that a device switch retains structural removal. CSS Grid tracks, if touched, must retain all children.
5. **The control inventory will need additive reconciliation.** The 529-row register predates Columns count/removal/Gap-link additions. Once root authors them, record new control/confirmation/recovery IDs and their scope; mark the CSS track row distinctly. Do not keep claiming 529 as the current complete authored-control count without recounting the changed inventory. This is a closure action, not a defect in the current historical R36 count.
6. **Historical queue items need narrow supersession.** `R39-COVERAGE-HANDOFF-AUDIT.md` was written at R38 closure and still lists Icon ownership as future work. The newer R39 report links and supersedes that bounded part; it does not settle full Icon contracts. Preserve the queue's chronology or add a dated disposition later so the next worker does not redo the same ownership fix. The source-audit action list is likewise pre-authoring advice, not current status.
7. **Selection-label readback is recorded only narratively in the reviewed packet.** R39 states that `I8843:21698;8314:8` was corrected to “1 selected element” after the walks and read back. I did not find that exact late readback in the reviewed saved mutation/native receipts. This does not invalidate the behavioral evidence or imply the label is wrong; retain a small final receipt on the next affected-root inspection if independent reproducibility is required. Do not imply older screenshots show the corrected label.
