## Current findings

### RR-01 — Review revoke checks one site but can target a different site in the same workspace

**P1, source-confirmed authorization gap; not exploited.** `server/trpc/routers/reviews.ts`, `revoke`, checks EDITOR on `input.siteId`, obtains that site's workspace, then calls `revokeReviewRound(workspaceId, input.reviewId, input.expectedRevision)`. `server/services/review.service.ts:461`, `revokeReviewRound`, updates by review ID + workspace + revision + unrevoked status; neither its update nor fallback read constrains the review to the authorized site.

An editor allowed on site A who knows a live review ID/revision on site B in the same workspace can cross the intended site boundary. Revision knowledge is a prerequisite; this audit does not claim a demonstrated discovery path. Workspace scoping blocks another workspace but does not enforce specific-site grants or per-site role caps. The audit activity would also be attributed to supplied site A. Existing router tests assert workspace forwarding; service tests cover outside-workspace refusal, not same-workspace/different-site refusal.

Required contract after approval: derive the target site from the review or bind the review mutation to the already-authorized site, and test same-workspace cross-site grants and role overrides. No fix is implemented here.

### RR-02 — AI publish action omits ordinary publish freshness and loaded-state safeguards

**P1, source-confirmed divergent publish contract; no deployment attempted.** `src/editor/sidebar/tabs/ai/hooks/useAiActionGate.ts:68` exports current composer pages and confirms the action with `{pages}`. `server/services/ai-actions.service.ts:66` calls `startPublish(siteId, actorId, pages)` with no expected baseline. Its payload schema carries only optional pages. `server/services/publish.service.ts:392` checks staleness only when `opts.expectedLastEditedAt` is present.

The ordinary `src/services/PublishService.ts:80–92` path rejects a never-loaded project or missing site settings, waits for the save baseline and supplies `expectedLastEditedAt`; `sites.publish` forwards that value. The AI route still enforces EDITOR and the shared approval/deployment gates and uses a single-use confirmation, but these do not replace document freshness. Thus stale exported pages can reach publish without the ordinary conflict test, and the loaded-project/settings boundary is absent from the AI gate itself. This is a source-level risk, not a claim that a live site was overwritten.

Required contract after approval: all page-payload publishing paths use an explicit fresh baseline and loaded-state checks; a stale tab and failed-load fallback must be refused before deployment. The current action-service test verifies role recheck, not baseline parity.

### RR-03 — Issues may announce “No issues” after server checks fail

**P2, source-confirmed false confidence.** `src/editor/shell/hooks/useIssuesFeed.ts:127` clears `checkIssues` on a pre-publish check fetch rejection. Returned `scanState` describes only the local content scanner. `src/editor/shell/IssuesPanel.tsx:246` renders “No issues.” when the merged array is empty. With no local findings, loss of server checks is indistinguishable from a complete clean assessment. Publish's separate error state does not inform someone currently viewing Issues. No fault injection was performed in the browser.

Required contract after approval: preserve last known checks or explicitly mark server checks unavailable; a clean result must name its evaluated scope.

### RR-04 — Viewer Review door and backend read permissions disagree

**P2, source-confirmed integration mismatch; role-fixture runtime pending.** CommandPalette tests intentionally retain Review among viewer read-only doors. ReviewTab's `load` at `src/editor/sidebar/tabs/review/ReviewTab.tsx:233` uses one `Promise.all([fetchCurrentRound(), fetchReviewComments()])`. With agency enabled, `reviews.currentRound` requires EDITOR, while `comments.list` allows any member with site access. A VIEWER therefore cannot render even permitted comments through this coupled load. With agency disabled, currentRound returns null before the EDITOR check, but review entry points may be hidden by that flag. Separate issue: Review's reply textarea is disabled for VIEWER although `comments.create` expressly allows viewers; product intent should resolve this inconsistency rather than silently widening permissions.

Required contract after approval: establish intended viewer comment/review scope, align entry/read/composer contracts, and exercise an actual VIEWER session. Existing mocked UI tests do not cover the real router combination.
