# Phase 5 capability and compatibility boundaries

10 October 2026. A factual annotation reference for the later authorized design phase; **no TO-BE screens, implementation sequence, migration plan, API change or Phase 7/8 work is created here**. Gate 4 is still open. These boundaries prevent a visual proposal from silently promising unsupported output or declaring a runtime defect repaired.

## Existing contracts to preserve in design

| Domain / trace | Current source-supported capability | Constraint on later design claims |
|---|---|---|
| Public project representation | `src/shared/types/project.ts:33–73` defines version/pages/page order/styles/assets/metadata/settings and optional CMS bindings plus migration flags. `Composer.exportJSON():1010` serializes `exportProject()`. Token settings retain schema version, tokens, dark mode and flat preset bindings (`project.ts:296–353`) | Reorganizing controls must preserve page/element/token/component/binding identity and existing saved-project interpretation. A project JSON serializer is not proof of a public JSON option in the Export dialog. No schema/version migration is part of this design task. |
| Export formats — F-027 / AS-39 | `ExportOptions.tsx:26–30` offers HTML, ZIP and React; Vue/Next.js are disabled Soon. Do not imply full React application scaffolding, Vue/Next output or successful browser archive/download QA merely because names occur in types. Current source supports output paths; production parity remains unverified. |
| Preview — F-026 / UX-09/11 / IA-08 | Site Preview, template preview and Brand live preview use `sandbox="allow-same-origin"` without allow-scripts (`PreviewOverlay.tsx:209–211`, `TemplatePreview.tsx:135`, `BrandLivePreview.tsx:234`) | Show a visual/content validation surface with stated script limits. | CMS/import/dynamic pages — F-019–021 | Collection/schema/record/binding chains exist; public project data persists bindings. | Brand vs editor tokens — F-024/078 | Site Brand persists tokens, presets, dark-mode policy and bindings; current token Apply/presets can write immediately. Editor chrome uses its own Tailwind/Flowbite/chrome-ui foundations | Do not merge site styles and editor UI tokens, or add a fictional final Brand Save to describe current behavior. Keep source capabilities and existing project token identities compatible; arbitrary future extraction/generation remains separate. |
| Settings and forms — F-017/032–034 | Footer-authored fields, immediate object actions and workspace doors use different save/permission scopes. Form Behaviour explicitly says site settings save immediately outside Undo and Send to requires admin | Model the real scope of Save/Discard/Undo. Site Settings Members/Billing/Integrations are dashboard handoffs, not duplicate editor-owned management. No design claim of email, DNS, OAuth, billing or webhook success without real service evidence. |
| Collaboration/review/publish — F-025/028/029/036 | Review/comment/publish services have separate scope and role boundaries; multiplayer remains production-gated. Share preview can create a token on open | Do not turn unavailable collaboration into a working feature through mock avatars or role labels. Explicitly distinguish prototype simulation from server authorization, approval, freshness and deployment state. |

## Critical findings that need engineering, beyond visual treatment

This is a dependency classification for honest design annotations, **not an implementation roadmap or an authorization to fix code**. The finding register remains authoritative on priority/confidence. Later TO-BE frames may propose intent; their notes must retain these dependencies.

| Findings | Design can specify | Why a visual change cannot close the finding |
|---|---|---|
| CAN-01/02/03; CI-01 | Resize coordinates/feedback/cancel, lock and responsive scope, one-operation Undo | Engine/geometry/input/transaction and mutation-gate behavior must change and be verified. Finite dimensions and preserving unrelated history cannot be proved by a static screen. |
| UX-09/10/25; IA-10; R-04/05/09 | Effective/inherited/authored values, override origin and correct Preview context | CSS cascade, value derivation and preview/export serialization must agree; restyling or substituting a corrected display value would hide the defect. |
| CI-02; IA-08 | Trigger/action state, preview limitations, reverse/cancel/reduced-motion expectations | Runtime listener lifecycle, reverse behavior and sandbox capability are executable contracts, not drawing choices. |
| IA-06; IA-07; UX-22; MENU-01; PAGE-01 | One active surface, focus return, shortcut/action scope and disabled reasons | Routing priority, focus isolation, keyboard handlers and command eligibility need implementation. Picturing a visible Activity panel does not fix Issues priority. |
| HIST-01 | Explicit compared scope and metadata differences | Diff/equality semantics must include relevant restorable metadata. A comparison label cannot make an omitted difference appear in data. |
| WS-01/02/03; RT-01 | Truthful sync/retry/local/error state and caller recovery | Persistence, rehydration, durable retry and failure propagation require runtime changes. RT-01 exact root cause remains unisolated; do not select a speculative fix in the design notes. |
| RR-01/04; RR-02 | Read/mutate role distinctions, review target identity and publish guard explanation | Server authorization and AI publish freshness/loaded-state enforcement require engineering. No attack, unauthorized revoke, publish or live role switch is needed for the design artifact. |
| RR-03; WS-04 | Unknown/error checks separated from clean/verified status | Rejected check handling and provider assurance semantics must change; renaming a green badge alone is insufficient. |
| WS-05 | Redacted credential entry/replace controls and safe status disclosure | Credential encryption/write-only API/storage boundaries are backend concerns. No secrets should enter design evidence. |

IA-02/11/12 and UX-01–08/13–21 contain presentation, hierarchy or task-sequencing opportunities that can be specified in design. Their eventual live implementation still needs validation; this classification is not a claim that those issues are already fixed. Source-confirmed security/durability findings remain source-confirmed, not newly exploited or reproduced by these documents.
