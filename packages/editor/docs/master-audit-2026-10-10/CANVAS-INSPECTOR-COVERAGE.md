## Workflow traces and what their tests establish

**Drag/add/reorder.** `Canvas.tsx` integrates `useCanvasDragDrop`; its `drag/useDropExecution.ts` reads all native DataTransfer channels before awaiting, recomputes a drop target, clears visuals, then dispatches multi-element, element, component, catalogue, template and block insertion. `dropOperations.tsx` uses transactions and rollback on throwing insert/move paths. Single-item placement respects before/after edge intent. Section reorder has a separate handle path, converts client bounds with `canvasScale`, and passes the pre-removal insertion slot to `moveElement`.

Existing tests cover payload survival, root/self refusal, nesting rejection, before/after slot contracts, transaction calls, selection callbacks and error callbacks. Most use mocked composer and rectangles. They do not establish browser DataTransfer behavior under real mouse gestures, overlay accuracy, drag cancellation history, or server persistence. `handleMultiElementDrop` chooses the target's parent at lines 103–104 and treats any non-before slot as after at line 133: specifically probe an advertised **inside** drop for a selected group of siblings. This is a source-derived hypothesis requiring a real target/indicator trace, not a newly reproduced runtime bug.

**Selection and keyboard.** Marquee waits for movement before clearing, then selects intersecting descendants; selected parent/child normalization must be evaluated through subsequent actions. The selected marquee suite primarily tests the 5px clear threshold, not the complete intersecting-element geometry. `useCanvasKeyboard` owns navigation, modifier nudges and sibling reorder; `keyboardHelpers.ts:103` reads active-breakpoint styles and routes writes through `writeCanvasStyles`; reorder uses `writableElements`. Arrow tests mock helpers, while breakpoint/lock tests exercise the helper boundary. CommandCenter text-field tests cover shortcut refusal while typing. None replaces a keyboard-only task through actual chrome focus, menus and editable content.

**Grouping.** Engine grouping requires two siblings, inserts a container at the earliest index and moves selected elements in document order. Ungroup moves children back before removing the container. The three real-Composer tests verify simple tree shape, fewer-than-two refusal and ungroup restoration; they do not prove lock handling, history boundaries or layout preservation. The coordinating browser audit separately verified four-sibling Group→Undo with IDs/order retained; see [extended runtime audit](EXTENDED-RUNTIME-AUDIT.md). Inspector now explains cross-parent ineligibility, but context menu and keyboard command still use a different eligibility path. Preserve IA-04 rather than treating every Group door as equally broken.

**Inspector.** `shared/constants/elementCapabilities.ts` is the type table. `InspectorTabContent.tsx:76–82` intersects capabilities for every selected type and then evaluates runtime section predicates. Registry tests establish gating for text/container/media, type-specific behavior and component instances. `useStyleHandlers` checks `canWrite` at input time and `writableElements` again when its 300ms pending write flushes; changes to selection/breakpoint/pseudo scope flush the captured edit. Reset and discrete controls have separate flush/transaction behavior. The real-Composer `discreteUndo` suite is stronger history evidence than mocked begin/end calls, but still does not exercise resize cancellation or every inspector section.

**Responsive preview.** The inspected source supports the mechanism behind UX-09: `Composer.exportHTML:930` combines element HTML and `styles.toCSS`; `shared/utils/html/generation.ts:111–118` emits base styles inline. `StyleEngine.ts:540` generates ordinary rules without `!important` by default. The live canvas separately appends `editorDevicePreviewCSS` (`StyleEngine.ts:689`), which intentionally adds `!important` to beat inline base styles. The exported preview does not append that editor-only override block. `ExportEngine.ts:560` documents a separate class-based base-style export path. Therefore a successful published/exported responsive test does not disprove the observed **site-preview** mismatch, and the preview mismatch does not prove published output is broken.

**Interactions and site preview.** Inspector interaction writes use `writeElement`; its inline Preview button sets the selected canvas node's CSS animation directly. That is a sample of an animation, not execution of the configured event trigger. `renderPreviewHtml` (`shell/exportPublishPages.ts:161`) resolves CMS over `Composer.exportHTML`. Composer can include an interaction runtime, but `AquibraStudio.tsx:294,874` passes the HTML through `sanitizeHTMLForPreview`; `editor/export/ExportUtils.ts:39` removes scripts, forms, iframes and embedded objects. `PreviewOverlay.tsx:211` uses `sandbox="allow-same-origin"`, which also forbids scripts. The existing PreviewOverlay test explicitly asserts no scripts run; `Composer.previewInteractions.test.ts` only checks interaction attribute serialization. These are compatible passing tests around an incomplete end-to-end visitor preview. Do not remove the sandbox casually or claim arbitrary authored scripts should execute. Product policy and an appropriate safe preview runtime need a reviewed design.

## Source-confirmed finding and carried-forward failures

### CI-01 — Multi-selection alignment bypasses lock and breakpoint write contracts — P1

`inspector/components/MultiSelectBar.tsx:48–53,93,102` calls `AlignmentHandler` directly. Buttons gate only composer/selection count. The handler obtains `getStyles()` (base styles), parses left/top/width/height numerically, defaults missing dimensions to 100, then calls `el.setStyle` directly at lines 221/224. `Element.ts:211` delegates to `ElementStyles.ts:131`, which writes `data.styles` without a lock check. There is no use of `writableElements`, `writeCanvasStyles`, active breakpoint or InspectorFieldContext in this alignment path.

**Classification:** source-confirmed contract violation; live UI outcome not reproduced by this subtask. The generic inspector guard tests do not cover these buttons, and the alignment suite uses mocks without locks or responsive state. Potential consequences are locked members receiving base-style writes and mobile alignment altering desktop styles. Parsing percentage/auto dimensions and writing left/top on static elements also fails to establish meaningful visual alignment; those consequences need their own runtime fixtures.

The existing alignment suite additionally has a TODO at `AlignmentHandler.test.ts:341` for explicit `width: 0px` being replaced by the 100px fallback, followed by a passing test that deliberately pins that current quirk. This is an automated demonstration of the handler's existing zero-size arithmetic, not a successful acceptance test for correct zero-width alignment. It must remain visible in the test summary.

**Acceptance after implementation approval:** test a mixed locked/unlocked selection on Mobile; align/distribute through actual inspector controls; assert locked data unchanged, desktop styles unchanged for unlocked elements, computed positions correct in supported layouts, one undo restores only this operation, and refused/unsupported layout states explain why. Include save-conflict read-only mode, inherited/percentage/auto dimensions and cross-parent selections.

### CI-02 — Live canvas interaction runtime has known reversal and cleanup gaps — P1

`engine/interactions/InteractionRuntime.ts:333` implements reverse-on-exit only as a log statement. At lines 216/224/247 it attaches scroll/beforeunload listeners to `window`, but tracks them under synthetic event names on the element. `stop():98–107` removes listeners from those elements rather than removing the window listeners. The existing suite explicitly records both issues as `it.todo` at lines 624/628. These are **source-confirmed known implementation gaps**, not new browser reproduction, and TODO tests must not be counted as passed acceptance checks.

This is the **live engine runtime** used by `InteractionManager.startRuntime`, not the separately generated exported-site runtime and not proof that published sites leak listeners. Verify hover/focus/pressed reversal, repeated start/stop, and window-trigger cleanup against actual timelines after approval. Keep this separate from IA-08's script-free full-site preview limitation.

CAN-01/02/03 remain **runtime-confirmed P0 findings** in `PHASE-2-CANVAS-FINDINGS.md`; no changes or regression repairs were made. UX-09/10/11/14/25, IA-04/05/08/10 and MENU-01 retain their original IDs and evidence. This report strengthens source explanations without counting duplicate findings. Clone cancellation, multi-drop inside targeting and grouping locked descendants are hypotheses/gaps, not confirmed runtime bugs.

## Gate 2 disposition for this domain

This report closes the **source ownership, known failure classification, selected automated-contract execution and explicit runtime-gap accounting** portions of canvas/inspector review. Known defects may remain open at an audit gate; an audit is not a repair release. The evidence is sufficient to carry those defects into Phase 3 and design work with accurate scope.

It does **not** independently close the whole-product Gate 2. The master coordinator consolidates this domain with the other audits. For the Phase 2 **audit** gate, a core workflow can be assessed as working in its tested scope, broken, partially implemented, or runtime-unverified with a concrete tool/access blocker and completed feasible source/test analysis. No separate approval of every limitation is required. Whole-product QA certification, fixes and release readiness are later gates. The following is the smallest useful remaining runtime batch; blocked steps become explicit handoff coverage rather than a claim of success:

1. On a disposable authenticated page, Add→native drag before/inside/after→reorder→undo/redo→save/reload; compare element IDs and parent/sibling order.
2. Multiselect→align/distribute on positioned elements at Mobile with one locked member; compare base/mobile styles and computed positions. Repeat a flow-layout selection to assess availability/feedback.
3. Multiselect siblings→group→ungroup→undo, plus cross-parent and locked-descendant refusal. Verify sibling order and prior accepted edits survive.
4. Typography/spacing edit across Desktop/Tablet/Mobile and hover, clear one override, preview same breakpoint, then reload. Measure computed values rather than only input labels.
5. Configure a click/hover interaction, save/reload, try its canvas sample and site preview separately. Record the site-preview restriction as assessed unavailable behavior; exercise visitor runtime only on an authorized non-production output target.

Additional cross-browser/native touch, full accessibility, large-document performance and every type-specific field remain explicit breadth limits. The code's drag hook currently attaches no touch listeners (an existing test asserts that); touch authoring support requires a stated product policy and its own runtime evaluation.

## Supplemental source and existing-contract review

This follow-up adds F-007/045/046 assessment without starting another broad test batch. The tests named here were **read, not newly executed**. They are not added to the 373 fresh passing tests or used to claim browser success.

**F-007 internal element clipboard and deletion.** `defaultCommands.ts:267` serializes topmost selected nodes into `composer.clipboard`; it does not write the OS clipboard. `ElementCRUD.ts:257–279` clones serialized data on copy and paste so the clipboard is a snapshot and pasted trees are newly built. Cut (`defaultCommands.ts:284`) filters locked/component-internal targets before pruning descendants, stores the retained selection and removes it in one transaction. Delete (`:88`) uses the same destructive eligibility filter, requests confirmation for multiple eligible roots, and requires `{ confirmed: true }` to proceed. `DeleteSelectionConfirm.tsx:19` owns the event-driven dialog and reruns the engine command on confirmation. Paste (`:307`) chooses requested landing parents per item using nesting rules before opening a transaction, maintains offsets per parent and falls back to the active page root. Items without a target are skipped; placement itself is delegated to `pasteElement`, which emits the paste event. No new selection is explicitly made in this command body. Duplicate (`:154`) prunes nested selection, creates clones in one transaction and unlocks each new top-level copy while retaining independently locked descendants.

Existing contracts inspected: `engine/commands/__tests__/defaultCommands.test.ts` covers multi-copy/cut, nesting-aware paste, empty clipboard, locked/component refusal, multi-delete confirmation and reselection; `deleteLockedDescendant.test.ts` uses real Composer to check locked descendants and ancestor preservation; `canvas/__tests__/DeleteSelectionConfirm.test.tsx` covers confirm/cancel command routing; `useCanvasKeyboard.clipboard.test.ts` checks that the canvas hook stands down for registry-owned shortcuts. The fresh `CommandCenter.textfield` suite separately passed and establishes text-field shortcut ownership. Runtime verification currently covers duplication and selection/grouping only. Internal clipboard behavior is therefore source-assessed and contract-supported, not newly runtime-certified. Changing selection while a delete confirmation is open should be checked because confirmation reruns the command against the current selection.

**F-045 CSS animation editor.** This is an actively consumed editor, not an orphan file: `ElementAnimationRow.tsx:14,57` imports and renders it from the Interactions section. `AnimationEditor.tsx` supplies 12 entrance, 8 attention and 5 exit presets, duration/delay sliders, easing and iterations, an `onPreview` callback and generated CSS text. The historical trigger controls are intentionally absent; triggered behavior belongs to F-015. Registry `behaviour.tsx:68` writes through `writeElement` to `ElementOperations.setAnimation`, which stores config in `data.animation` and sets a `bd-anim-*` shorthand. Clearing removes both config and shorthand. Canvas injects shared keyframes at `Canvas.tsx:779`; `ExportEngine.ts:402,857` separately collects used keyframes. This separation requires output verification rather than assuming a callback or stored shorthand guarantees playback in every preview.

Existing contracts inspected: `animation/__tests__/AnimationEditor.test.tsx` covers preset counts, preserving config fields, timing/easing callbacks, default/custom CSS copy, infinite display, absent trigger controls and preview callback; `engine/elements/__tests__/Element.ops.test.ts` covers stored config/shorthand/clear. The previously executed `InteractionsSection` and `InteractionEditor` suites establish their own containing UI contracts, not direct execution of all AnimationEditor controls or a rendered animation lifecycle. No additional missing-feature defect is inferred from the existence of a separately configured interaction runtime.

**F-046 inline rich text.** Double-click or `UI_INLINE_EDIT_REQUEST` reaches the same `beginEdit`; only supported leaf tags can enter and the shared lock gate is checked at entry. The browser node becomes contenteditable and captures an original snapshot. Toolbar commands mutate that live DOM without forcing an engine rerender. Semantic formatting and safe links use Range/Selection operations; list/alignment/indent/font-size/color commands still use the browser's `document.execCommand`. Enter, blur or left-click outside commits sanitized HTML in one `inline-edit` transaction; Escape restores sanitized original content and persists nothing; toolbar focus/clicks keep the session open. Autosave owns persistence after the project change rather than an immediate local-only save call.

Existing contracts inspected: `useCanvasInlineEdit.test.ts` covers pointer-button commit behavior, pasted-markup sanitization, autosave ownership and toolbar continuity; `.gaps.test.tsx` covers eligible tags, nested-node refusal, Enter/no-change and Escape; `.locked.test.ts` covers locked entry refusal; `useCanvasInlineCommands.test.ts` covers link scheme validation and dispatch. That last suite explicitly mocks `execCommand` because jsdom cannot implement its markup behavior. Therefore a passing dispatch assertion, even if rerun, cannot close browser formatting output. Lock/permission changing after edit entry, IME composition, multiline expectations, focus/range restoration, history and remote persistence remain concrete runtime follow-ups.

**Native drag evidence boundary.** The coordinating audit owns browser work. Its CLI lacked the required native drag operation; the isolated Playwright attempt encountered a sandbox launch error and a later development-navigation timeout, then retried against the visible canvas after an empty-root zero-height locator failure. An attempted `dragTo` has no success outcome until the coordinator records the resulting tree and screenshot/DOM evidence. The final native evidence in `EXTENDED-RUNTIME-AUDIT.md` takes precedence over this attempt log. Source/hook contracts here remain useful feasible audit evidence; a tool failure is not a confirmed application drag defect and does not require declaring every drag path absent.

**RT-01 supporting mechanism, not a complete root-cause claim.** `MediaManager.ts:1146,1234` retains the local blob/asset and marks it `localOnly` when remote registration fails. `BuildrikSyncProvider.ts:830–840` intentionally clones each affected page tree and calls `dropSessionMediaUrls(root)` with no remap before server persistence. That removes a blob-backed `src`/`poster` (`sanitization.ts:270–294`) while keeping the image's identity. On library load, `MediaManager.ts:937–971` rebuilds local asset object URLs and emits an old→new URL remap; `Composer.ts:809` uses available remaps during import. A tree whose `src` was already stripped has no old URL for that remap to match. This supports how a retained local asset and same image ID with missing `src` can coexist. It does **not** establish which server/recovery snapshot supplied the observed reload or prove the unsettled save completed. The coordinating runtime and workspace audit own RT-01; no duplicate finding is added here.
