## Material obtainable gaps

These gaps concern whole task or property surfaces, not an arbitrary demand for every hover or loading permutation.

1. **Inspector breadth and viewport behavior:** Behaviour, Effects, multi-selection/locked selection and selected image/container variants; actual View/breakpoint menu and mobile editing canvas; one wider desktop shell. The coordinator's planned wide/type additions address part of this. Preview Mobile alone does not establish the mobile authoring UI. Interactions belong under Behaviour in the current [state spec](AS-IS-INSPECTOR-STATE-SPEC.md).
2. **Settings beyond General:** Overview, SEO, Redirects, Domains, Access, Analytics, Form submissions, Languages, Custom code, Security headers, workspace doors and danger-action presentation are distinct current screens. Empty, failed or plan-restricted versions are valid AS-IS results. Reading them does not require provider changes, publishing, secret entry or dangerous actions.
3. **Content detail states:** actual page settings tabs; image asset details/edit-cancel; selected CMS field, dynamic pages and collection settings; component detail/instance scope where an existing fixture can be reopened. If a fixture truly cannot be recovered without additional data work, label that boundary rather than pretending the empty manager covers the populated task.
4. **Brand beyond tokens:** Styles, Component styles, Classes, Presets, Brand checks, Starters and Import/export are distinct read-only destinations. Capturing them does not require applying a starter or changing the design system.
5. **History and action boundaries:** existing-save comparison, Published tab (including empty), one version overflow and representative page/Layers/media menus. Current selected-element actions do not stand in for all menu owners. Existing historical compare evidence makes read-only comparison a feasible target; external deployment comparison is separate.
6. **Evidence reconciliation and visual checking:** publish the complete node/state ledger, persist source captures currently under temporary paths, and record which frames were visually compared and corrected. Review more than the three sampled screens, especially full workspaces, overlays, iframe content and the wider layout. Do not call all screens faithful solely because native text/vector creation succeeded.

A newly captured genuine error or empty state can close the corresponding screen-level gap when that is the state currently accessible. This does not require altering backend data to produce a preferred happy path. Low-level permutations can remain explicitly bounded; the major obtainable destinations above should not be collapsed into a generic “source covered” completion claim.

## Legitimate unavailable or excluded states

- Successful AI/provider operations, review emails/comments/client sign-off, publishing, deployment rollback, DNS verification, billing and OAuth: not needed to force for reconstruction. Existing read-only screens and source-backed unavailable branches remain truthful evidence.
- Share preview is unusually sensitive to opening: `PreviewShareModal.tsx:76–83,107` can create a token on open when none is reusable. Preserve this boundary; do not obtain a screenshot by casually creating public access.
- Actual viewer/other-role sessions, session expiry and concurrency conflict: cannot be certified by visual DOM changes, flags or a mock role. Record source/test state references until genuine fixtures exist.
- Native drag transient states: prior attempt did not produce a verified outcome. The source/geometry audit is not a captured successful drop. Keep this limitation separate from ordinary settled canvas screenshots.
- Missing raster content, shadows, pseudo-elements and font substitutions: inspect and annotate the actual reconstruction. A font substitution can be documented; it cannot support an exact-fidelity claim.
