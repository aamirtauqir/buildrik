# Phase 6 expansion acceptance

The user's 12 October correction is the controlling scope. Phase 6 stays open until product coverage and design review are satisfied.

| Area | Design acceptance | Runtime dependency |
|---|---|---|
| Inspector | Selector/class usage, explicit breakpoint/state, readable origin, scoped reset, flex/grid/box controls, semantic settings, interactions, mixed/locked selection | CSS cascade, capability registry, command transactions, computed styles and export parity |
| AI | Element/page/site scope visible; generation, review, apply/discard/undo, stale/error/quota/history states | Provider success, usage accounting, scope enforcement, freshness and durable history |
| Agents | Task bounds, plan approval, progress/cancel, result diff, partial approval, failures, stale state and attributed run history | Agent executor, action grants, sandbox/tool permissions, job durability and billing |
| Collaboration | Roles, presence, comments, versioned review, invite confirmation, offline/conflict resolution, human/agent activity | Server authorization, delivery, convergence, reconnect and personal undo |
| Whole product | Reconcile the 81-row feature/service inventory and 55-type inspector matrix with current Figma | User acceptance and later implementation plan |

Screen count alone is not acceptance. Native graph validation is not browser playback. Product proposal states are not evidence of implemented services.

Remaining integration items must be called out: type-specific inspector adaptation (forms/CMS/components/media), empty/loading/permission-change states, notification/invite expiry/revocation flows, and end-to-end cross-module consistency with the older CMS/Media/Brand/release designs.
