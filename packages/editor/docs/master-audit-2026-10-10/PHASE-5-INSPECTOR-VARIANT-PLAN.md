# Phase 5 inspector and canvas variant plan

Status: content and capability plan; no Figma screen is claimed built by this document. Root owns the shared TO-BE shell, responsive profiles, and Phase 5 gate. Assigned native area starts at x=12000 on page `8312:2`; use the shared kit and its tab/header contract. Geometry baseline: rail60, left280, right300, header56, canvas context40, footer36; Inter12/13, canonical blue #1A56DB (root reconciled with AGENTS.md). These are proposed design dimensions, not new runtime measurements.

The design uses existing actions and field capabilities. Changes to action eligibility, effective values, grouping, focus and gesture safety remain engineering dependencies identified outside product UI. Screens use a coherent example site and labeled selection; they do not imply any backend operation succeeded.

Root's shared inspector contract is **Style / Content / Effects**. Style owns layout, size, spacing, typography, fill and border. Content owns existing element source/text/alt/link/form/CMS, accessibility and attribute controls. Effects owns shadow/filter/transform and a separately grouped Interactions section. This redistributes current Behaviour controls without adding capabilities. Every inspector header shows type/name, breadcrumb, Desktop or Mobile / Base context, and clear local/inherited/mixed origin. A component-instance banner sits above applicable sections. Active tabs: Content for IN-01/04/05; Style for IN-02/03/06/07/08/09/10/11. Columns start at x12000,13600,15200 with 1100px row steps.

## Coverage and exclusions

The 55-type category mapping remains authoritative in [PANEL-AND-CONTEXT-RULES.md](PANEL-AND-CONTEXT-RULES.md): Text5, Button1, Form controls7, Media6, Embeds2, Utilities2, Widgets3, Layout primitives4, General containers18, Structural child1, Behavior owners3, Reserved product containers3. These 11 representative states exercise shared controls; they do not pretend every specialized type is individually redesigned or validated.

Product-card/product-grid/product-detail have no functioning specialized commerce body and receive no invented stock/payment/checkout controls. Forms and containers receive no direct CMS leaf binding. Label lacks direct CMS binding. Collection-list owner configuration is not a leaf field picker. Media/embeds have no generic text editing. Mixed selection has capability intersection, not a union. A component instance retains its underlying type and override restrictions. A root/document and a locked ancestor are structural/permission contexts, not additional types.

No screen adds reverse animation, executable editor Preview, arbitrary external HTML paste, remote component success, publishing success, multiplayer guarantees or a provider/backend that was unavailable in the audit. An interaction chooser remains an editor action; deployed interaction behavior has a separate runtime gate.

## Shared interaction contract for later Phase 6

Selected scope and page stay visible. Inspector uses one internal vertical scroll region and a stable header; property popovers remain anchored and fit the viewport. Canvas pointer selection does not steal text-input focus. Escape belongs to the innermost popup/menu/dialog before the selection. Close returns to the opening control or a stable fallback. Applicable actions revalidate selected IDs, lock/role, component restrictions, parent compatibility and clipboard state at execution. These are proposed design and engineering acceptance rules; Phase 6 wires only the prototype transitions assigned by root.

Verification before handoff: native nodes and readable text; stable 300px inspector; no horizontal clipping; all current capability controls remain reachable; named visible selection and scope; honest disabled reasons; no technical risk IDs embedded in product UI; external per-screen notes list source controls, proposed changes, dependencies and exclusions. Record created IDs and screenshot comparison after the shared helper arrives.
