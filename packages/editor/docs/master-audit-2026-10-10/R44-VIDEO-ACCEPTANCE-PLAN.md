## Global Ratio versus scoped Style

`data-embed-ratio` is a global per-element attribute. Its three inspected values are 16:9, 4:3 and 1:1; missing/empty/unsupported values resolve to 16:9. The generated iframe uses that ratio. Moving the editor into Style must not change storage semantics or imply a Mobile override. Use **Video ratio · This video · all breakpoints**. Keep active device/context visible because the surrounding Style controls may still be scoped.

Reset removes this owned attribute and resolves to default 16:9; it does not inherit Desktop, reset Width/Height or recreate an obsolete legacy box. Raw presence must be represented separately from effective value so Undo distinguishes absent/default from explicit 16:9. An effective same-value click with no cleanup should preserve useful history; cleanup of a known legacy pair is a real change even if effective ratio stays 16:9. Do not equate zero, Auto, Hug/Fill, free dimensions or custom ratios with the three-value contract.

The source cleanup path creates a scope conflict: it writes a global ratio but removes effective height/padding through active breakpoint/pseudo Style. On Mobile it can leave inherited base cropping; multi-selection uses the primary's detector and can affect peers incorrectly. The finite design should identify one stock **base** pair, remove only that pair with the ratio edit, preserve unrelated styles, and recover raw ratio presence/value and both declarations through one Undo. Arbitrary responsive/pseudo/class/authored boxes remain open. This is a proposed correction, not source parity.

The handoff's general “Style uses current breakpoint/state” rule therefore needs an explicit Video Ratio exception. A generic Style location or override badge is insufficient evidence of ownership. Width `8841:14994` and Height `8841:14999` remain separate property contracts; avoid expanding their accepted scope merely because the ratio specimen resizes.
