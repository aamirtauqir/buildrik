# AS-IS Inspector state reference

10 October 2026. Source-backed reference for comparing current DOM captures during AS-IS reconstruction. **No redesign, Phase 5 proposal, browser capture or Figma modification is included.** The state matrix describes what the current implementation renders; it does not certify every control's runtime behavior. Use the actual captured values, selected tab, scroll position and disclosure state when reconstructing a screen. Do not replace them with cleaner defaults or values from older board comments.

## Current shell and state frame

The right column is **300px**, from `--bk-size-inspector` in [tokens.generated.css](../../src/themes/tokens.generated.css). [LayoutShell.css](../../src/editor/rail/LayoutShell.css) reserves it in the desktop grid; at viewport width ≤1366px it becomes an absolute overlay. The rail and default left drawer are 60px and 280px. At 1440×900, the audit measured the right column at 300px ([Pages/History evidence](PAGES-HISTORY-AUDIT.md)). There is no proposed width-budget threshold in this AS-IS reference.

[inspector.css](../../src/editor/inspector/styles/inspector.css), lines 15–45 and 178–193: `.bdi-panel` is full-height flex-column, overflow hidden, square-edged with a **1px left border**, no card shadow. `.bdi-panel-scroll` is flex:1, vertical auto-scroll and horizontal hidden; `.bdi-body` has zero padding. Open/summary sections have a top hairline; empty “+” rows do not. Header uses 12px padding, a breadcrumb then a minimum 28px name/action row; tabs are 32px high. Context chips use 24px targets inside 2px vertical padding. These are source CSS values, not fresh DOM measurements.

Top-to-bottom order in [ProInspector.tsx](../../src/editor/inspector/ProInspector.tsx), lines 329–409:

1. Element breadcrumb and editable name/type, AI chip, element menu and hide control ([InspectorHeader](../../src/editor/inspector/components/InspectorHeader.tsx)). A multi-selection uses `N selected · Headings` or `N selected · Elements` instead of the single icon/name input; breadcrumb points to the common parent.
2. Single-selection status marks when applicable: `Component: {name}`, CMS `{Collection.field}` chip (with ` · missing` if broken), and `Locked`. These marks are omitted for multiselection ([StatusMarks](../../src/editor/inspector/components/StatusMarks.tsx)).
3. Status line when locked or conflicted: `Locked — unlock to edit` / `Unlock`; or `This site changed elsewhere — resolve to keep editing` / `Resolve`. Conflict takes precedence ([StatusLine](../../src/editor/inspector/components/StatusLine.tsx)).
4. MultiSelectBar only when more than one ID is selected.
5. Tabs **Style · Behaviour · Effects**, spelled exactly this way. While an AI agent run is active, the controls are replaced with `AI`, run summary or `Working…`, and `Your selection is kept and restored when you go back.`
6. Context row on **Style and Effects only**; then the active tab's scrolling sections. No selected element, or the page root, routes to the separate PagePanel rather than an empty element inspector.

[ContextRow](../../src/editor/inspector/components/ContextRow.tsx): `State: Base` menu contains **Base, :hover, :focus, :active, :disabled**. Non-desktop context has a noninteractive breakpoint chip such as `Mobile · 1 override`; this is not a breakpoint selector. Non-base state with overrides adds `N :hover overrides · Reset`; non-desktop overrides add `Mobile · Revert`. Preserve these separate lines when visible; do not merge them into a redesigned scope control. Existing property/section override marks remain part of the capture.

A different selected **type** resets the active tab to Style; another element of the same type retains it. Section open/closed choices persist by `${elementType}:${sectionId}` under localStorage key `buildrick-inspector-sections-v3`. Source defaults are overridden by those choices. Advanced groups may auto-expand once per selected element when their properties have values; this is distinct from section disclosure. Sources: [useInspectorSections](../../src/editor/inspector/hooks/useInspectorSections.ts), [useAdvancedSettings](../../src/editor/inspector/hooks/useAdvancedSettings.ts), and `ProInspector.tsx:172–192`.

## Current ordered groups

Source order is [sectionOrder.ts](../../src/editor/inspector/config/sectionOrder.ts); gates are [elementCapabilities.ts](../../src/shared/constants/elementCapabilities.ts), [registry](../../src/editor/inspector/sections/registry/index.tsx) and [InspectorTabContent](../../src/editor/inspector/tabs/InspectorTabContent.tsx). “Open” below is the default in the absence of a saved choice. A valued section opens when it carries authored values; otherwise it renders its compact **+** row. “Always” in the registry still permits an explicit user's closed choice.

| Tab | Ordered labels and default display | Gate |
|---|---|---|
| Style | Component (open) → type name, e.g. Heading/Image (open) → Layout (open) → Typography (open) → Size (open) → Spacing (open) → Fill (valued) → Border (valued) → Text inside (closed summary) | Only applicable rows survive. Component needs an instance; type needs an implemented type block; Layout and text sections use capabilities plus instance-root restrictions |
| Behaviour | Fields → After submit → Slides → Playback → Collection → Link → CMS binding → Visibility → Interactions → CSS classes → Attributes | All default open except Attributes, which is a closed summary. Fields/After submit are form-only; Slides/Playback slider-only; Collection collection-list-only; Link/CMS are capability-gated |
| Effects | Opacity → Shadow → Filters → Transform & motion → Advanced | First four valued; Advanced closed summary, normally `Cursor: auto · Blend: normal`. No type capability filter on these entries |

Common shorthand used in the matrix: **S** = Size → Spacing → Fill → Border; **B** = Visibility → Interactions → CSS classes → Attributes; **E** = the complete Effects sequence above. These are source eligibility sequences, not a claim that every section is expanded or visible without scrolling.

## Multiselection controls and preserved defects

[MultiSelectBar](../../src/editor/inspector/components/MultiSelectBar.tsx) appears before tabs. **Align** has six action buttons, with accessible labels **Align left, Align centre, Align right, Align top, Align middle, Align bottom**. No alignment choice stays selected. **Distribute** has **Horizontal / Vertical**, disabled below three targets with `Distribute needs 3 or more elements`. **Group** requires common non-null parent and has `Group needs elements that share a parent` when unavailable. Footer text is exactly `Edits apply to all N. One Undo restores all N.` This is current product copy; it is not a blanket audit guarantee.

## DOM-capture reconciliation record

For each root-owned capture, record: variant ID; selected IDs/types and primary ID; viewport and right-column rectangle; active tab; breakpoint/pseudo-state; visible status marks; component/binding state; section preference/disclosure state; panel scrollTop; visible labels and field values; computed canvas values only when measured; and screenshot/DOM evidence path. Attach source-only expectations separately from observed values. A missing unavailable fixture stays **source-backed / uncaptured**, rather than a fabricated AS-IS screen.

Useful hooks: `inspector-panel`, `inspector-header`, `inspector-breadcrumb`, `inspector-element-name`, `inspector-status-marks`, `inspector-status-line`, `inspector-tab-strip`, `inspector-context-row`, `inspector-bp-chip`, `inspector-multi-bar`, `component-row`, `cms-pickers`, `cms-source-missing`, plus `inspector-section-*` IDs. No new tests or application changes were made for this reference.
