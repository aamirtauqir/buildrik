| **Layout shell dims** | 2 (`bd-shell-*`) | hard-coded 48/56/320/280/32 in shell components | weak (low surface anyway) |

### Story

- **Color is mostly migrated.** ~80% of chrome color decisions go through tokens. Remaining 1347 hex sites concentrate in: legacy `components/` .css files (4 files = 240 sites), template/block data fixtures (~150 sites — mixed with legitimate user-content data), and ad-hoc modal/dropdown chrome (~300 sites in `editor/shell/*`).
- **Spacing is barely migrated.** `--bd-space-*` adoption is 14 sites against 2076 inline px. Spacing migration is the largest remaining lift.
- **Shadows mostly bypass tokens.** Only 8 `--bd-shadow-*` consumers. Inline `box-shadow:` definitions need cataloging in Phase 2.
- **Typography family is good, sizes are weak.** Family migration done (`--bd-font*` 192). Size scale (`--bd-text-*` 38) under-used — most sizes are inline `13px`/`14px`/`16px`.
- **Component primitives are clean** in `shared/ui/`. Legacy `components/ui/` is dead weight.

## 8. Migration Priority (Phase 2 input)

Ordered by impact / effort:

1. **Delete `components/ui/` (9 files).** Zero consumers. Pure cleanup. ~5 min.
2. **Codemod legacy .css hex → canonical tokens** for the four legacy .css files in `components/Panels/LeftSidebar/`, `components/Canvas/`, `editor/sidebar/tabs/templates/`, `editor/sidebar/tabs/build/` (304 sites combined). High-yield grep-replace.
3. **Spacing migration.** Big batch. 4-pt grid: `4` → `--bd-space-1`, `8` → `--bd-space-2`, etc. Apply to top-15 px offender list (~480 sites). Skip dynamic computed values.
4. **Shell + modal hex sweep.** `editor/shell/{PublishDropdown,InviteModal,AccountModal,CommandPalette}.tsx` (~90 sites combined). Inline Emotion CSS, mechanical replacement.
5. **Shadow tokenization.** Catalog inline `box-shadow:` definitions, map to `--bd-shadow-{xs,sm,md,lg,xl,modal,dropdown}`. Likely <100 sites.
6. **Banned-pattern manual review.** 51 banned colors + 161 gradients + 135 2px borders need spot-check to separate chrome leakage from legitimate user-content / picker tooling.
7. **Convert `shared/constants/canvas.ts` (31 hex) and `shared/constants/defaultStyles.ts` (81 px)** to reference tokens via `getComputedStyle(document.documentElement).getPropertyValue('--bd-...')` lookup OR move literals to a manifest that mirrors token values.
8. **Optional:** consolidate `--buildrick-*` legacy usage in `components/` to `--bd-*` aliases for consistency. Low priority, high churn.

## 9. Inconsistencies Surfaced (flag to user before Phase 2)

1. **`--bdc-*` namespace claimed in memory but absent on disk.** Memory entry "chrome CSS namespaced `.bdc-*`" refers to CSS class names (`.bdc-topbar`), not custom properties. Confirm whether a third token tier was intended.
2. **`styles/tokens/canvas.tokens.ts` defines tokens with literal hex values instead of token references.** 21 hex sites + 22 px sites in a file whose name implies it should reference, not define.
3. **`shared/constants/canvas.ts` (31 hex) + `shared/constants/defaultStyles.ts` (81 px) define defaults that should be derived from tokens** to stay in sync.
4. **`features/design-system/constants.ts` has 12 hex + 45 px** — the DS implementation itself does not consume its own canonical tokens. Verify this is intentional (e.g. preview swatches need raw values for color picker UI).
5. **Memory baseline matches exactly** (1498 hex). No drift since 2026-04-20 — gate is effective at preventing new hex from being added.
6. **ESLint dropped 1033 → 931** (102 warnings resolved in 5 days). Migration velocity: ~20 warnings/day passively from ongoing work. Phase 3 codemod can take a much bigger bite.
