# Audit 7 — Collaboration product architecture

Date: 2026-09-25. Phase 1, Audit 7. Read-only source inspection. No tests, browser sessions, network requests, database queries, or deployed environment checks were run for this audit. Every capability below is **NOT RUNTIME VERIFIED**. Source references establish code ownership and declared behavior only.

## Scope and classification

This audit maps the editor's live/synchronous editing capabilities and their persistence boundaries. “Implemented” means a source path exists; it does not mean the path works end to end in a deployed environment. “Conditional” means it is behind a feature flag or requires a connected session. “Partial” means the code implements part of a capability but source does not establish a complete product contract. “Demo-only” is the repository's explicit release designation for the OT implementation, not a runtime test result. “Absent” is scoped to the inspected editor/repository paths. “Not runtime verified” applies to all rows.

## Ownership boundaries

- Live op replay and ephemeral room events: `CollaborationManager` + `SSETransport` + `CollabOperation` DB log.
- Durable editable draft: editor save hooks + `BuildrikSyncProvider` + site/page rows. Saves are full project snapshots protected by a `lastEditedAt` baseline.
- Undo/redo: one editor instance's `HistoryManager` stacks.
- Named/automatic draft versions: `VersionTimelineManager` local history mirrored to `SiteVersion`.
- Published output and rollback: publish job service/history, independent of editor draft restore.
- Comments and client review: separate Review/comment services and models, not collaboration presence or operation transport (see Audit 1 ownership inventory).

## Audit result

The repository contains a conditional live-collaboration stack with an SSE/DB transport, presence/cursor/selection models, and OT-based edit operation plumbing. Release documentation explicitly keeps that editing feature demo-only because of known convergence concerns. Autosave, local undo, saved draft versions, and publish rollback are separately owned systems; none supplies collaborative undo or conflict-free editing semantics. No production or runtime conclusion is established by this source audit.
