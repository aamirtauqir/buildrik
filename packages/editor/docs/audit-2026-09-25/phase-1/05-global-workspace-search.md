## SRCH-W01 — Pages scope is logically unreachable

**Severity:** P2. **Status:** VERIFIED BY SOURCE; NOT RUNTIME VERIFIED.

**Evidence / reproduction target:** Dashboard palette exposes Pages at `packages/dashboard/components/search/command-palette.tsx:126` and scope shortcut sets `Pages: ` at line 521. For a two-character term in that scope, `shouldSearchSites` at line 211 is false because it accepts only null/sites. Pages result branch at line 273 requires `shouldSearchSites`, and actual push at line 275 requires `scope === "pages"`. No scope can satisfy both. Even cached site results cannot pass this contradictory guard.

**Expected:** Existing Pages scope should return its intended matches or explicitly state its true scope. The implemented intent is site-editor jumps (`getEditorHref`, line 283), not page-title entity lookup; do not silently relabel this as full page search.

**Root cause / affected modules:** Scope predicate and dataset query predicate disagree inside dashboard global search. **CHANGE:** Align producer/query/display gating for the intended site-to-pages jump behavior; product decision before expanding to page-content/title search. Verify an existing site's name under both Sites and Pages chips.

## SRCH-W02 — Media Load more exceeds its validated request limit

**Severity:** P2. **Status:** VERIFIED BY SOURCE with >192 matching assets precondition; NOT RUNTIME VERIFIED.

**Evidence:** `packages/dashboard/components/media/media-library.tsx:26` PAGE_SIZE24; line 51 initializes limit24; line 356 increases by24 while nextCursor exists. Query at line 70 never supplies nextCursor. `packages/shared/schemas/media.ts:52` rejects limit>200. After fetching192 matches, another Load more sends216 whenever another match exists (even a193-item result set), before the service can return remaining assets.

**Expected / root cause:** Load more should traverse the matching dataset using the returned continuation contract, not increase a bounded page-size parameter indefinitely. **Affected:** dashboard Media search/filter/list results; shared backend API is internally consistent. **CHANGE:** Consume cursor with a bounded page size, preserving/resetting accumulated results for search/folder/type changes. Reproduce with at least193 matching assets, then change search/filter and verify fresh pagination. No claim about exact UI error appearance without runtime.

## SRCH-W03 — Media Name sort orders only newest loaded subset

**Severity:** P2. **Status:** VERIFIED BY SOURCE when matching results exceed current limit; NOT RUNTIME VERIFIED.

**Evidence:** `packages/dashboard/components/media/media-library.tsx:20` offers unqualified Newest / Name. Name selection does not change API input at line 70. `server/services/media.service.ts:107` always orders createdAt descending before page limit; client line 171 subsequently sorts only returned items by filename. An older alphabetically-first match can remain behind Load more while newer Z-named items appear first.

**Expected / root cause:** A list-wide Name sort should choose the matching result window in name order, or explicitly label itself as ordering the loaded subset. Current client sort follows server pagination, not precedes it. **Affected:** dashboard Media search + filtering + sort. **CHANGE:** Decide global-vs-loaded scope, then align ordered pagination contract or scope copy. Test more than24 matches with reverse name/date ordering. Coordinate with SRCH-W02 but do not collapse distinct ordering and pagination failures.
