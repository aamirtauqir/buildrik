## Actual orchestration contracts

- `src/editor/shell/StudioPanels.tsx:269` derives fullpage state from explicit mode, tab mode, or the Assets fullpage override. The shell supplies drawer, Inspector and fullpage visibility at `:465`–`:471`. `:506` keeps Canvas mounted; `:552` renders Inspector unless AI occupies that slot. The fullpage component only mounts when needed at `:572`.
- `src/editor/rail/LayoutShell.tsx:318` retains the canvas slot and `:319` the inspector slot. `src/editor/rail/LayoutShell.css:314` hides drawer/canvas/Inspector during fullpage mode using `visibility:hidden`, zero size and `pointer-events:none` (`:318`–`:323`). This is state preservation, not three visible competing surfaces. Global engine-keyboard behavior while a workspace is open needs interaction verification; CSS alone proves neither mutation safety nor an issue.
- `src/editor/sidebar/LeftSidebar.tsx:714` mounts one active tab via the router; its selected content remains mounted while the drawer is closed, but the panel container is `inert={!drawerOpen}` at `:698`. Module switching replaces the active tab subtree; it is not a stack of persistent module panels.
- `src/editor/sidebar/FullPageRouter.tsx:85` portals Full Media and `:105` portals Settings as full-screen workspace hosts. These are `Portal` surfaces, not modal scrims. Their owners handle leaving and dialogs. Source-dispatched ordinary Settings entry passes through the transient project-settings flag but clears that flag at `src/editor/shell/StudioModals.tsx:143`–`:145`; there is no second rendered Project settings modal in that path.
- `src/editor/chrome-ui/ModalParts.tsx:57` implements ModalRoot through `OverlayMount` at `:63`. `src/editor/chrome-ui/OverlayMount.tsx:55` portals a fixed full-screen scrim; `:72` declares its dialog. `src/editor/chrome-ui/focus.ts:65` checks topmost modal before handling Escape and `:94` restores the previous focus target. Nested dialogs can therefore be intentional; their mere co-existence is not a defect. Complete Tab/focus/accessibility verification is deferred.
- `src/editor/shell/hooks/useStudioModals.ts:194` composes global/content/domain modal state. Each modal owns its payload and close reset; `closeAll` fans out at `:216`. No global exclusivity guarantee is inferred from this helper. A real collision requires a reachable competing trigger and observed/source-proved inappropriate outcome, not just independent booleans.

## Collision review and limits

Confirmed existing collision: right AI plus left AI are simultaneously rendered through different event routes. This is IA-PROD-01, already runtime reproduced by lead. Its solution must normalize destination/session ownership, not merely raise one z-index. Confirmed restoration issue: generic Settings exit resets Add (NAV-01). Both remain in the phase dependency set without duplicate findings.

The shared modal primitive gives nested picker/import and image-editor/discard dialogs an explicit topmost Escape rule. Multiple open states are therefore not automatically an orchestration defect. This audit did not reproduce a second unrelated global dialog opening over an existing dialog through a real user control; independent booleans alone are insufficient evidence. Source exclusivity and runtime keyboard interaction are distinct questions.

No new “complex management must be full-screen” finding was invented for CMS or Components based only on width. Their present hierarchy, record count, schema complexity and production user workload need direct task evidence before proposing a workspace migration. The existing full-library compile blocker prevents such runtime evidence for Media in this working tree; see `03-navigation.md` and `runtime-evidence.md`.

Detailed leaf confirmations, all focus restoration permutations, global shortcuts behind workspaces, and interrupted async edits were not exhaustively exercised. These are explicitly deferred to Interaction / States / Accessibility / Functional audits, not asserted safe. The lead may append targeted browser results. No production changes were made. Audit 5 is documented in the companion search reports.

Companion evidence: `04-collaboration-surfaces.md` supplies the detailed Review/Issues/History/Publish, presence/comments and external sharing/invitation matrix. Its findings retain their specialist IDs and should be consolidated without duplicate counts.
