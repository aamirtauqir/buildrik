Date: 2026-09-25. Read-only source trace of editor collaboration actions: canvas comments, Review, Issues, History, notifications, presence, review invitations, and publish crossovers. This pass records UI-to-result behavior and checks failure/cancel paths. Findings are source-verified unless explicitly labeled otherwise; no authenticated collaboration session or production mutation was run.

## Findings

### CI-01 — Review resend rejection has no user-visible failure state

- **Priority:** P2. **Disposition:** CHANGE. **Status:** VERIFIED STATIC / NOT RUNTIME VERIFIED.
- `ReviewTab.tsx:298–319` closes resend confirmation and awaits `onResend` inside `try/finally`, with no `catch`. The component buttons invoke it using `void doResend()` at `ReviewTab.tsx:1003` and `:1021`. The shell callback `AquibraStudio.tsx:402–422` may reject when `submitForReview` rejects; service `ReviewService.ts:115–146` propagates mutation rejection.
- On rejection, `finally` resets only `resending`. The confirmation is gone, `notice` is unchanged, and the promise rejection is unhandled by this path. The user receives no actionable indication that the round was not resent.
- Keep the mail-failure case distinct: the server can create the round while mail fails, and the current success outcome communicates that correctly. For a rejected mutation, show a retryable error and preserve/reopen confirmation or equivalent context.

### CI-02 — Compare conflates failed current export with an empty current site

- **Priority:** P2. **Disposition:** CHANGE. **Status:** VERIFIED STATIC / NOT RUNTIME VERIFIED.
- `ReviewTab.tsx:328` catches current-page export failure and calls `setCurrentPages([])`. `ApprovedCompareView.tsx:182–195` then unions the approved/current page paths and computes the diff against the empty array. It renders `Nothing changed` only when the computed diff is empty (`:215–219`); otherwise absent current pages show “Not present on this side” (`:204–209` / pane rendering) and removals.
- A renderer/export failure therefore masquerades as every approved page being removed, while a genuinely empty current site is represented identically. Give current export its own failure state and retry action; do not supply an empty success value for a failed read.

- Review reply, resolve/reopen, revoke, first-send and notification actions have explicit loading/error/success treatment in the traced paths. No new issue was established for them.
- History restore/undo, activity feed bounded retrieval, editor issue-row dismissal, and authentication continuation have separate findings in other Phase 1 audit files and are not duplicated here.
- This is not a live collaboration security or permissions assessment. No deployment, invitation, comment mutation, delete, or authenticated session was exercised. Phase 4 owns security claims; Phase 7 owns the full collaboration product model.
