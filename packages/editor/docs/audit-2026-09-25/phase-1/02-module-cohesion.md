## COH-01 — Asset alt-text generation has competing responsibility contracts

**Severity:** P2. **Status:** VERIFIED (static). **Recommendation:** MERGE generation responsibility, KEEP both contextual entries. **Runtime:** NOT RUNTIME VERIFIED.

**Expected owner:** the asset-specific media generation service should own image context, supported local/server asset behavior, existing-text policy, output and provenance. Quick and Full Media may expose this same job.

**Current owners and evidence:**

1. `src/editor/sidebar/tabs/media/MediaTab.tsx:234` mounts `AssetDetailOverlay` and passes `state.updateItem` at `:236`. Its `generateAlt` at `src/editor/sidebar/tabs/media/components/AssetDetailOverlay.tsx:274` calls `generateContent` using only the display filename, `"headline"` and `"professional"` (`:278`–`:282`); `:286` writes `{altText}`. `src/shared/utils/openai.ts:104` sends this through generic content generation. `src/editor/sidebar/tabs/media/hooks/useLibraryState.ts:330` maps the patch to `composer.media.updateAsset` at `:336` without an AI provenance update.
2. `src/editor/media/LibraryManager.tsx:973` supplies `onRegenerateAltText`, calls `generateAltTextRemote` at `:974`, respects `result.skipped` at `:976`, and writes both alt text and generated metadata at `:977`. `src/services/AltTextService.ts:44` calls `media.generateAltText`.
3. Repository-root `server/trpc/routers/media.ts:295` delegates to `applyAltTextToAsset` at `:299`. `server/services/alt-text.service.ts:140` skips already-populated text and `:144` generates using the stored asset image URL. This is materially different context and output policy from the Quick drawer path.

**Root cause:** two views independently implement one asset-generation responsibility. The Quick view retained generic text-generation logic after the media-specific service became the Full view's owner.

**Affected modules:** Quick Assets, Full Media, AI media service, asset metadata/provenance; upload auto-generation also uses the media service via `src/editor/shell/hooks/useAltTextAutoTrigger.ts:54`.

**Impact established by source:** the same named user job can depend on filename-only information or actual asset imagery, and follows different existing-text and provenance rules depending on entry. No claim of generated-text accuracy or runtime persistence outcome is made.

**Specific correction to plan after the phase:** establish one asset-generation operation/result contract; route both UI entries and applicable upload automation through it. Decide how local-only assets are handled and whether “Generate” versus “Regenerate” replaces populated text before merging. Do not simply remove one useful entry or attach an unchecked server-only assumption to local assets.

**Dependencies and validation required:** asset identity/local-only policy, human-edited versus generated provenance policy; targeted contract tests across both entry points for empty/populated alt text and supported/unsupported asset identity, followed by runtime confirmation that both produce the same metadata policy. Security, provider accuracy and failure-state UI are deferred to the later relevant audits.

## COH-02 — Same palette contains two identical Undo actions

**Severity:** P3. **Status:** VERIFIED (static); duplicate visibility independently observed by lead in the browser. **Action:** REMOVE/MERGE one redundant row. The specialist did not execute Undo at runtime.

`src/editor/shell/modals/CommandPalette.tsx:71` declares `edit-undo`, label Undo, group Edit, shortcut Ctrl+Z, `!composer.history.canUndo()` guard and `composer.history.undo(); onClose()` handler at `:77`. The same builder independently declares `history-undo` at `:143`, label Undo last action, group History, the same shortcut and guard, and the identical handler at `:149`.

Expected owner is one palette command delegating to the engine history manager. Current owner is two hardcoded palette entries for the same job. Root cause is overlapping Edit/History groups populated independently. Intent, scope, trigger surface, handler, mutation, outcome and context are identical; only label/group differ, so this is a verified redundant action rather than a useful contextual entry. Keep one action and preserve alternate wording as search aliases if supported. Relevant validation is a palette build/search assertion that exactly one executable Undo result exists; no production mutation is needed merely to verify duplicate removal. Affected modules: Commands and History. No product decision is needed to establish the duplication; preferred grouping is a minor implementation choice.

## Cross-module specialist aggregation and exclusions

The Review/Issues/History/Activity/Publish/Collaboration rows incorporate the collaboration specialist's source handoff. The companion `02-collaboration-cohesion.md` owns the detailed collaboration evidence, including presence, comments, mentions, membership, sharing, roles and live editing. Its **CO-C01, P2 PRODUCT DECISION REQUIRED** records that internal admin review and external client sign-off share the pending review-round owner despite distinct submission payloads. Keep the contextual actions and decide audience naming/shared-round policy; do not merge actions by label alone.

`02-backend-cohesion.md` independently documents the component-library authority seam: dashboard workspace rename/delete mutate server SiteComponent rows while editor hydration skips already-present local definitions and does not clear local rows for an empty remote list. The backend specialist's P2/PARTIAL ownership finding is retained as its own item; stale data or resurrection at runtime is not asserted here. Editor Components versus Add insertion remains a valid split, while dashboard/editor management reconciliation needs an explicit authoritative update contract. The lead should preserve specialist finding IDs during consolidation and avoid counting their evidence again as an editor duplicate.

This audit evaluates cohesion, not navigation discoverability, typography, accessibility, performance, or a full functional/security test. Not all leaf controls were re-audited: Audit 1's module owner chains were reused, and targeted additional reads covered Add groups, CMS condition/data ownership, Settings workspace webhooks, AI mode/output types and Media generation paths. Missing functional runtime coverage belongs to later audits and does not prevent source-level Audit 2 closure.
