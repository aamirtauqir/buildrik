## Navigation model established from source

`src/editor/rail/tabsConfig.ts:359` provides the six primary rail modules: Add, Layers, Pages, Assets, CMS, Brand. `src/shared/utils/editorViewMode.ts:70` forces that model in production; E3/legacy rail renderers are development-only and are not counted as competing production navigation.

Module panels use shell state, not browser routes: `src/editor/shell/hooks/useStudioState.ts:317` opens a left panel and optionally records its sub-screen. `src/editor/sidebar/TabRouter.tsx:138` dispatches drawer content; `FullPageRouter.tsx:66` dispatches Settings and full Media. Global SiteMenu entries provide resource/settings/history/review destinations that are absent from the six-item rail. The real Inspector is continuously mounted on the right unless hidden/read-only/fullpage; contextual AI temporarily replaces it.

`src/editor/sidebar/LeftSidebar.tsx:471` gives rail buttons switch/open/toggle behavior. Panel headers receive `onClose: onDrawerToggle` at `:629`, so closing a drawer hides it while retaining its selected module. Back inside a module generally changes its local view rather than switching modules. Full-workspace return is a separate shell handler; see NAV-01.

## NAV-01 — Settings return resets the editor's module context to Add

**Priority:** P2. **Disposition:** CHANGE. **Status:** VERIFIED source behavior and lead's local-demo runtime (R4 in `runtime-evidence.md`). This specialist did not operate the browser; authenticated production-host behavior was not verified.

**Expected:** leaving the temporary Settings workspace should restore the editor context from which it was opened, or explicitly communicate a fixed return destination. A user opening Site settings from Pages/Brand should not silently have the resource panel changed to Add.

**Actual:** `src/editor/sidebar/tabs/settings/SettingsTab.tsx:585` wires Back to canvas to the guarded leave request; `:265` invokes `onClose`. `src/editor/sidebar/FullPageRouter.tsx:119` forwards that close callback. `src/editor/shell/StudioPanels.tsx:411` handles full-page close: Media returns to its quick panel, but every other destination calls `onLeftPanelTabChange("add")` at `:417`. No captured prior panel is read in this handler.

**Root cause:** full-workspace exit uses a hardcoded fallback as the whole return policy instead of storing its originating module/context. **Affected:** Settings, Pages, Brand, Components and other possible source modules. **Recommendation:** plan a minimal origin/return-target contract for workspace navigation; preserve dedicated page-repair return targets. No content loss is claimed. **Lead runtime result:** Pages → Site menu Settings → Back to canvas selects Add. This is a return-context finding, not the broader surface-arbitration audit.

## NAV-02 — Bare module shortcuts do not open a closed drawer

**Priority:** P2. **Disposition:** CHANGE. **Status:** VERIFIED source chain and lead's local-demo runtime for bare P (R5 in `runtime-evidence.md`). Other registry keys are source-supported variants, not individually runtime exercised here. Authenticated production-host behavior was not verified.

**Expected:** advertised bare module shortcuts should reveal the requested module, consistently with rail selection and palette Open commands.

**Actual:** `src/editor/sidebar/LeftSidebar.tsx:522` registers `useSidebarKeyboard(safeTabChange)`. `src/editor/sidebar/useSidebarKeyboard.ts:43` matches bare shortcut and `:45` invokes only the supplied tab setter. `src/editor/sidebar/LeftSidebar.tsx:443` (`safeTabChange`) calls `onTabChange` at `:448`; `src/editor/shell/StudioPanels.tsx:401` (`handleRailTabChange`) only changes tab. It does not open the drawer. Actual rail clicks separately open the drawer at `src/editor/sidebar/LeftSidebar.tsx:475`. Thus the keyboard chain can change module state while leaving its content hidden after the drawer was closed. Modified shortcuts such as Shift+A have a separate shell handler that opens the panel; they should not be generalized into this finding.

**Root cause:** keyboard navigation reuses a tab-only setter rather than the open-destination action. **Affected:** bare shortcuts routed through the tab registry, including P/D/A/L/M/B and off-rail modules; only P was runtime exercised for this finding. **Recommendation:** route open-module shortcuts through one visible destination action while preserving active rail toggle semantics. **Lead runtime result:** closed Add drawer → bare P mounts Pages in the hidden 1px-wide drawer; clicking Pages rail then reveals a 280px panel. Evidence screenshot: `shortcut-hidden-pages.png`. No production fix or browser mutation was performed by this specialist.

## Deep links, context actions and return hierarchy

- Element links are implemented, not just copied: `src/editor/panels/layers/hooks/useLayerContextActions.ts:35` sets `el` and `page` query parameters; `src/editor/shell/hooks/useDeepLink.ts:29` reads them after project load, activates the page at `:36`, selects the element at `:43`, and scrolls it at `:44`. Missing-element behavior returns without selecting at `:42`. Runtime with fresh backend hydration was not exercised here.
- Selected element → Show in Layers emits `SHOW_IN_LAYERS` at `src/editor/canvas/menus/actions/standaloneActions.ts:105`; shell handler `src/editor/shell/hooks/useEditorEventListeners.ts:111` opens the owning module. This is a useful contextual secondary entry.
- Page SEO → site redirect repair uses `UI_SETTINGS_OPEN`; `src/editor/shell/StudioPanels.tsx:298` stores the target screen and repair context before lazy navigation. Its matching `UI_PAGES_OPEN_SETTINGS` handler at `:306` stores page ID and desired settings tab for the return. This is an explicit parent-aware route, distinct from NAV-01's generic workspace exit.
- CMS's root/collection/record hierarchy and Brand's root/section/token-kind hierarchy have explicit one-level Back operations (`ContentTab.tsx:261`, `:277`; `DesignSystemTab.tsx:714`). They are not browser-history operations.
- Full library Close returns to Assets, while contextual picker Close returns to its caller. These different outcomes match different parents and should not be forced into a single generic close callback solely for consistency.
- Settings entry alias `plugins` is normalized to `integrations` at `src/editor/sidebar/tabs/settings/SettingsTab.tsx:322`. A stale internal identifier is not by itself evidence of an unreachable destination.
