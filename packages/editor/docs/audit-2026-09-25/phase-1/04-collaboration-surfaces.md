## Shared overlay mechanics actually inspected

`chrome-ui/OverlayMount.tsx:54` portals a fixed inset-0 scrim into shared overlay root; it closes on scrim click unless disabled/dirty. Its inner dialog is aria-modal. `chrome-ui/focus.ts` records the opener, focuses into the overlay, restores opener on cleanup and allows only the last modal dialog to answer Escape. `ModalParts.tsx:63` delegates ModalRoot to that primitive. These mechanisms support valid layered modal flows, but do not by themselves prove every global editor shortcut or background mutation is blocked.

Notification quick view is different: `header.css:29` anchors it below the header; it has no full-screen scrim. `NotificationPanel.tsx:104` focuses the panel and restores the opener; `:126` closes on Escape. Comment-mode Escape explicitly yields while a modal is present (`CommentLayer.tsx:246`). Consequently, coexistence of a nonmodal drawer, comments mode and a modal is not automatically a collision: one may be contextual state retained beneath a temporary decision.

Dashboard modals use their own primitive (`packages/dashboard/components/dashboard/primitives/modal.tsx:79`) with fixed viewport scrim, focus capture and restore (`:31`, `:68`). They operate in the dashboard tab, not inside the editor overlay tree.

## SUR-C01 — Issues overlay coexistence observation (not a confirmed defect)

- **Priority:** Unassigned until harmful obstruction is reproduced. **Status:** SOURCE VERIFIED overlay independence; visible collision NOT VERIFIED. This is a verification note, not a counted finding.
- **Trigger/state:** topbar Issues sets shell issuesOpen. That state is independent of StudioPanels' drawer/full-page/Inspector state.
- **Evidence:** `packages/editor/src/editor/shell/AquibraStudio.tsx:605` renders the overlay as a sibling after StudioPanels, absolute at top56/right0/bottom0, width360, z45. `StudioPanels.tsx:465`/`:467` independently chooses drawer/full-page mode and `:471` independently retains Inspector. No workspace transition is part of the Issues render condition. Closing the overlay does not need to reconstruct Inspector because it never replaced it.
- **Risk to verify:** Open Issues, then enter a different dedicated workspace or Preview through a still-accessible trigger. The overlay may continue covering the new workspace's right region while that workspace believes it owns the surface. Open Issues alongside the notification dropdown to assess whether either necessary close/action is obstructed. Source permits these states; it does not establish that every overlap is harmful.
- **Expected architecture:** A nonmodal Issues inspector may intentionally cover/replace the right region while editing, but full-workspace and preview transitions should make the intended precedence explicit.
- **Recommendation:** After confirming actual collision, enroll Issues in the existing surface precedence/close policy or explicitly constrain it to editing context. Avoid adding a global “close everything” rule without checking valid compare/comment recovery overlays.
- **Deduplication:** NAV-C02 addresses the issue-row destination, not this surface lifecycle. Existing split-AI/settings lost-return findings are separate and not repeated here.

## Keep results and limits

- Review's compact List and larger Split/Overlay comparison have deliberately different surfaces; Close-to-List and Back-to-Review are distinguishable source behaviors.
- Comment mode legitimately intercepts canvas clicks while preserving document visibility, and yields Escape to a modal.
- Published rollback advances picker to confirmation without intentionally keeping both open. Closing a progress view is not proven to cancel the backend job.
- Presence and ReviewBar are ambient/inline surfaces rather than competing management drawers.
- Sharing/invites remain dashboard forms in another tab; closing them need not reconstruct editor context.
