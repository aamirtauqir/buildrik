## CO-C01 — Internal and external review submission share a label and round owner

**Severity:** P2 decision item. **Status:** PRODUCT DECISION REQUIRED; NOT RUNTIME VERIFIED. **Disposition:** KEEP functionality; decide audience naming and whether shared round policy is intentional.

The dashboard site-header mounts `SendReviewModal` (`packages/dashboard/components/site-detail/site-header.tsx:181`). Its explanatory text says admin review, and its submit at `components/reviews/send-review-modal.tsx:52` sends only siteId/note. Editor Review's empty-state instruction says a client gets a link (`packages/editor/src/editor/sidebar/tabs/review/ReviewTab.tsx:515`); its SendForReview path includes snapshot and email via `services/ReviewService.ts:115`. The server deliberately uses the same pending-site ReviewRequest (`server/services/review.service.ts:54`) and only issues a token if the call carries clientEmail (`:93`). This is established shared workflow state, not evidence of two unrelated stores.

The module-boundary question is whether Review explicitly owns both internal admin authorization and external client sign-off as variants of one round. Confirm that intended product model before separating storage or removing an entry. If retained, distinguish “Request admin review” from “Send to client” at the point of action; both can continue to delegate to the shared Review owner. No data-loss/security conclusion is drawn from this static overlap.
