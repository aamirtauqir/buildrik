# Inspector integration closure specification

Date: 2026-10-16. Baseline: `19f964d5e7efda2c276a4c185782bb963da605ec` plus the main brief's separately recorded isolated-runtime evidence. Principal Product Designer review; AUDIT_AND_DESIGN only. No application/test/data changes, new tests, browser work or Figma use in this continuation.

This supporting specification closes the **Inspector-side design decisions** for inventory M07 rows 9, 42, 76, 86, 89 and 103. The main `PRODUCT-DESIGN-BRIEF.md` remains the authoritative decision record. Four tabs — Content / Style / Behaviour / Effects — are the selected direction for this closure; nothing here reopens approved shell ownership. “Specified” means behavior can be implemented and accepted against the criteria below; it does not mean the existing implementation passes them.

## II-01 — Authoritative value, source and reset contract (M07-42)

### What the current source establishes

1. `ElementStyles.getStyles()` merges stored element styles with component-related style overrides (`src/engine/elements/ElementStyles.ts:175–182`). Component resolution applies selected variant then explicit instance override (`src/engine/components/ComponentVariantResolver.ts:156–184`). This materialized map is not the complete browser cascade.
2. Inspector `stylesAt()` reads that base plus only the exact non-desktop breakpoint (`src/engine/commands/commandOperations.ts:254–261`); `computeEffectiveStyles()` then reads only the exact breakpoint/pseudo selector (`src/editor/inspector/config/cssContext.ts:54–68`). This is an implementation gap, not the proposed authority for effective values.
3. Canvas style rendering appends editor-only pseudo rules and narrowed-device rules, with `!important` to beat inline base styles. Mobile explicitly includes Tablet followed by Mobile (`src/engine/styles/StyleEngine.ts:652–710`). Publish emits base element classes, then desktop-first responsive rules; the inspected multi-page path appends site-token/font CSS after those (`src/engine/export/ExportEngine.ts:524–547,779–804`). `generateResponsiveCSS()` groups base→Tablet→Mobile; generic `generateCSS()` groups media by insertion order (`StyleEngine.ts:354–405,478–522`). Output paths must therefore be checked independently rather than inferred identical.
4. CSS selectors, specificity, important declarations, inheritance, pseudo-state matching, shorthand/longhand interactions and custom-property resolution affect the final result. A desktop `:hover` selector can outrank a narrower normal selector; “breakpoint always wins” is false. Do not replace CSS cascade with an unconditional base→breakpoint→pseudo map.
5. Brand tokens are references, not a universally higher CSS priority. `packages/shared/tokens/resolve.ts:6–23` follows aliases/replacements with Dark falling back to Light at each hop. Broken/cyclic references return null. Component/master data, token source, local property owner and CSS winning declaration are different dimensions.

### Specified Inspector behavior

The read model exposes these **semantic facts**, regardless of implementation representation:

| Fact | Required behavior |
|---|---|
| Authored value | Preserve raw stored value/reference and whether this layer has a declaration. Absence and explicit `0`, `none`, empty attribute or `inherit` remain distinct |
| Effective value | Resolve for the current site/page, target element, actual website breakpoint, authored pseudo-state and site preview colour mode. For style preview measurements, the canvas must be settled and represent that context |
| Source | Name the actual winning declaration/owner when known: `This element · Mobile`, `Tablet`, `Parent …`, `Component … / Variant …`, `Token …`, or attached class. Include token chain separately from winning CSS layer |
| Unknown provenance | Show `Computed value · source unavailable` plus inspectable value and local-write scope. Never claim `Desktop`, `Default`, or a token source merely because provenance was not found |
| Write target | Element/instance override at the explicitly displayed breakpoint and pseudo-state. Normal non-style attributes retain their actual element scope; a heading-level change does not acquire a responsive scope just because Mobile is visible |
| Shared edit | An explicit source action changes the named shared owner. Editing a local style control never silently edits a CSS class, component master or Brand token |
| Mixed | Compare semantic values and source identity separately. `Mixed` for different values, and a source summary for equal values with different provenance. Applying a literal is explicit; focusing/reading never homogenizes the selection |

Property display uses authored units/references when present, with resolved preview as supplementary information. Example: `1.5 ×` line height is not replaced by `48px` merely because computed CSS reports pixels; display “48px at this font size” as a readout. A bare inherited value can display its effective value and source without creating a local declaration. Fonts and image loads may temporarily produce `Resolving…`/`Fallback rendering`; retain authored values throughout.

Reset actions are **owner-specific**, not one generic “Reset”:

| Action | Exact mutation | Preview / recovery |
|---|---|---|
| Remove Mobile override | Remove only current Mobile normal declaration, or Mobile current-state declaration when that state is selected | Preview actual next value/source, e.g. `32px · Tablet`. Do not write an explicit Desktop value |
| Remove state override | Remove only this element's matching pseudo-state/breakpoint declaration | Other states and breakpoint declarations untouched |
| Reset instance property to master | Remove corresponding instance override via component owner | Selected variant/master effective value returns; unrelated responsive rules remain |
| Remove local value | Remove this layer's declaration | Resolve class/parent/browser fallback; it need not equal a product default |
| Unlink token | Replace reference at current local write layer with its **current resolved literal** | Explain that literal applies in both colour modes unless a separately supported theme-specific rule owns it; preserve ability to Undo |
| Restore default | Only where the product actually has an explicit reset-to-default operation | Names the default and writes it deliberately. Never substitute this for remove-override |

Multi-reset removes each eligible member's own matching declaration, yielding potentially different fallback values. Snapshot each authored pre-value and absence marker for Undo. Counts reflect eligible targets and declaration counts, not only primary selection. Read-only/locked/conflict guard runs at mutation time.

**Output acceptance:** same saved project/configuration is evaluated in canvas, preview, downloaded output and publish-generation output (without deployment). Compare normal and pseudo behavior, Tablet inherited on Mobile, alias tokens in both modes, component variant/instance overrides, attached class plus local override, custom CSS values and breakpoint reset. Any rendering adapter needing editor-only specificity workarounds must still yield equivalent authored outcomes. Schema/renderer corrections are engineering dependencies; the Inspector cannot claim they are fixed merely by displaying a different number.

## II-02 — Field draft, commit, cancellation and asynchronous target contract

### Target identity and draft ownership

Every edit session captures `project/site`, page ID, ordered target IDs, property or action ID, breakpoint/state where applicable, colour mode where applicable, authored original values **per target**, relevant source revision and an operation generation. This is temporary editor state, never a website-content schema field. Selection membership changes create a new generation even when the primary element remains the same.

| Event | Specified behavior |
|---|---|
| Focus | Capture authored originals, including absent declarations/references. Do not commit the displayed computed value |
| Valid live typing | Preview/write through the canonical guarded command to captured targets. Continuous changes in one focus/scrub interaction form one meaningful history unit; engine throttling may remain 50ms but must not define user-visible commit semantics |
| Incomplete/invalid typing | Keep local text only; last valid applied state remains. Show validation on Enter/blur, not on every intermediate `-` or decimal prefix. Empty means remove only where that field explicitly defines it |
| Enter | Validate; settle current interaction and history boundary if valid. Invalid retains input/focus with error; never converts to zero or a default |
| Blur within same target | Settle valid pending write; retain invalid text keyed to that field. An unrelated discrete action settles the valid interaction first |
| Selection/page/breakpoint/state/tab change | Settle valid pending writes against the **old captured target/scope before switching**. Retain invalid local draft by its full identity and restore it when that field is revisited; do not apply it to the new target. Show a local unapplied-input indicator when returning. Browser/project exit must include Inspector drafts in the shared dirty-input guard: Stay or explicitly discard unapplied inputs; saving the project does not serialize invalid draft text |
| Escape in a live field | Cancel only this field interaction: restore each captured authored original, including absence/token link, and cancel pending timer. Never call global Undo blindly. If another operation changed the property meanwhile, do not overwrite it: discard uncommitted local draft, refresh canonical value, explain `Value changed elsewhere. Uncommitted input was discarded.` Do not claim earlier live writes never occurred |
| Escape in a picker/subview | Close innermost uncommitted surface, discard its preview draft, restore focus to its trigger. Once an explicit Apply/Use completed, closing the surface does not undo it |
| Undo/Redo | Refresh canonical field values and override/source state without reselection. Finish/cancel the active field session first so history cannot replay a delayed old write afterward |
| Lock/conflict/access loss mid-edit | Stop new mutations immediately. Keep pending local input with its original identity; show reason/Resolve where authorized. After resolution, compare revision and revalidate before explicit continuation; never auto-replay against changed content |

The current shared guard has only `settings` and `cms-record` domains (`src/editor/shell/shellDirtyRegistry.ts:18–39`); registering Inspector drafts is a proposed extension, not a claim they are already protected. Project leave can use the existing custom guard; browser close/reload uses the browser's native beforeunload wording. Drafts are session-only unless a separate recovery mechanism explicitly supports them.

For async pickers and resource requests, completion must verify: current request generation, original site/project still active or explicitly returnable, target existence, eligibility, effective permissions, lock/conflict, source existence, and expected property revision. A newer request supersedes the old request; cancelling invalidates it. Selection/scope navigation invalidates automatic application. If a captured original target still exists but user moved elsewhere, the resolved resource can remain a non-applying picker result; explicit **Use on [target]** starts a newly validated commit to that named original and returns there. Never substitute current selection or resurrect an invalidated callback. If target was deleted or permission lost, selection cannot commit; show `This element is no longer available` / permission reason with Close and retain the resource itself. Expected revisions account for this operation's own live writes; foreign revisions require review rather than overwriting.

Partial multi-target invalidation is never silently reduced. Before commit show eligible/skipped counts and reasons; user can apply to the listed remaining targets, otherwise cancel. A class/asset/token management operation may have persisted independently; cancellation of local selection does not delete that resource.

## II-03 — AI entry, takeover and return (M07-9)

**Existing evidence:** `InspectorHeader.tsx:105–113` opens AI; `StudioPanels.tsx:959–992` mounts AI over a preserved Inspector instance and has an explicit Back to Inspector. `ProInspector.tsx:112–126,349–356` replaces controls with run status while `ai:agent-run` is true. Runner broadcasts state, stops on step failure, distinguishes awaiting/applied/nochange and offers Stop (`src/editor/sidebar/tabs/ai/hooks/useAgentRunner.ts:203–220,235–237,340–383`). Undo handles only operate while their own history entries remain current (`:413–422`). This is not evidence of arbitrary safe rollback across intervening edits.

**Specified flow:** selected element(s) → header **Ask AI** → same right-column AI surface with an explicit named scope. Default is captured selected element(s), not page/site. Existing supported broader scopes remain available through AI's own scope control; changing scope is an explicit action with affected-count summary. Settle Inspector edits using II-02, preserve page/selection/breakpoint/state/tab/scroll/canvas view and return-focus ID. Prompt scope and run scope are pinned at Run; canvas selection changes do not retarget the run.

While a run is mutating the same document, Inspector shows **AI is editing [scope]** with current step and **Open AI run**; its authored mutation controls are blocked, navigation/inspection allowed. The run owner supplies pending/applied/failed/stopped counts. **Back to Inspector** only changes the visible panel. It does not stop the run, undo work, approve proposals or clear a draft prompt. If still running, the preserved Inspector shows the takeover state. **Stop** requests cancellation of pending work; completed operations remain with a truthful summary and available owner-defined undo/review. Do not say “Cancelled, no changes” after any operation committed.

Completion/failure restores applicable controls and re-reads canonical values. Retain original selected objects if they still exist; otherwise select the nearest surviving original ancestor or show Page appearance with `The original element was removed by this run`. Do not claim exact selection restoration when IDs no longer exist. An AI result requiring acceptance stays in the AI flow; returning to Inspector is never acceptance. If rollback cannot safely remove only this run's changes because later work exists, explain the limitation and offer existing History/Compare route; do not roll back unrelated work.

No new AI generation model, unlimited run scope, permission expansion or multi-user rollback algorithm is introduced here. Acceptance covers open/back without a run; return during running; Stop after one applied step; failure; no-op; original-target deletion; intervening edit before Undo run.

## II-04 — Font selection and site-font management (M07-76)

**Current source:** system font values in `FontPicker.tsx:34–40`; selected font writes immediately, Google load is fire-and-forget (`:99–110`). Uploaded entries read FontManager custom fonts and subscribe to font events (`:67–88`). `FontPickerDropdown.tsx:268–278` caps displayed Google matches to 50; foot **Manage site fonts** emits `ui:site-fonts` (`FontPicker.tsx:43–45`). Site-font membership is an asset operation, and the confirmation explicitly says existing text is unchanged until chosen (`src/editor/media/components/SiteFontsModal.tsx:151–166`). Google service adds a link and records it loaded without waiting for browser success (`src/services/GoogleFontsService.ts:119–145`).

**Specified flow:** Style → Typography → Font → search/category/groups → choose exact family/source. Default selection marker follows the authored stack, not merely same display family name. Uploaded/built-in names that collide show source and file/family identity. Selecting a row applies one field transaction to named eligible targets at the current breakpoint/state; loading font bytes is asynchronous presentation, not permission to rewrite the font later. Show loading and `Font unavailable — fallback is rendering` with Retry while retaining the intended saved family. Undo restores the prior stack/reference; a late successful font load cannot reapply a reverted choice.

Search shows matching count, not total catalogue count as if all matched. Preserve the existing search, categories and Uploaded/System/Google groups. Replace the invisible 50-row dead end with **Show next 50** within the same list; retain search/category while appending. This is a discovery extension of the existing catalogue, not a new font provider. Empty catalogue, no matches and network/load failure have distinct states.

**Manage site fonts** stores picker query/category/scroll, pending family and origin field snapshot; opens the existing site-font manager. Upload/Add makes the font available, does not apply it to any text. Successful Done returns to the Font picker, refreshed, with newly added family highlighted and an explicit **Use [family]** row. Closing manager without choosing returns unchanged local styling. Management changes use media/site-font permissions and persistence; local font application uses document edit permissions. Local Undo is not promised to delete the uploaded file or reverse independent membership writes. If membership removal is blocked by the existing owner policy, Inspector obeys it rather than adding a bypass.

Output must use the same selected family, source URL and required weight/style assets; persist reference identity where the current stack alone is ambiguous. Engineering may need a backward-compatible font reference augmentation; legacy CSS stacks remain readable and unchanged until intentional selection. Font-load success is distinct from project save and asset-upload success. Keyboard: searchable dialog/popover semantics with a listbox for options only (not a listbox wrapping arbitrary management buttons), arrows navigate options, Enter selects, Escape returns focus; Manage is a separate button.

## II-05 — Background image pick and compound background preservation (M07-86)

**Current source:** Background section converts shorthand/longhand, switches colour/gradient/image and has typed Image URL + Browse (`BackgroundSection.tsx:60–103,265–287`). Browse callback closes over a style handler without an explicit background-layer request descriptor. Advanced size/position/repeat/attachment/blend options exist (`:295–370`). This is local background presentation; selecting a background image must not edit an image element's source or asset metadata.

**Specified simple-image flow:** Style → Fill → Image → **Choose image** / **Replace image** → existing Assets picker filtered to image, title `For [element] · Background` (or explicit N eligible targets). Capture layer/property/scope/request identity. Picker search/upload/management are their existing owner workflows. Explicit **Use image** validates target and resource, writes one selected background layer, returns to the exact Fill section and triggers visual load feedback. Cancel leaves authored background and selection unchanged. Failure retains the chosen resource/draft and provides Retry; no phantom success if write was refused.

Choosing Image mode alone changes the visible subview and does not clear a gradient/colour. Complete replacement commits only on explicit Use or valid URL Enter/Apply. Typing a URL stages complete input; validate syntax/safe scheme through shared URL policy. Loading failure does not erase the intended URL or a prior valid resource. Replace in library is a separate, explicitly shared asset operation with its own impact summary; local background choice never invokes it.

Preserve background-size/position/repeat/attachment/blend values during source replacement unless the user explicitly changes them. For a simple single-layer shorthand, use a lossless decomposition to named CSS properties before editing; do not discard colour, position or attachment encoded in the shorthand. For multiple layers or syntax not losslessly supported, show `Custom background · [N layers if reliably parsed]` and raw value read-only. Offer **Replace background…** with old/new summary; Cancel retains exact original; confirmed replacement is one Undo unit. Existing individually supported layers/values remain inspectable; this scope does not introduce a full multi-layer background editor. Do not classify a comma inside rgba()/url()/gradient() as a layer separator without balanced parsing.

Background images are decorative in output; alt text belongs to meaningful image elements, not CSS background. An informational hint may direct users to an Image element when content requires alternative text, without inventing alt metadata on the background. Acceptance covers stale picker, locked/deleted target, source failure, URL with quotes, multi-layer shorthand, existing gradient, custom position, Cancel/Undo, reload and output.

## II-06 — Local and shared colour edit, modes and alias ownership (M07-89)

**Current source:** token Use binds a CSS variable; custom edit and **Update everywhere** coexist (`ColorFillPopover.tsx:69–102,160–176`). Colour input resolves list values using Light (`ColorInput.tsx:102–106`); `useUpdateColorEverywhere.ts:25–30` writes Light via the Brand setter. Brand schema supports primitive/semantic tokens, Light required and Dark optional (`packages/shared/schemas/design-tokens.ts:30–55,60–98`). Primitive Dark literals are disallowed. `setTokenLiteral` for a semantic token reuses/creates an owned custom primitive so changing that semantic token does not mutate unrelated palette consumers (`packages/shared/tokens/resolve.ts:31–99`).

**Specified picker:** header states `Colour for [target(s)] · [breakpoint/state]`; token previews resolve current site preview mode. Use token binds that exact semantic token at the local write layer; it preserves mode responsiveness. Existing retired/primitive bindings remain readable but are not silently substituted by a new selection. Unresolved token shows its identifier and **Open in Brand / Replace / Unlink to a valid chosen colour**; never use fabricated black as if the token resolved.

**Edit shared token subview:** show name, `Editing shared Brand colour`, **Light / Dark** selector, effective value and source alias, known usage scope/count. Default editing mode is the current resolved site preview mode; changing it changes only the draft editing target, not website preview or site Dark-mode setting. If Dark has no override, show `Follows Light` plus explicit **Set Dark value**; reset Dark removes that mode ref and restores fallback. A primitive is inspectable through Brand with its actual Light-only rule; do not offer a no-op Dark mutation.

Use a draft colour with two explicit commit paths:

- **Update [token] · Light/Dark:** calls canonical Brand semantic-token value operation, validates token schema/permissions/revision and preserves sibling tokens. Explain when replacing its current alias with an owned value: `Changes this token's colour; the original palette colour stays unchanged.` No direct write into primitive siblings. Known usage count is labelled `N references in this site` only if that is what was counted; an incomplete count is `Known references`, never `N elements everywhere`.
- **Use on selected element(s):** creates local literal at displayed breakpoint/state, removes the token reference only at that layer. Explicit note: `Applies in Light and Dark. Other uses of the token stay unchanged.` This is not a Dark-only override because current local element styles have no theme mode axis.

Both commit paths are separate single history units with action-specific labels. A failed/refused shared mutation retains the picker/draft with error; do not close optimistically. Only confirmed local operation completion dismisses. Server save remains pending until persistence confirms it. Cancel/Back/Escape discard only uncommitted picker draft. Already committed Brand change remains on returning to Inspector, with normal owner Undo where supported. If a token changed elsewhere while the picker was open, require reviewing refreshed old/new values before overwriting; keep user's draft separately.

Colour entry preserves alpha already supported by the visual picker. Proposed consistent hex validation accepts 3/4/6/8-digit forms; show alpha as 0–100% while preserving exact underlying value. This is not a claim all four forms already work in every input. Existing valid rgb()/hsl()/var()/currentColor/transparent values are displayed without forced conversion. Raw arbitrary CSS-colour authoring is not added: unsupported editing syntax is retained as Custom with explicit replacement. Alpha preview uses a checkerboard and does not pretend the background is known when displaying contrast.

## II-07 — CSS animation versus triggered interaction (M07-103)

**Current source:** `AnimationConfig` contains type/duration/delay/easing/direction/iterations/trigger/scrollOffset/fillMode; defaults and generator are `src/shared/types/animations.ts:35–68,113–118`. Generated CSS uses timing/direction/iterations/fill, **not trigger/scrollOffset**. `AnimationEditor.tsx:193–197` acknowledges removal of trigger control. Yet `ElementAnimationRow.tsx:18–25` displays stored hover/click/scroll trigger labels. Interactions use a different GSAP-backed config (`sections/interactions/types.ts:42–53`) and existing trigger set; preserve that distinction.

**Specified flow:** Behaviour → Interactions → separate `CSS animation · [preset]` row, caption `Plays when rendered`. Open same-column drill-in with **Back to Interactions**; timing edits use II-02 and existing animation owner. Display current preset/category even if not in the default Entrance list. Existing animation is never reset merely by opening a category. Unsupported/custom preset remains `Custom: [name]`, with existing fields shown and exact object retained. Preset selection changes only type; timing/direction/fill and unknown fields survive unless an explicit conversion declares otherwise.

For stored trigger other than load, show `Saved trigger: Hover/Scroll/Click — this CSS animation currently plays automatically; that trigger is not applied.` Preserve stored trigger/scrollOffset round-trip on unrelated edits. **Create triggered interaction…** opens existing trigger/action authoring with a suggested equivalent preset only when a real compatible runtime preset exists; creation is explicit and uses a new interaction ID. Do not automatically remove the original animation or translate unsupported custom keyframes. Show conflict warning if both would animate the same property, and let user remove the old CSS animation separately with Undo. This closes misleading Inspector promises without adding a missing engine trigger implementation.

Expose supported existing config under compact **Playback options**: Direction normal/reverse/alternate/alternate-reverse; Fill none/forwards/backwards/both; Repeat finite positive integer or Infinite (`-1`). This is an Inspector extension of already serialized/generated values, not a new animation engine. Duration/Delay keep existing slider convenience ranges, with exact value fields retaining valid stored values outside slider ranges; do not clamp on load. Duration is non-negative finite ms; delay accepts finite signed ms where CSS already permits it, visibly stating a negative delay starts partway through. Invalid values stay draft. Trigger-specific settings remain in triggered interactions, not a pseudo-working CSS-animation toggle.

**Preview** is transient playback of the exact draft/current configuration, never a saved mutation. Controls are **Play preview / Stop / Reset preview**; stop/reset on closing drill-in, changing selection, changing generation or entering read-only conflict. Restore pre-preview visual state/property declarations, not a hardcoded opacity/transform. Reduced-motion preference is respected; explicit preview may require user Play, never autoplay UI motion. Preview limitation text identifies that automatic CSS animation is being previewed; no claim it simulates a saved unsupported trigger. Remove animation clears only CSS AnimationConfig with one Undo; triggered interactions stay. Existing interactions' unknown target/loop/reverse fields survive unrelated edits.

## II-08 — Safe advanced CSS and schema boundaries

Current `src/shared/schemas/project.ts:10–11` stores styles/breakpointStyles as string records; it is not a complete per-property validator. Many UI ranges are convenience controls, not universal saved-model limits. Separate semantic validation for new edits from lossless reading of older saved content.

1. Parse compound CSS with balanced syntax and ordered terms/layers. Preserve duplicate functions, unknown valid functions, nested calc()/var(), custom units and term order. Transform order changes the result. Existing `effectValues.ts:44–79` rebuilds a whitelisted map; that behavior is explicitly replaced for supported edits, not preserved.
2. A control can edit one term only if it identifies that term unambiguously and can serialize all untouched terms losslessly. Otherwise show Custom + exact authored expression (read-only) and offer an explicitly scoped replacement/conversion with before/after summary. Never run regex simplification on blur, mount or selection.
3. Existing raw fields (shadow/transition/grid tracks/custom attributes) remain editable under their property-specific validator and shared sanitization. Empty removes the authored declaration; `none` is an explicit CSS value. For new numeric edits, enforce legal domain (e.g. non-negative padding/width/blur; signed margin/offset/rotation), supported units and finite values. `NaN`, Infinity and incomplete signs never persist.
4. Sliders clamp only the pointer interaction range. A saved value beyond that range is shown exactly with an out-of-slider-range indication, not rewritten. Raw valid unsupported values remain saved and output-capable. Unsupported unsafe CSS does not get an implicit exception: show a concrete rejection, preserve the existing project for inspection/recovery and do not mark output successful.
5. No automatic schema migration merely from opening the Inspector. Necessary source metadata/reference identifiers are backward-compatible additions handled by engineering migration tests; raw saved content and stable element/asset/token/component IDs remain intact.
