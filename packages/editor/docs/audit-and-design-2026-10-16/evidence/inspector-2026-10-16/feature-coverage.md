## What currently exists and must remain

The current Inspector has Style, Behaviour and Effects. Page root/no selection has a distinct Page panel, not an empty prompt. Type capabilities and section registry decide visibility. Style has component identity, type-specific settings, Layout, Typography, Size, Spacing, Fill, Border and Text inside. Behaviour holds form/slides/collection-specific workflows, Link, CMS binding, responsive visibility, Interactions, CSS classes and Attributes. Effects holds opacity, shadow, filters, transform/transition and advanced visual values.

The useful foundations are conditional sections, canvas text editing, source/override marks, one shared style writer, per-element scroll memory, property jump, contextual media/CMS/Brand doors and meaningful local lock feedback. Redesign must retain their behavior and appropriate advanced values. Removed old buttons are not automatically missing features when a new destination already covers the same task.

## Findings and proposed corrections

IDs below use `INS-Fnn` for this feature sub-audit. Priority is recommended order, not runtime-verified severity. Effort is unestimated. All corrections are PROPOSED, not implemented.

### INS-F01 — Multi-selection promises all targets, several controls change primary only

**P0 verification/correction; source confidence high; runtime unverified.** `MultiSelectBar.tsx:113–115` promises “Edits apply to all N. One Undo restores all N.” `InspectorTabContent.tsx:75–83` leaves Behaviour sections visible when their capabilities intersect. But `registry/behaviour.tsx:33–50,151–174,196–207` adapts Link, CMS, Interactions and CSS classes to the primary only; form/slides/collection adapters also receive a single element ID. `LinkSection.tsx:150–163` updates only that ID. `mediaBodies.tsx:134–142` icon replacement similarly targets primary only. The whole-selection banner is therefore not a truthful scope contract.

**Probe:** select two link elements → Behaviour → change destination; inspect both saved href values and Undo. Repeat with classes and two sliders' playback. **Proposed:** classify each operation batch-safe vs single-object. Supported batch property writes must show Mixed and apply atomically to eligible IDs; component/source/structure management that remains single-object must say “Select one element to edit…” or offer explicit target drill-in. Never silently choose primary under a broad all-target banner. Acceptance: displayed scope matches affected IDs; one Undo restores precisely that set; locked/skipped counts visible.

### INS-F02 — Section intersection does not establish field eligibility or mixed values

**P0; source confidence high; runtime unverified.** Mixed detection in `ProInspector.tsx:218–227` only collects style keys. `PropertyField.tsx:177–209`, `mediaBodies.tsx:49–58`, `textBodies.tsx:45–57` and `formBodies.tsx:115–140` read attributes from primary and may write to all. `input/textarea/select/upload` share typeBlock=input; `grid/columns` share grid; `icon/svg` share svg (`elementCapabilities.ts:124–155`). Type-block admission accepts the shared block ID, then actual rows use primary type. A mixed Input+Select selection can show Input type/default rows and write attributes to incompatible targets. Generic ID similarly writes the same authored HTML ID to all.

`widgetBodies.tsx:165–171` also writes the primary progress Maximum to every target when only Value changes, and primary Value to every target when only Maximum changes. This destroys differing companion values without user intent.

**Proposed:** a common field contract declares supported types, data source, batch transform, mixed/read-only/skipped state and constraints. Distinct IDs are single-selection or explicit patterned bulk rename; ordinary one-field updates preserve each target's other properties. Mixed zero/empty/default are distinct. **Acceptance:** select unlike type families/parents and differently valued attributes; no incompatible field appears; modifying one property does not overwrite unrelated per-target values.

### INS-F03 — Some attribute/link/component controls can display stale values after Undo

**P0 probe; source confidence medium-high; not runtime proven.** `PropertyField.tsx:180–189` loads rows only when composer/element ID/type/rows changes. Undo can change values without changing these dependencies. `LinkSection.tsx:84–96` refreshes renders for rel, but href/type input state loads only on composer+selected ID (`118–148`). `ComponentRow.tsx:61–69` caches instance/variant info on composer+ID only. The source contains local-state paths with no authoritative change subscription for these displayed values.

**Proposed:** re-read committed state on relevant engine/history/resource updates; preserve active invalid draft separately and resolve external updates explicitly. **Acceptance:** edit → Undo → Redo with unchanged selection updates control and canvas together; refresh/reselect not required. Selection changes clear unrelated pending validation/draft. Verify old project load and component variant reset too.

### INS-F04 — Custom attributes are write-only from the normal Inspector flow

**P1; source confidence high.** `DataAttributeEditor.tsx:57–103` supplies key/value/Add, no existing list, edit or Remove. Re-entering an existing key can overwrite its value, but users cannot discover the current value or remove it. `AttributesSection.tsx:27–35` counts data-* but omits aria-*, so an ARIA-only configuration can appear to have no attribute state. Its add writer targets only primary even when generic attribute rows target all.

**Proposed:** Attributes contains existing name/value rows, edit/remove, add and per-row validation; dedicated accessible-name/role decisions remain explicit, not fake existing controls. Preserve reserved/internal attributes and meaningful empty attribute values; expose only safe user-owned keys. Reset/remove is explicit, not confused with an empty value. **Acceptance:** add aria-label → collapse/reopen → value visible and counted → edit → remove → Undo; selection change cannot attach staged key/value to wrong target.

### INS-F05 — Form “Label” means placeholder; changing field kind can discard work

**P0; source confidence high; output/runtime unverified.** `FormFieldsSection.tsx:116–120,172` labels a placeholder writer “Label”; this does not author a visible associated label. `replaceField:66–79` recreates input/textarea preserving only name, placeholder, aria-label, required and HTML ID. It drops local styles, classes, other attributes/default content and internal element ID; dependent interactions/bindings/references require compatibility handling. `fieldType:50–56` treats select without type as text; field Type options omit select/checkbox/radio despite those descendants appearing in the list. Element-level Input type is a different path, creating conflicting mental models.

**Proposed:** name the current capability **Placeholder** immediately in design; define visible Label separately as actual authored markup/association. Unify selected-field and form-list entry to one field editor. Type conversion must show what stays/changes, preserve compatible properties and identity, and handle incompatible values explicitly. Do not silently flatten a select into a text setting. **Acceptance:** convert a styled field carrying default, custom attrs and references to long text and back; one Undo restores all original data. Test submit output/accessible label later, not inferred from UI.

### INS-F06 — Invalid Countdown date looks accepted while previous date remains saved

**P1; source confidence high.** `widgetBodies.tsx:59–89` retains typed draft and writes only valid `parseEndsAt` strings, but renders no invalid/pending indicator. A wrong date is visible even though authored configuration remains earlier date; navigating away may lose it without explanation.

**Proposed:** local draft + explicit date/time format, readable local validation, valid commit/Enter/blur behavior, Escape revert, named visitor-local-time policy. “Not saved: enter a valid date and time” when invalid; never success styling for rejected input. A date picker is optional assistance, not required to fix feedback. **Acceptance:** invalid February date, partial date, clearing, Escape, selection change and return; saved runtime end time equals displayed committed value.

### INS-F07 — Columns control reads attributes but writes another representation

**P0; source confidence high; reload symptom unverified.** `layoutBodies.tsx:21–39` declares data-columns/data-gap. `PropertyField.tsx:141–150` reads those attributes, but `attributeWriter.ts:73–106` changes children count or gap CSS without writing corresponding attributes. Local state masks this until reselection/reload. Reducing count removes trailing children immediately (`89–95`) with no content-impact warning in this UI.

**Proposed:** choose the existing rendered authoritative model, derive count from children and gap from proper responsive style scope; do not introduce a second count. Treat count reduction as structure edit, showing affected columns/content and a safe move/remove choice or suitably explicit undoable removal. **Acceptance:** 3→2→reselect/reload shows actual 2; gap still reads correctly; hidden content not silently lost; Undo restores nested content and references.

### INS-F08 — Inline Size inputs accept ineffective changes without explanation

**P1; source confidence high.** `cssContext.ts:146–151` marks width/height/min/max disabled with reason. `SizeSection.tsx:342,362–379` checks hidden only, never disabled/reason. Users can author a width while the inline object looks unchanged. Related vertical-spacing context deserves CSS-correct validation, not wholesale reuse of a blanket rule.

**Proposed:** show actual eligibility reason, retain existing values, offer a deliberate compatible display change when supported. Do not silently change display just because user edits width. **Acceptance:** inline link vs inline image vs block text; legitimate replaced-element sizing not disabled incorrectly; reason understandable; undo preserves display and width.

### INS-F09 — Generic Layout properties depend too heavily on named element type

**P1 architecture; source confidence high.** `elementCapabilities.ts:80–109,133–155` makes Layout absent for text/media/fields and flex/grid primitives. Dedicated `layoutBodies.tsx:42–50` supplies FlexControls/GridControls only, while position/overflow/display live solely in Layout (`registry/box.tsx:44–61`). Thus a generic container using display:flex exposes Position, whereas a named Flex can lose it despite CSS support. This is a source-proven Inspector eligibility gap; other canvas commands may still manipulate position and must be preserved.

**Proposed:** split “children layout” from “this element placement/overflow.” Use CSS applicability and saved values, not container label alone. Retain specialized flex/grid controls without duplicating them. Advanced saved position/overflow must be inspectable/resettable for eligible types. **Acceptance:** same authored display/position configuration on container and Flex offers consistent effective capabilities; root/components/structural-child exceptions documented.

### INS-F10 — Simple select options can flatten meaningful saved option structure

**P1 compatibility; source confidence high.** `PropertyField.tsx:141–145` reads only inner text of option markup. Its writer `164–171` rewrites a newline list to bare `<option>label</option>`, losing distinct value, selected, disabled, option grouping or option-specific attributes. Existing simple options remain valid; this is not a missing select control.

**Proposed:** explicit option Label/Value/Default rows with add/remove/reorder, or preserve unrepresentable markup in a clearly declared advanced state until supported. Never claim a compact text list is a lossless editor for richer saved options. **Acceptance:** import/load Label≠Value + disabled/default option → edit one label → keep all unaffected semantics; Undo exact restoration.

### INS-F11 — CMS distinguishes deleted collection but not all broken binding states

**P1; source confidence high.** `CmsBindingSection.tsx:123–133` defines missing only as absent collection. A deleted field/changed type leaves a bound field slug unmatched. Preview reads absent value as empty; fetch failure `.catch` sets null (`163–193`) rendered as ellipsis (`304–311`), indistinguishable from loading. Async first bind `198–211` has no local error completion in that call and requires rechecking captured target/current permission after request completion.

**Proposed:** independent source states for collection deleted, field deleted/incompatible, record missing/unpublished, legitimate empty value, loading and load failed with Retry. Show stored reference rather than clearing it. Reconnect maps a compatible field; Unbind explicitly preserves current rendered content according to verified manager behavior. On navigation preserve source query and selection return; no apply to new selection. **Acceptance:** each failure has accurate text/action; retained binding survives recoverable load failure; binding resolution/output parity separately tested.

### INS-F12 — Icon metadata controls need renderer verification before claiming usable editing

**P1 probe; source confidence medium.** `mediaBodies.tsx:118–160` Icon size/stroke rows write data-icon-* attributes through generic PropertyRows. `attributeWriter.ts:173–197` icon picker updates metadata and wrapper size/colour but does not replace stored SVG content. `blocks/Media/Icon.tsx:41–70` initially stores literal SVG with own size/stroke/colour. Searches found no data-icon-* renderer consumer outside construction/Inspector in src. This is strong evidence of a broken-update risk, not yet a runtime claim.

**Proposed:** one icon configuration owner and render adapter updates glyph, dimensions, stroke and colour consistently; preserve existing saved icon content during migration. Since icon has no typography capability, do not suggest Typography as an existing icon colour home. **Acceptance:** choose visibly different glyph → change size/stroke/colour → inspect canvas, preview, saved reload and export; all interpret same configuration. Parent should verify before assigning confirmed defect severity.

### INS-F13 — Existing lists need a complete accessible management path

**P1 UX; source confidence high in these sections.** Form fields (`FormFieldsSection.tsx:190–214`) and Slides (`SlidesSection.tsx:119–146`) reorder through drag; no Move up/down action in the inspected local menus. Accordion only open/close/multiple (`widgetBodies.tsx:216–258`); child editing may remain reachable through Layers. These are fragmented local workflows, not proof that global child CRUD is impossible.

**Proposed:** provide per-item Move before/after (or up/down) keyboard-operable alternatives and exact **Edit content** selection jump; preserve item ID and return to parent list. Consolidate item operations around existing commands, not duplicate data models. Add accordion list CRUD only after preserving/reusing existing child operations and validating nesting. **Acceptance:** keyboard-only add/select/reorder/delete/Undo and return; nested content intact; at least one item left rule decided per actual renderer.

### INS-F14 — Inventory claims require correction before using them as design proof

**P1 evidence correction.** HTML #55 says no UI can set radio Value; direct Choice block lacks it, but inner input maps to `input` (`typeMapping.ts:37`) and refinement upgrades wrapper, not inner node (`refineElementTypes.ts:39–46,62–77`). Selecting inner input through Layers should reveal `Default`→value (`formBodies.tsx:49,53`), source-derived path pending runtime. Classify as primary authoring/discoverability gap plus unsafe defaults, not total absence.

HTML #56 says replacing image resets alt. `SourceRow.tsx:97–107,128–133` only writes src for image; `ElementStyles.ts:38–53` setter has no alt synchronization. Record mismatch; verify whether another integrated picker path adds behavior. Proposed replacement must disclose and deliberately preserve/review/reset existing description; automatic clearing is not the only acceptable policy.

HTML #49 broadly says component reset/detach toast plus Undo; current ComponentRow explicitly toasts detach but has no Undo action in this component (`86–105`). Engine/global toast/history could supply it; do not claim absence without tracing those. HTML #108 describes role check as the only Inspector gate, while read-only shell, conflict and lock also change access. Keep server enforcement distinct from visibility.

## Proposed grouping and full task flow (for parent synthesis)

Do not add a fourth tab merely to distribute fields. Compare these two coherent alternatives against current three tabs:

1. **Recommended first comparison, still PROPOSED:** Content / Style / Behaviour / Effects. Preserve the existing Effects destination while separating element content/semantics/binding from visual styling. At the current 300px panel, four equal tabs have only about 75px each; test actual labels, keyboard focus and short-height layout before approval. Do not widen the Inspector merely to fit another tab.
2. **Three-tab alternative:** Content / Style / Behaviour, moving visual Effects into grouped Style sections. This gives about 100px per label and keeps all visual properties together, but increases Style scrolling and relocates a familiar working destination. It needs measured density and task-flow benefit before adopting the merge.

Both options require clear Content versus Behaviour boundaries and persistent component/source scope above tabs. A tab count is not a completion criterion. Whatever tab result, the ownership and field-contract corrections above are prerequisites and not solved by moving headings.

For a selected object the proposed journey is **select → see target/scope → choose relevant aspect → see current source/value → edit valid draft → confirmed live result → explicit save/recovery status → Undo/return**. Shared-resource edit jumps must identify exact token/component/record and preserve page, selection IDs, breakpoint, state, canvas zoom/position, original tab/section, scroll and focus. A field operation stays attached to captured eligible IDs if a picker is open; no late mutation of a new selection. A failed write must not display success or a falsely committed value.

## Regression gate before claiming Inspector complete

1. Every indexed row and its old/new destination has a preservation decision; retired UI counted separately from lost capability.
2. All element families tested at least once; high-risk combinations: mixed input/select, icon/svg, grid/columns, instance/plain, different flex/grid parents, primary-locked/secondary-unlocked.
3. Single and batch displayed values equal authoritative state after edit, Undo, Redo, navigation, external update and reload. Mixed value is not primary/default/zero.
4. Type conversions and list reductions preserve compatible data/references and expose destructive consequences; older values unsupported by simplified controls remain readable and intact.
5. Source-specific missing/error/loading states recover without losing references or applying to wrong selection.
6. Keyboard selection, labels, focus, modal/picker return and list reorder tested in actual UI; this source audit cannot establish accessibility compliance.
7. Parent style audit covers base/tablet/mobile plus pseudo states, token/class/instance inheritance and resets. Parent runtime must distinguish browser/editor width from authored breakpoint.
8. Output round trips: links, form choice values/labels/options, media alt, CMS binding, icons, visibility and animation. Never run production publish just to satisfy the audit.

No “100% correct” claim follows from inventory coverage. A design-ready label requires resolving the above ownership/control contracts, explicit panel geometry and acceptance behavior; implemented/runtime-verified requires actual successful checks.
