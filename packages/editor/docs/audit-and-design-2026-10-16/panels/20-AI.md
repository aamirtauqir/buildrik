## 3. Problems this design solves (job 1 "Build"; job 3 "maintain" for alt text/SEO)
1. **Two undo models** (AI-01 one step vs AI-03 one per step + Undo all) and no shared rule (review §B "two different undo models").
2. **No preview** for edits to existing content: set-text has no "before" (AS-10); Regenerate alt text overwrites at once (AI-10); Generate can forward non-insert commands (§13-4).
3. **Quota is invisible and wrong-sized**: a run's cost (1+N) is never shown; background AI (AI-09, AI-12) spends the user's 10 Free requests silently; plan read from the wrong workspace (AS-04); "out of credit" wording + billing link for everyone (AS-11).
4. **Privacy is unstated**: nothing tells the user what leaves the browser (AS-08).
5. **Not configured is discovered only after typing a prompt**; five routes return a generic failure instead (AS-02).
6. **Roles are client-only** (AS-07): a viewer can trigger AI summary; no server site-role check.
7. **Scope can widen silently** (AS-09) and context trimming is not disclosed (IAF-12 H).
8. **Inconsistent keys and copy** (AS-13, AS-06 "generations" vs dashboard "AI generations" = monthly drafts).

### 4.4 AIC-4 Undo — one reconciled rule
**One user approval = one step in the shared document Undo.** *(DS; amends SC-18 "applies as one step")*
- Generate (class A): one approval → one step "AI · Generated a block". Keep closes the subview; Undo removes it. Unchanged.
- AI task (class B): each Approve = one step "AI · {step title}" (unchanged mechanism). **Undo all this run** remains, renamed "Undo this run's N changes", with the **existing stop rule**: it walks the run's own entries newest first and **stops at the first entry a newer edit sits on** (`useAgentRunner.ts:413-421`). Result copy: "2 of 3 undone — stopped at a newer edit. Use ⌘Z to go further back." No selective undo (skipping over the user's edit) — that is §10.3 Planned. ⌘Z outside the task undoes one AI step at a time like any edit; **Redo** (⌘⇧Z) re-applies one step at a time, also after Undo all.
- Class F Apply and class A insert are document steps too, so ⌘Z order is one timeline for all AI and manual edits.
- History › Session lists AI steps with the ✦ prefix so provenance survives (labels already passed to `applyAiEdit`, `GenerateBlockScreen.tsx:101`).
- After any undo of an AI insert, selection returns per SC-17.

### 4.5 AIC-5 Limits and cost (SC-18 + SC-20)
- **Noun**: **AI prompt** = one unit = one request to the model (SC-11 row below). Kept per request *(OD-AI-3)*. Plans: Free 10/day, Pro 200/day, Business unlimited; **trial = Pro** via the effective-plan resolver (SC-20, Panel 23); the plan is the **site's workspace** (Fix AS-04, AI-D1).
- **Counting with several workspaces** *(DS)*: one counter **per user per workspace per UTC day** — editing a site in a Free workspace spends that workspace's Free allowance; a Pro workspace's sites use its Pro allowance; one user's usage never moves between workspaces. (Today: one counter per user, plan from the oldest workspace — AS-04.)
- **When "left" is measured**: read from `ai.quota` when the surface opens, after every request ends (existing refresh on run end, `AITab.tsx:177`), and when the tab regains focus; the cost line compares against the last read. The server reservation is the truth: a run that meets the limit mid-way stops (below).
- **Cost before Run**: class A/C/D "Uses 1 AI prompt"; page plan "Planning uses 1 · running uses up to N more (one per step)". If the estimate exceeds what is left: Run stays enabled for what fits, with "4 AI prompts left today — the run will stop after 3 steps" *(DS)*.
- **Counter** (SC-18 form, as Panel 23 §7): **"{used} of {limit} AI prompts today on {plan} · resets {local time}"**; during the trial "… on Pro · Pro trial". Change: "generations"/"left" wording → this form; local time, not "midnight UTC". Unlimited: no counter. Unknown: no number (existing).
- **At the limit** (SC-18 pattern): action disabled with reason "Daily AI prompt limit reached — {limit} of {limit} today on {plan} · resets {time}" + **Upgrade** for the **workspace OWNER only** (billing mutations are OWNER-only, `billing.ts:40-49`); everyone else sees SC-18 **"Ask the workspace owner to upgrade"**. Replaces "AI is out of credit" and the all-roles billing link (Fix AS-11).
- **Mid-run limit**: run stops; "Daily limit reached at step 4 — 3 changes applied · Undo this run's 3 changes".
- **Rate limits are technical** (SC-20 copy rule): "Too many AI prompts right now — try again in a moment." Never mentions plans. "{n} min" only after AI-D2 returns a retry-after.
- **Monthly site drafts** (AI-14) are a separate counter "{used} of {limit} AI site drafts this month on {plan}" in the dashboard (Change: from "AI generations").
- **Background spend** (AI-09, AI-12): stops when **3 or fewer** daily prompts remain (measured as above), so the user's own actions keep their budget *(DS; OD-AI-1)*; skipped images show "No alt text yet · Write with AI" in Assets.

## 5. Flows
### 5.1 Generate a block (class A)
Prompt → Generate (cost line) → "Generating…" (Stop inserts nothing) → validate insertion-only → insert as one step, select, highlight → **Keep** (back to Add) / **Undo** (removes, prompt kept). Errors per §7, prompt kept. Unchanged otherwise (Panel 03 §6.4).
### 5.2 AI task run (class B)
Scope line → prompt → (element) one step generates → awaiting with before/after → Approve/Skip; (page) plan 1–8 steps → edit steps → "Run N steps" (cost line) → each step awaiting → Approve/Skip/Stop → done ledger "N applied · M skipped · K no change" → **Keep N changes** / **Undo this run's N changes** / Done → Inspector. A failed step stops the run (existing) and keeps applied steps with the honest Undo.
### 5.3 Write with AI in a field (class C)
SEO title: press "Write with AI" → field shows suggestion with "✦ AI suggestion · Discard"; Page settings footer Save commits; Cancel restores. Each failure kind shown separately (Fix SeoTab generic flag). Assets Regenerate: Current/Suggested + Keep/Discard.
### 5.4 Background alt text (class E)
Upload → if no alt text and ≥4 AI prompts left → request → write unless the user typed meanwhile (existing guard) → Assets/Inspector show "AI-generated · Edit · Regenerate". Limit reached → nothing sent; "No alt text yet · Write with AI".
### 5.5 AI site draft handoff (AI-14, Panel 16 §5.4)
Dashboard wizard counts against "AI site drafts this month"; failure copy per §7 (replace string matching with the server code, AI-D2). Editor opens the draft as a normal site; Getting started applies; one-time AIC-11 note. Brand answers become tokens only after F-3 (Panel 16).

## 13. Code defects found during this inventory (engineering, not design)
1. AI routes are site-agnostic: no `siteId`, no site-role check (`ai.ts:199-490`); a viewer can request AI summaries and the result is written to the version (`AIPanel.tsx:51-96`, `useVersionHistory.ts:147-151`).
2. Quota plan is the user's oldest ACTIVE workspace, not the site's (`quota.service.ts:48-55`); no trial path.
3. `reserveQuota` success path returns `used: limit` (`quota.service.ts:98-99`) — wrong value if anyone reads it.
4. Generate forwards non-insert commands: only `add-section` is pinned, everything else passes to `applyAiEdit` (`GenerateBlockScreen.tsx:90-104`) — violates IAF-04 H.

7. `set-text` rows send an empty `from` (`ai.service.ts:776-778`); `applyOps.preview` always `{}` (`ai.ts:423`).
8. Background AI spends the user's daily quota without a user action: every image upload (`useAltTextAutoTrigger.ts:47-73`) and milestone suggestions (`useAutoMilestone.ts:11-14`).
9. Page pool silently falls back to all site elements and slices to 200 (`useAgentRunner.ts:157-167`).
10. Quota copy "AI is out of credit" and a billing link for every role (`AITab.tsx:333-345`, `GenerateBlockScreen.tsx:121`); Generate counter says "generations" for prompt units (`GenerateBlockScreen.tsx:164`), clashing with the dashboard's monthly "AI generations" (`ai-credits-tab.tsx:16-23`).
11. Three different "open AI" shortcuts (`defaultCommands.ts:580` ⌃⇧A, `keyboardSheetRows.ts:138` ⌃J, Panel 12 I/⌘J).
12. Plan steps announce nothing to assistive tech (`AgentPlan.tsx` has no live region).
13. Dashboard detects AI not configured by message substring (`onboarding/ai/generating/page.tsx:19`).
14. Privacy page does not mention AI processing or the provider (`packages/dashboard/app/privacy/page.tsx`, grep) — content/legal gap.
