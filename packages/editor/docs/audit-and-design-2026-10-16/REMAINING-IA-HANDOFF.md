## 4. Navigation and panel rules

### NAV-01 — State and return contract

Keep one `moduleWorkspace` (Editor / Assets / CMS / Brand / Site settings / Templates / Components), its local resource route and draft registry, one optional `activeTask`, and an origin stack only for deliberate contextual visits. These are proposed frontend state responsibilities, not claims of an existing router. **URL state (R-1018, N5 → SC-26):** the URL carries area, record and open task so reload and shared links restore them; an invalid, denied or other-site target falls back per IA-07.

A return frame carries site/page IDs, selected IDs, component definition/instance scope, authored breakpoint and state, canvas pan/zoom, panel visibility/tab/scroll, resource IDs/query/filter/page, origin focus locator and drafts keyed by owner+property+revision. Async completions carry their captured identity and cannot write to a newly selected object. Direct rail navigation replaces the primary workspace; it does not accumulate Back entries. Back restores the immediate frame. Explicit Pages selection opens the chosen page in Editor, instead of returning to an unrelated prior page.

If the origin is deleted or access is revoked, retain recoverable draft, show the reason and return to the nearest permitted containing list. Never match by display name. Inspector authored-state reset on a genuinely new element remains IA-06; a same-object return restores its recorded state. Browser Back, task Back and document Undo remain separate operations.

Unknown/denied task request leaves the current task intact and explains eligibility. Task-to-task replacement runs the outgoing draft guard; it cannot discard an AI prompt (inactive, SC-21) or Review reply because old shell registration only covered CMS/Settings. While a resource task tray overlays content, the covered resource body is inert; the global shell and task remain keyboard reachable, with no full-window modal trap. Editor tasks keep the exposed canvas available under its actual permission/target rules. The tray does not trap focus, steal focus repeatedly after updates or silently close resource details. Escape closes only the topmost cancellable layer; uploading/saving operations follow their own contract.

### NAV-03 — Draft and operation registry

Each owner declares live applied edits, unapplied input, staged form, preview transaction and irreversible/server job separately. The guard is the one SC-24 dialog — **"Leave without saving?"** · Keep editing (default) · Discard changes · Save and leave (only where an explicit Save exists: Site settings, CMS record, Page settings) *(R-1018, S3 / CS-02)*. Save-and-leave is offered only if that owner has a validated asynchronous save result; local/queued does not count as server-saved. Multiple owners save sequentially; display completed and remaining owners, stop on failure, retry only unresolved ones. Discard operates only on that named staged draft or reversible preview. No generic “Discard everything” rollback of already applied Brand edits, uploads or server actions. Existing IA-03/IC/II preflight remains normative.

## 6. Shared controls and workflow contracts

### CTRL-01 — Common editable control

Label identifies property and owner. Read canonical value/presence before formatting. Empty, zero, inherited, mixed, invalid legacy and local draft remain distinct. Repeated inspector/style inputs use existing IC/II/BIC; this annex does not replace them. A staged CMS/Settings field updates its keyed draft on typing, validates locally and on server, and commits only through its owner Save. Enter submits only where it is the documented form action; textarea Enter inserts text. Escape discards unapplied field input or closes a cancellable subview after its dirty guard, never an unrelated history entry. Reset removes the applicable override/attribute only; seed/default replacement is labelled separately. Multi-select is only for explicit supported bulk operations, not schema, component version or service forms.

### CTRL-02 — Resource list

Search is local UI state; active filters show removable chips and count scope. Sort/filter/page changes keep the selected resource ID and draft until deliberate deselection or explicit guard. Empty library, no matches, loading, failed load, truncated search and permission denial use different states. Add/Edit/Duplicate/Move/Delete identify complete resource/semantic units. Keyboard rows and non-drag Move dialog share commands. Bulk actions preflight every target; if server cannot transact them, report per-target outcome and retry only failed targets, never claim atomicity. Missing resources retain a labelled missing reference until deliberate repair.

### CTRL-03 — Contextual picker

Capture source owner/property and revision before opening. Manage library and Choose/Use are distinct modes with named target. Selecting a tile only stages a choice; Use validates compatibility, target existence and permission then applies once. Cancel retains old assignment; completed uploads remain in library. A nested manager returns to the picker with choice/query, then to the originating field. Never apply to whichever canvas element happens to be selected later. Upload failure retains retryable local draft under existing asset safety rules; no saved durable URL claim before registration.

### CTRL-04 — Shared change and deletion

Whether an action is Undo-only, a consequence confirm or a typed confirm is decided once in SC-15's three classes (S2) *(R-1018)*. Impact summary names scope, usages found, unknown scan domains and dependent references. Do not say globally unused from a partial scan. Exact Undo is offered only when the operation restores original identity and dependencies. Otherwise label supported recovery precisely (Restore as new record, Retry upload, Restore revision). Shared destructive actions require current server revision/capability; stale summary triggers refresh. Cancellation before commit changes nothing; after confirmed server commit Close is navigation, not rollback. Local document commands remain atomic and use captured meaningful history units.

### CTRL-05 — Save / preview / release

Display local applied, sync queued, server saved, failed, conflicted and unpublished separately. A valid mutation receipt, not a timer or manager return, confirms persistence. Preview preserves source context and explicitly chooses applied document values or named CMS saved/draft record; unapplied drafts remain excluded per IA-03/INS-D11. Publish reviews exact destination and site-wide payload/revision; no page-only implication. An unknown network outcome first checks operation/job status before retry to avoid duplicate requests. Download initiation does not prove a file was retained. See IAF-15/16/22. **Preview target (amended 2026-10-17, panels/00 SC-8):** last Editor page, current breakpoint and current frame width (incl. saved custom width); a template page previews the canvas Record-switcher record; Desktop 1440.

### CTRL-06 — Permission and flag resolution

Resolve workspace membership, effective site role (including caps), resource permission, current view mode, plan and feature availability independently. Unknown/loading is neither granted nor permanently denied: retain safe read context, prevent destructive execution until service adjudication, show Check access/Retry. A feature-off entry follows the existing explicit policy; a discoverable denied action uses disabled-with-reason where useful, while inaccessible data remains hidden/redacted. All routes, keyboard, commands and deep links use the same resolved result. Server remains authoritative; UI changes cannot fix FI-05.

### CTRL-07 — Performance and output consistency

Proposed acceptance fixtures, not measured guarantees:100 pages,5,000 tree nodes,1,000 assets,1,000 CMS records,100 component definitions with nested references and1,000 token usages. Use existing virtualized/paged patterns; selection and drafts must survive recycled rows, search and async updates. No full-site re-render or serialization on each uncommitted keystroke merely for a count. Compare/save/AI jobs show progress only from actual measured work. Test real engine/persistence/rendering across editor, preview, export and published artifacts against the same saved configuration; unsupported dynamic/server behavior is labelled, not simulated as shipped output.
