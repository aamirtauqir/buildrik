## How to read the status

The brief requires each principle to be *applied in the design and verified in the final result*. **No hi-fi design exists** (Figma deferred by owner sequence; AGENTS.md audit mode). So every principle carries two statuses:

| Column | Object | Values |
|---|---|---|
| **Spec** | The written panel/contract docs | PASS-SPEC (spec defines enough to apply it, and is sound) · NEEDS REVISION · BLOCKED · N/A |
| **Design** | Hi-fi screens | **BLOCKED — no screens** for all 40. Nothing is visually verified. |

No row is PASS overall. A PASS-SPEC row means "ready to design from", not "verified". Evidence IDs point to `_extraction/` files (T1–T7, D1–D3) and their source citations.

Verification method used for every row: document inspection (read + grep across 35 design docs and the 1,238-row inventory). Not used: usability testing (none exists), runtime walk, contrast measurement, screen-reader pass.
