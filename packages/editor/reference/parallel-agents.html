Parallel agents

The safety unit is the file, not the agent. Two agents writing disjoint files in one tree are safe. Two agents writing one file lose data silently — no conflict, no error, last writer wins.

Single-writer resources

Each of these is a whole-repo snapshot. A second writer does not conflict — it overwrites with a view of the world that is missing the first writer's work.

Subagent prompt — the four clauses

Every dispatched agent gets these verbatim. Clause 3 is the one that keeps failing without a named destination, so give it the path. 

1. Write ONLY <one file>. No other file.
2. Do NOT run `--update`. Do NOT `git commit`. The parent does both.
3. Do NOT `git stash`. The baseline is already at /tmp/baseline-before.txt.
4. Business logic must not break. Visual drift is acceptable.

Report: what was removed, and which chrome-ui atom replaced it.
Measured, not assumed Across 15 recorded incidents, roughly 30–50% of agents dispatched in parallel run git stash anyway — with the ban stated explicitly in the prompt. Recovery averages ~10 minutes each. Recording the baseline to a file before dispatch does not stop the reflex; it makes it cheap, because the agent has somewhere else to look.

Commands

Create and remove a worktree

git worktree add ../buildrik-lane-b -b lane-b     # new branch
git worktree add ../buildrik-baseline HEAD        # throwaway, for a baseline read
git worktree list
git worktree remove ../buildrik-baseline
git worktree prune                                # after deleting a dir by hand

Record a baseline before dispatch

node scripts/check-styling-ratchet.mjs      >  /tmp/baseline-before.txt
npx tsc --noEmit 2>&1 | grep -c "error TS" >> /tmp/baseline-before.txt

Converge after agents return

git log --oneline -10                       # a parallel session may have shipped it
pnpm test && pnpm run verify:ds             # 10 gates; the ratchet is the last
node scripts/check-styling-ratchet.mjs --update
git commit -am "refactor(chrome): N panels drained — …"

Nightly squash, Lane B → main

cd ~/Desktop/pencil/buildrik
git fetch origin
git merge --squash sandbox-a
git commit -m "chore(cleanup): nightly batch YYYY-MM-DD — N tasks"
git push origin main

cd ~/Desktop/pencil/buildrik-sandbox-a
git fetch origin && git reset --hard origin/main
git push --force-with-lease origin sandbox-a

Traps specific to this repo

TrapWhat happensFix
pnpm 11 in a fresh worktreeBuild scripts are skipped silently.Run prisma generate by hand; graft the linux sharp binary.
Any pnpm command in a worktree with a symlinked node_modulespnpm's dep-status check decides the modules dir is stale and tries to purge it — through the symlink, at the main tree's 1.9G of deps. Only the no-TTY guard stops it, and CI=true removes that guard.Never run pnpm there. Call the gate scripts directly with node / bash.
Symlinking a package's whole node_modulesWorkspace links inside it are relative, so they resolve from the symlink's real location — the main tree. TypeScript then sees the same class from two paths and reports phantom TS2322/TS2345 nominal mismatches (22 of them here) in a package you never touched.Make the dir real and symlink each entry, with the workspace link (@buildrik/editor) pointed at the worktree's own copy.
git stash for a baselinePops a stash entry from another session onto your tree. 15 incidents, one near-loss.Throwaway worktree, or read the baseline before you start.
Two sessions, same arcBoth land bit-identical commits (verified 2026-05-11).git log --oneline -10 before staging anything.
Pre-push hook hangverify:ds runs on push and stalls.git push --no-verify after you have run the gates yourself.
