Vibcoder

Born 26 Apr 2026. Died 28 Jul 2026. 70 primitives, 63 CSS files, 106 preview files, deleted in one commit of −29,179 lines. It is the model for the migration you are asking for, because it has already been done — twice.

What it actually was

Not something written from scratch. The first commit (7a4328fe, 26 Apr) says it plainly: 

feat(editor): vibcoder React wrapper namespace

Phase 0 Task 2. shared/vibcoder/ is the single import surface for
chrome JSX consuming vendored components. Barrel ready;
Button lands next.

A vendored UI kit — copied into the repo from docs/reference/vibcoder/ — with a thin React wrapper per component so chrome had one import surface. Exactly the role chrome-ui/ plays for flowbite today.

Look at that list again ListRow. Menu. Modal. EmptyState. Toolbar. Popover. Skeleton. Those are the same names chrome-ui/ ships today. The library changed; the shapes a visual editor needs did not.

editor/ui was built to replace vibcoder, absorbed every consumer, and was itself deleted three days later once flowbite absorbed it. Two full component libraries were built and buried in one quarter.

How the deletion was actually done

This is the part worth copying. The library was not deleted first. Six slices moved every consumer off it, and the delete was the last step, when the count was already zero:

SliceWhat moved
1 · eaa9a393topbar / shell header
2 · c5a64252rail + drawer
3 · 8c0d4f4fTooltip compound + leftovers
4 · a67f6779seven dialogs onto one Modal
5 · 73a0cbd1forms, compounds, mechanicals — 34 surfaces
6 · 8c326538delete — ratchet already read 402 → 0

The deletion commit's own summary line: ratchet 402 → 0. The gate counted remaining imports, and the delete happened when that number hit zero — not before. That is why 29,179 lines could be removed in one commit with 7,803 tests green.

Why order matters more than courage Deleting first and fixing after would have produced hundreds of broken imports at once, with no way to tell a real breakage from a missing shim. Draining first means every commit is independently green, and the delete is boring.

What is left of it today

Thirteen mentions in src/. Twelve are comments — archaeology explaining where a shape came from:

shared/forms/NumberField.tsx:5
  * The vibcoder-era −/+ stepper buttons are gone (the Figma design has no…)

The thirteenth is real, and it is a test cleaning up a legacy DOM id: document.getElementById("vibcoder-overlay-root")?.remove() in MyTemplatesSaveTemplate.test.tsx. No imports. No components. No CSS.

The answer to "delete vibcoder" There is nothing to delete. It went on 28 Jul, its successor went on 31 Jul, and both are locked at zero by gates that fail the build on a single import. What remains is a fossil record, and fossils are useful — they tell you which shapes this editor has needed three times running.
