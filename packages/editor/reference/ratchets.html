Ratchets

A ratchet is a counter that may go down or stay flat, never up. It is the mechanism that made 29,179 lines deletable in one commit, and it is the only reason a months-long migration does not quietly reverse.

The one-line definition

if (now > baseline) → exit 1 → build fails

That is the whole idea. A wrench ratchet turns one way and locks the other. A code ratchet is the same: the number you are draining can fall, and the moment it rises the build stops.

The four ratchets in this repo

GateCountsLocked at
gate:vibcoder-ratchetimports of the deleted vibcoder / shared-ui paths0
gate:editor-ui-goneimports of the deleted editor/ui0
gate:chrome-ui-surfacedirect flowbite-react imports outside chrome-ui/0
gate:styling-ratchetinline styles + in-scope CSS linesdraining

The first three are finished ratchets — locked at zero, so they are now bans. The fourth is a live one: its number is still falling, and every conversion lowers it.

Anatomy of the live one

scripts/check-styling-ratchet.mjs   # the counter
scripts/.styling-baseline.json      # its memory
{
  "inline_literal": 1280,
  "inline_hoisted": 590,
  "css_lines": 10940,
  "css_files": {
    "inspector/styles/inspector.css": 1038,
    "media/LibraryManager.css": 955,
    …
  }
}

Three aggregates plus a per-file map. The map exists because aggregates alone cannot see direction:

[styling-ratchet] ok   css_lines  10939 (baseline 10940, drained 1)
[styling-ratchet] FAIL shell/chrome.css grew 45 -> 50 (+5)

Five lines added in one panel and six removed from another nets to −1 and the total says "drained". The per-file lock catches it. Without that, a ratchet measures tidiness, not architecture.

The two commands

CommandDoesWhen
node scripts/check-styling-ratchet.mjsCompares now against baseline. Exit 1 if any number rose.Every build, via verify:ds
… --updateWrites the current numbers as the new baseline.Only after a real drain, in the same commit
… --topWorst remaining files, the in-scope CSS list, and what is excluded and why.Choosing the next target
The failure mode --update is also how a ratchet dies. Run it to make a red build go green and you have not drained anything — you have moved the goalposts and kept the ceremony. The rule: --update only ever lowers a number, and only in a commit that explains what was drained.

Why it made vibcoder deletable

The vibcoder deletion commit's own summary carries one line: ratchet 402 → 0. The gate counted remaining imports across six migration slices. The delete landed when the counter said zero — not when someone felt ready.

That is the difference between "we should clean this up" and a deletion of 29,179 lines with 7,803 tests green. The counter, not the intention, decided the moment.

A ratchet you never watch fail is a lie

Every ratchet here has been negative-controlled: a violation is planted deliberately, and the gate is watched failing before it is trusted. The styling ratchet was checked three ways:

PlantedResult
+1 line in chrome.cssFAIL — both aggregate and per-file
+5 here, −6 thereaggregate says "drained 1"; per-file says FAIL
brand-new panel CSS fileFAIL — new panel CSS file

The middle one is the reason the per-file map exists at all. It was found by planting the violation, not by reading the code.
